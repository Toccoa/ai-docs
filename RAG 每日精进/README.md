# RAG 每日精进

一个面向 **AI Agent 架构师** 的 RAG 长期学习系统：每天 1–2 个知识点，按知识地图推进，自动插入前沿更新。

## 它怎么运转

- 每天 **09:00（Asia/Shanghai）**，自动化任务会在一个专用会话里生成当天内容。
- 任务会读取知识地图和进度，选择下 1–2 个未完成知识点。
- 生成前会检索最近的重要更新；有实质内容才写“前沿插入”，不硬凑。
- 生成后写入 `02-每日推荐/YYYY-MM-DD.md`，并更新进度与索引。
- 同一天重复触发不会重复生成；如果当天笔记已存在，只返回摘要。

## 自动发布到站点

- 每天生成完笔记与元数据后，**默认自动发布并推送**，站点地址：<https://blog.093681.xyz/>（板块「RAG 学习路线图」）。
- 发布链路（在仓库根 `/Users/zhaochunyu/Documents/docspace/资讯/AI 文档` 执行）：

```bash
# 1) 按显式文件列表发布（源文件只读，不会写回）
node scripts/publish.mjs "RAG 每日精进/02-每日推荐/YYYY-MM-DD.md" \
  "RAG 每日精进/00-RAG知识地图.md" "RAG 每日精进/01-学习进度.md" "RAG 每日精进/04-索引.md"

# 2) 知识地图回链（知识点标题必须写成「## 知识点 N：标题（Rxx-xx）」才会被识别）
node scripts/link-knowledge-map.mjs

# 3) 地图有变化时再发布一次，然后本地构建校验
node scripts/publish.mjs "RAG 每日精进/00-RAG知识地图.md"
npm run docs:build

# 4) 提交并推送（22 端口被网络层阻断，走 ssh.github.com:443）
git add -A && git commit -m "docs: RAG 每日推荐第 NNN 期（…）"
GIT_SSH_COMMAND="ssh -o UserKnownHostsFile=/tmp/gh443_known_hosts -o StrictHostKeyChecking=yes -p 443" \
  git push ssh://git@ssh.github.com:443/Toccoa/ai-docs.git main
```

- 若提示 `Host key verification failed`，先重建 known_hosts：`ssh -p 443 -o UserKnownHostsFile=/tmp/gh443_known_hosts git@ssh.github.com`（会自动写入主机密钥）。
- 推送后 Pages 由 `.github/workflows/deploy.yml` 自动部署，通常 1–2 分钟；验证：
  `curl -o /dev/null -w "%{http_code}" "https://blog.093681.xyz/RAG%20学习路线图/02-每日推荐/YYYY-MM-DD.html"` 应为 200。
- 注意事项：
  - **知识点标题格式**：`## 知识点 1：文档层级与父子关系（R1-07）`——ID 必须在全角括号内且位于标题末尾，否则知识地图不会自动回链。
  - `git add -A` 会一并带入仓库里其他自动化产出的内容（如 `AI-Agent-开发日报-*.md`），这是当前约定。

## 前沿资料的默认处理（2026-11-27 起）

每期「今日前沿插入」里出现的**非中文来源**，默认做三件事，不再逐次询问：

1. **译成中文**：条目正文全中文；英文标题保留原文并附中文译名，避免检索时对不上。
2. **下载到本地**：跑 `bash scripts/fetch-frontier-originals.sh`——ACL Anthology 的 PDF 逐一比对 `Content-Length` + `%%EOF` 才留；arXiv 的 PDF 在本网络下会被限速截断（实测约 4 KB/s），**改存 HTML 版本**（判据：含 `</html>` 且 >20 KB）。拿不到存档的，条目里只留原文链接，**不假装有**。
3. **随文章上线**：`scripts/publish.mjs` 会把与文章同级的 `原文/` 目录镜像到 **`content/public/`**（VitePress 把 `srcDir` 当 Vite root，所以有效 publicDir 是 `content/public/`，**不是** `site/public/`），构建时原样复制进站点。条目里的 `[PDF](原文/…)` 因此在 GitHub Pages 上可点。

- 归档位置：`RAG 每日精进/05-前沿资料/原文/`（PDF）与 `原文/html/`（arXiv HTML），索引页是 `05-前沿资料/index.md`。
- 同一主题的 2–3 篇会**合并成一篇精读**，避免碎片化；每篇必带「精评：值钱处 / 不能当真处」和「对你的动作」。
- 站点侧死链检查只对 `/原文/`（含 URL 编码形式 `%E5%8E%9F%E6%96%87/`）放行，其他死链仍会让构建失败。

## 怎么用

1. **每天读 15–20 分钟**：先看“一句话结论”，再看“怎么做”和“坑”。
2. **做完 3 道自测**：把答案或疑问直接回复在会话里，第二天会带上复习提醒。
3. **每周日回看**：把本周的“一句话笔记”串起来，形成自己的架构判断。
4. **每月一次**：用 `M7 评估` 的知识，给自己的场景做一次归因。

## 怎么调整

- 改时间：在自动化任务列表中编辑这个任务的时间。
- 改节奏：在任务提示词里把“默认 2 个”改成 1 个，或改成“工作日 2 个、周末复习”。
- 改方向：直接编辑 `00-RAG知识地图.md`，增删知识点；ID 尽量保持稳定。
- 暂停：在任务列表中暂停，不会丢失进度。

## 设计原则

- **架构师视角**：不背概念，重点回答“为什么、什么时候用、代价是什么、怎么验证”。
- **证据优先**：区分事实、论文结论、个人建议；引用可核验来源。
- **先框架后细节**：先建立边界感和失败模型，再进入解析、切分、检索、评估。
- **前沿是插件**：新知识进入“前沿插入”或“动态新增区”，不打断主线。
