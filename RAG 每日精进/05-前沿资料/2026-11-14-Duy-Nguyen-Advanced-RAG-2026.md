# 2026 年的 RAG 架构全景：Duy Nguyen 的分类与选型

> 定位：前沿资料 · 单篇精读（原 Duy Nguyen 个人博客长文）

> 主源：Duy Nguyen《Advanced RAG Techniques in 2026: From Naive to Production-Grade》，更新于 2026-08-12，<https://duynguyenngoc.com/posts/advanced-rag-techniques-2026>

## 一句话结论

这篇的价值不在"教你一个技术"，而在**给了一张 2026 年的地图**：RAG 已经从 2023 年的一条链，长成了一棵树（Agentic / Graph / Multimodal / Bidirectional 四个方向 + MiA-RAG、HGMem、Graph-O1 这类新组合）。**当目录用，不要当证据用。**

## 演进：四代，一条主线

| 代次 | 时间 | 结构 | 主要失败模式 |
| --- | --- | --- | --- |
| Naive RAG | 2023 | 切块 → 向量 → top-k → 拼 prompt | 切块丢上下文、单轮、不会追问 |
| Advanced RAG | 2024 | 加预检索（改写/扩展）+ 后检索（rerank/压缩） | 流程仍是单向的，中途出错无法回退 |
| Agentic RAG | 2025 起 | 模型自己决定"查不查、查几次、查哪个库" | 成本与延迟不可控、评测难 |
| 分支形态 | 2025–2026 | Graph RAG / Multimodal RAG / Bidirectional RAG | 各自解决一个特定断层，但都更贵 |

主线其实只有一句话：**从"检索是流水线的一步"，变成"检索是 agent 的一个工具"**。这也解释了为什么"该不该用 RAG"这个问题在 2026 年反而更需要先问——因为答案可能是"用 agent + 工具检索"，而不是"搭一个 RAG 系统"。

## 四个方向各自修哪个断层

| 方向 | 修什么 | 代价 |
| --- | --- | --- |
| Agentic | 一次检索不够，要会追问、会换查询、会判断"够了" | 多轮 token 成本、不可预测延迟、需要评测护栏 |
| Graph | 多跳关系（"谁负责这个项目的上级部门"），向量检索天然不擅长 | 建图与维护成本高，抽取质量决定上限 |
| Multimodal | 图表、扫描件、截图里的信息 | 解析链更长，错误来源更多 |
| Bidirectional | 检索结果反过来影响查询（迭代式改写） | 容易陷入"越查越偏"的循环 |

新组合（MiA-RAG、HGMem、Graph-O1）都在做同一件事：**把"检索"和"记忆"混起来**——不再区分"外部知识库"和"对话历史"，而是统一成一个可检索的状态。

## 三个企业级缺口（这部分最实用）

作者列的三个"demo 能跑、上线就崩"的地方：

1. **实时数据**：向量库是批处理的，业务数据是流式的。答案里出现"上周的数据"就已经错了。
2. **知识图谱**：跨部门、跨系统的实体关系，纯文本切块表达不了。
3. **细粒度访问控制**：**这是内网 RAG 的生死线**。向量检索是"语义最近"，不是"权限允许"——如果把权限过滤放在检索之后（rerank 或生成后），你已经把没权限的内容送进了模型上下文，等于泄露。

第 3 条的工程结论必须记住：**权限过滤要前置到检索层（同一批 where 条件进向量库），不能后置。**

## 选型决策树（转述 + 补第一问）

原文的顺序大致是：数据规模 → 查询复杂度 → 延迟预算 → 是否需要多跳 → 是否多模态。我给它补上更靠前的第一问：

0. **这题到底该不该用 RAG？** 三种情况不该：知识能塞进 prompt（< 20 万 token）、答案是计算/查询而非文本（该走 text-to-SQL / API）、需要严格审计追溯（该走规则或知识图谱）。
1. 单跳事实查询 → Advanced RAG（混合检索 + rerank）就够，别上 agent
2. 需要多跳关系 → Graph RAG
3. 查询意图分散、需要判断"查够了没" → Agentic
4. 图表密集 → 先修解析（版面分析），再谈多模态检索

## 评测门槛（Ragas 口径）

| 指标 | 门槛 | 它其实在测什么 |
| --- | --- | --- |
| faithfulness | > 0.90 | 答案里的每句话是否都能在检索结果里找到依据 |
| answer relevancy | > 0.85 | 答的是不是问的那件事 |
| context precision | > 0.80 | 检索结果里有多少是噪声 |
| context recall | > 0.85 | 该找到的是不是都找到了 |

## 精评：它值钱的地方

1. **分类学本身是资产**。它把散落在几十篇论文里的方向收敛成四个 + 若干组合，用来对齐团队认知很省事。
2. **"三个企业缺口"是真话**。尤其细粒度权限这条，绝大多数 RAG 教程压根不提，而它决定了这套东西能不能进内网。
3. **它承认了 agentic 的代价**（成本、延迟、评测），没有一味吹。

## 精评：不能当真（这篇是导航贴，不是证据贴）

1. **代码不能直接跑**。示例里 `create_openai_tools_agent` 在新版 LangChain 已废弃，gpt-4o 的写法也和现在的接口对不上；按它抄会先花半天修 import。
2. **arXiv 编号（2512.*）无法核实**。2026 年的预印本编号在那个时间点本就偏新，部分引用查不到原文，等于**不可验证的二手转述**。
3. **决策树缺了最关键的第一问**（见上），直接按它走，很容易在"本来不该用 RAG"的题上搭一套系统。
4. **Ragas 的四个门槛不是统计显著的门槛**，只是社区约定俗成的经验值；0.85 和 0.86 之间没有任何本质差别，别拿它当验收红线去卡。
5. **"2026"是营销标签**。文中真正 2025 年之后的新东西不多，大部分是 2024 年的技术换了包装。
