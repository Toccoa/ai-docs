## 今日速览

- **R3-02 稠密检索原理**：cosine 相似度衡量的是**在一个学出来的空间里的方向一致性**，不是"语义真相"——它有三个已知失效面：**组合改写（否定/角色互换）保持高相似**、**各向异性（anisotropy）下的度量失准**、**绝对值不可当置信度**。
- **R3-03 混合检索与融合**：**RRF 不是"无需调参的免费午餐"**（研究显示它对参数敏感，且在域内/域外都输给调好的加权融合）；更关键的是，**融合带来的召回增量在 rerank + 截断之后大部分会被吃掉**——所以融合必须用"端到端"验收，而不是看召回涨了多少。

## 知识点 1：稠密检索原理（R3-02）

### 一句话结论

稠密检索把"query 与文档是否相关"压缩成**一个向量间的角度**；这个角度只在**训练分布内**可靠地反映相关性，出了分布它衡量的是"表征空间里的方向相似"，而**方向相似与相关性之间没有必然联系**——否定句、角色互换、精确约束都能让"方向"几乎不动，但意思已经反了。

### 为什么重要

**失效面 1：组合改写会翻转语义，但相似度几乎不动。**

【论文结论】*Training for Compositional Sensitivity Reduces Dense Retrieval Generalization*（arXiv:2604.16351）把这件事说得很直接：稠密检索把文本压成单个 embedding、按 cosine 排序；**这个接口对"身份级匹配"很脆——最小的组合编辑（否定、角色互换）就翻转了含义，却保留了高相似度**。
更值得注意的是它给出的代价：**加入面向结构的负样本训练后，零样本 NanoBEIR 检索能力反而下降**——小骨干 **8–9% 平均 nDCG@10**、中等骨干**最多 40%**，而池化空间的可分性只是"部分改善"。
→ 两个含义：① **"相似 ≠ 相关"不是理论洁癖，是可以在你的语料上复现的现象**；② **想靠训练把这件事修好，代价是牺牲泛化**（这是 R0-01 里"相关≠充分"的几何版本）。

**失效面 2：cosine 本身在某些空间里就不是最佳度量。**

【论文结论】*Anisotropy Decides Cosine vs. Rank Metrics for Text Embeddings*（arXiv:2606.29571）做了 19 个无参相似度度量 × 19 个编码器 × 7 个数据集的系统实验，结论很干净：
- **当编码器把方差均匀铺在各个方向上 → cosine 就是最佳的无参选择**，别的度量帮不上忙；
- **当方差集中到少数主导方向（anisotropy）→ 基于排名和 L1 类的度量明显优于 cosine**；绝对增益不算大，但因为 cosine 在这些编码器上本来起点低，**相对提升平均约 20%**；
- **一个数就能预测"要不要换度量"：单个最主导维度所占的方差比例**——在 19 个编码器上与"替代度量的帮助幅度"的**秩相关 0.86、线性相关 0.95**；
- 把主导方向投影掉之后，**cosine 恢复、替代度量的优势基本消失**，且**只在原本各向异性的编码器上**如此；
- 效应是**方向性而非幅度**的（把向量都归一化后依然存在）。

→ 最关键的一句：**"这取决于嵌入空间的几何，而不是模型怎么训的"**；而**检索场景常用的领域微调编码器通常是"铺得比较开"的，所以对它们 cosine 就是对的**。

**失效面 3：cosine 的绝对值不能当"相关性分数"用。**

【论文结论】*Calibrated Similarity*（arXiv:2601.16907）：各向异性会让 cosine 的**绝对值系统性失准**——分数挤在一个很窄的高相似区间里，跟真实语义相关性脱钩；它用保序回归做单调校准来恢复可解释性，同时**不改变排序**。
工程侧的对应证据：【论文结论/实践】*Relevance Filtering for Embedding-based Retrieval*（arXiv:2408.04887，含沃尔玛产品搜索的线上 A/B）：**与词汇检索天然有关键词截断不同，稠密检索经 ANN 取回后没有自然截断**；cosine 分数由对比/排序损失优化而来、**难以解释**，因此"top-K 或 cos 阈值"往往筛不干净；他们的做法是把原始 cosine 用**查询相关的映射**转成可解释分数，再套**全局阈值**，换来精度明显提升、召回小幅损失。

**还有两个"别忽略"的机制事实：**
- 【论文结论】*Scaling Laws for Embedding Dimension*（arXiv:2602.05062）：嵌入维度与效果的关系**拟合幂律**；对**与训练任务一致的**评测，维度越大越好（收益递减）；但对**不那么一致的**评测，**某些任务上维度越大反而更差**。→ **"加大维度"不是无风险操作。**
- 【论文结论】MA-DPR（arXiv:2509.13562）：embedding 常落在**低维非线性流形**上（尤其在 OOD 场景），此时 cosine 与欧氏距离都抓不住语义相似；用近邻图上的最短路径做距离，**OOD 段落检索最多提升 26%**，域内性能持平、查询开销只小幅增加。

### 核心机制 / 数据流

**先把"它在算什么"写成一句可检查的话：**

```
cos(q, d) = (q·d) / (‖q‖‖d‖)
```
它只关心**夹角**，完全不看长度。这意味着三件事：
1. **范数信息被丢弃**：如果训练时范数编码了"典型性/置信度"，cosine 会把这份信息扔掉（*Semantics at an Angle*, arXiv:2504.16318 讨论的正是这类情形）。
2. **角度接近 ≠ 蕴含关系**：`"这款药可用于儿童"` 与 `"这款药不可用于儿童"` 的词几乎全同，方向自然极近。
3. **分数不可跨 query 比较**：不同 query 的相似度分布不同（Cosine Adapter 那篇的出发点），**用同一个阈值卡所有 query 必然出错**。

**双塔的固有约束（这是"为什么它快但浅"的根源）：**

```
query ──▶ encoder ──▶ 一个向量 ─┐
                                 ├─▶ 内积/余弦 ──▶ 排序
doc   ──▶ encoder ──▶ 一个向量 ─┘
        （两者不能互相看见）
```
- **快**：文档向量可离线算好，查询时只算一次 query 向量 + ANN 检索；
- **浅**：query 与 doc 在编码阶段**互相不可见**，所有"跨文本的细粒度匹配"（哪个词对哪个词、否定修饰谁）都被压进了一个点。这正是 R3-06（多向量/晚交互）与 R3-10（rerank）存在的理由。

### 怎么做（3 步）

**第 1 步：给你的 embedding 做一次"几何体检"，决定要不要换度量。**

```python
import numpy as np
def geometry_report(vecs):          # vecs: (N, D) 已归一化
    X = vecs - vecs.mean(0)         # 去中心后再看方差分布
    s = np.linalg.svd(X, compute_uv=False)
    var = s**2 / (s**2).sum()
    return {
        "top1_var_ratio": float(var[0]),          # 关键诊断数
        "effective_rank": float(np.exp(-(var*np.log(var+1e-12)).sum())),
        "mean_pairwise_cos": float((vecs @ vecs.T).mean()),
    }
```
判读（对齐上面那篇的结论）：
- `top1_var_ratio` **低**（方差铺得开）→ **继续用 cosine**，别折腾；
- `top1_var_ratio` **高**（明显各向异性）→ 值得试 **排名类 / L1 类**度量，或在检索前去主导方向；
- `mean_pairwise_cos` 很高（比如 >0.6）→ 说明所有东西都"长得像"，此时**你的相似度阈值基本不可用**。

**第 2 步：为"相似≠相关"造一组对抗查询（这是最值钱的资产）。**

```
对 20 条现有 query，各造 3 个"高相似但语义反转/错位"的变体：
  否定：  "X 支持 Y"     → "X 不支持 Y"
  角色互换："A 收购 B"    → "B 收购 A"
  范围：  "适用于所有客户" → "仅适用于企业客户"
  时间：  "2024 年生效"   → "2026 年生效"
测：这些变体与原文的 cosine（通常 >0.9），以及"变体能否召回同一批文档"
若变体把原文的文档挤到 top-3 之外 → 你的检索器在"只差一个词"的场景不可靠
```
【论文结论】这正是上面那篇研究的核心现象（组合编辑保持高相似度）。**你的对抗集不需要大，20×4 就够说明问题。**

**第 3 步：把"阈值"从全局改成"按 query 校准"。**

```python
# 不要： if score > 0.75: 收下
# 而是：先按该 query 的候选分布做相对判定
def accept(cands, k_min=3, ratio=0.85):
    top = cands[0].score
    return [c for c in cands if c.score >= top * ratio][: max(k_min, len(cands))]
```
【我的建议】绝对阈值只在"单一 query 类型 + 固定编码器 + 固定语料"时才勉强可用；**跨类型就必须用相对判定或校准**（Cosine Adapter 那篇就是把这个思路做成一个可训练组件）。

### 权衡与坑

- **坑 1：把 cosine 当"相关概率"。** 它是有界的余弦，不是概率；**0.8 在不同 query 上含义完全不同**。
- **坑 2：以为"语义模型能理解否定"。** 【论文结论】组合编辑（否定/角色互换）**保持高相似度**；靠 embedding 区分"是/不是"基本不可靠——这类判断要交给 rerank（cross-encoder 能看到两边）或结构化字段。
- **坑 3：无脑加大维度。** 【论文结论】维度与效果是幂律关系，但**在与训练任务不一致的评测上，更大维度可能更差**；同时存储与检索成本线性上升（第 003 期 R0-06 的成本模型）。
- **坑 4：对所有编码器套同一套度量。** 【论文结论】各向异性高的编码器上，cosine 明显吃亏；**但领域微调的检索编码器通常铺得开，cosine 就是对的**——所以"换度量"要按模型实测，不要按传言。
- **坑 5：忽略"单向量"这个上限。** query 与 doc 编码时**互不可见**，所有细粒度匹配被压成一个点。指望调阈值解决"细粒度不匹配"是方向错了——那是 rerank 的活。
- 【我的建议】把 R3-02 的产出定义成三条**可执行断言**：① 我的编码器 `top1_var_ratio` 是多少；② 我的对抗查询通过率是多少；③ 我的阈值是相对判定还是绝对判定。

### 架构师视角

- **稠密检索是"召回器"，不是"判定器"。** 它的职责是"别漏"，不是"别错"。把"相关性判定"压在它身上，会导致你不断调阈值而永不满意——正确做法是**召回宽一点 + rerank 严一点**（R3-10）。
- **几何体检应该进"换模型"的准入清单**：任何换 embedding 的动作，都要同时报 `top1_var_ratio`、`mean_pairwise_cos`、以及对抗集通过率。否则你只是在换一个黑盒。
- **观测出口**：`score_dist_p50/p95`（分数分布是否挤在窄带）、`score_gap_top1_top5`（第一名与第五名的差距——差距小说明排序不稳）、`adv_query_pass_rate`（对抗查询通过率）。
- **一句话**：**cosine 度量的是"在这个空间里像不像"，而你要的是"能不能支撑这个结论"**——两者的缺口由 rerank 与生成端的引用约束来补。

## 知识点 2：混合检索与融合（R3-03）

### 一句话结论

融合的选型不是"RRF 还是加权"这种二选一，而是**先问"融合到底有没有端到端收益"**——研究显示 **RRF 并非免调参的稳妥默认**（对参数敏感，且在域内/域外都输给调好的加权凸组合），而**融合带来的召回增量在 rerank + 截断之后大部分会被吃掉**（有生产部署报告 Hit@10 从 0.51 掉到 0.48）。

### 为什么重要

**证据一：RRF 的"无需调参"是个误解。**

【论文结论】Bruch, Gai, Ingber, *An Analysis of Fusion Functions for Hybrid Retrieval*（arXiv:2210.11934 / ACM TOIS）系统比较了两种融合：**凸组合（convex combination, CC）** 与 **RRF**：
- **与既有认知相反，RRF 对自己的参数是敏感的**；
- **CC 的学习一般对"分数归一化方式"不敏感**（这点很重要，因为它消解了"量纲不同没法加权"的顾虑）；
- **CC 在域内与域外设定下都优于 RRF**；
- **CC 样本效率高**：只需一小批训练样例就能把它的**唯一参数**调到目标域。

→ 直接推翻了两条常见做法：① 用 RRF 是为了"不想调参"；② "分数量纲不同所以只能排名融合"。

**证据二（更要紧）：融合的收益会在下游被吃掉。**

【论文结论】*Scaling RAG with RAG Fusion: Lessons from an Industry Deployment*（arXiv:2603.02153）在**生产形态**的 RAG 管线（固定检索深度、rerank 预算、延迟约束）上评估多查询与 RRF 类融合：
- 融合**确实提高了原始召回**；
- 但**这些增益在 rerank 与截断之后基本被中和**；
- 在该设定下，**融合变体在 KB 级 Top-k 准确率上没能超过单查询基线，多个配置里 Hit@10 从 0.51 降到 0.48**；
- 同时融合**引入额外延迟**（查询改写 + 更大候选集），下游没换来对应收益。

**证据三：融合有没有用，取决于你的模型是不是"已在域内训练好"。**

【论文结论】*Know When to Fuse*（arXiv:2409.01357，COLING 2025，法语法律域）：
- **零样本**场景：融合不同通用模型**一致提升**，与用哪种融合方法无关；
- 但**模型在域内训练过之后，融合相对"最好的单系统"通常是降的**，除非用**仔细调过的权重**去融合分数。

→ 这句话解释了上面两个看似矛盾的结论：**融合的价值来自"模型互补且都还不够强"**；一旦有一个够强的单系统，融合就是在稀释它。

**证据四：融合确实能在某些场景带来明确增益（但要看清设定）。**
【论文结论】*Hybrid Retrieval for COVID-19 Literature*（arXiv:2604.13728，TREC-COVID，171,332 篇、50 条专家查询）：**RRF 达到 nDCG@10 = 0.828，比纯稠密高 6.1%、比纯稀疏高 14.9%**；它的"投影融合"变体 nDCG@10 = 0.678，但**快 33%**（847ms vs 1271ms）、列表内多样性 ILD@10 高 2.2 倍。

**证据五：真正稳的路线可能是"按 query 动态定权"。**
【论文结论】DAT（arXiv:2503.23013）指出**固定权重无法适应不同 query**，用 LLM 评估两路 top-1 的有效性再做归一化定权，在多指标上稳定优于固定权重融合。
【论文结论】MARS-Gate（Zenodo 预印本）用两个**分布形状特征**（dense top-10 分数分布的"尖锐度" + BM25 与 dense top-10 的 Jaccard 重叠）做**逐 query 门控**，在 21 个 BEIR 数据集上 **20 个优于标准 RRF（k=60）**，平均 **+0.028 nDCG@10**，且系数能零样本迁移到同族更大编码器（+0.0389）。

**证据六：别忘了"稀疏"这一路本身在变强。**
【论文结论】LACONIC（arXiv:2601.01684）：基于 Llama-3 的学习型稀疏检索（1B/3B/8B），**8B 在 MTEB Retrieval 上 60.2 nDCG**，且**索引内存比同效稠密模型少 71%**，可在 CPU 上跑。→ **"稀疏只是陪跑"这个前提本身正在变化**，这会影响你的融合配比。

### 核心机制 / 数据流

**三种融合的机制差异（这决定了它们各自的失效方式）：**

| 方式 | 机制 | 强项 | 失效方式 |
|---|---|---|---|
| RRF | 只用**排名**：`Σ 1/(k+rank)` | 免疫量纲；实现极简 | **对 k 敏感**；丢弃分数间距信息（"差一点点"与"差很多"同样对待） |
| 加权凸组合（CC） | 先归一化再**线性混合**分数 | 保留分数间距；研究显示优于 RRF；只需调一个参数 | 依赖归一化方式与少量标注；**归一化错了会放大噪声** |
| 级联 / 路由 | 先便宜后贵：BM25 命中足够就跳过 dense；或按 query 类型选路 | 成本最优 | 判据不准时**漏召回**；需要可信的"够了"信号（第 003 期 Coverage Illusion 讲过前置路由的失败） |

**RRF 的两个参数，很多人只知道一个：**
```
score(d) = Σ_i  w_i / (k + rank_i(d))
             ↑      ↑
          路权重   平滑常数 k（常见 60）
```
- `k` 越大 → 排名差异被压平，**更偏向"多路都出现"的文档**；
- `k` 越小 → **更偏向"某一路排第一"的文档**。
所以 k 不是"随便取 60"，它实际上在调"共识 vs 尖峰"的偏好。

**一个可直接用的判据：先看两路的重叠度。**
```
overlap@10 = |BM25_top10 ∩ Dense_top10| / 10
```
- overlap 很低（<0.3）→ 两路互补性强，**融合可能有真收益**；
- overlap 很高（>0.7）→ 两路在说同一件事，**融合多半只是加延迟**（这也解释了"为什么有些团队做了混合却没变化"）。

### 怎么做（3 步）

**第 1 步：先做"要不要融合"的实验，而不是"怎么融合"。**
```
基线 A：只用 BM25（top-50 → rerank → top-5）
基线 B：只用 dense（top-50 → rerank → top-5）
候选 C：RRF 融合（两路各 top-50 → RRF → rerank → top-5）
候选 D：CC 融合（归一化后加权 → rerank → top-5）
全部走**同一条 rerank + 截断**，比较最终 top-5 的命中率与 p95 延迟
```
【我的建议】关键在"**全部走同一条 rerank + 截断**"——上面那篇生产部署的教训就是：**融合的召回增量在 rerank 后消失**。你不这样测，就会得出"融合 +6%"的乐观结论。

**第 2 步：如果决定融合，先试 CC 再试 RRF。**

```python
import numpy as np

def minmax(x):
    x = np.asarray(x, dtype=float)
    return (x - x.min()) / (x.max() - x.min() + 1e-9)

def convex_fuse(bm25_hits, dense_hits, alpha=0.5):
    """alpha 是唯一参数：0=纯BM25，1=纯dense；用 20-50 条标注调它"""
    scores = {}
    for doc, s in bm25_hits:  scores.setdefault(doc, [0, 0])[0] = s
    for doc, s in dense_hits: scores.setdefault(doc, [0, 0])[1] = s
    b = minmax([v[0] for v in scores.values()])
    d = minmax([v[1] for v in scores.values()])
    for (doc, _), bv, dv in zip(scores.items(), b, d):
        yield doc, alpha * dv + (1 - alpha) * bv
```
【论文结论】上面那篇的结论是：**学 CC 时不必纠结用哪种归一化**（学习对归一化不敏感），而**只需少量样本就能把 α 调好**。所以先在小标注集（20–50 条）上网格搜 α，再固定上线。

**第 3 步：把"动态权重"作为第二阶段的优化，而不是第一天就上。**
```
第一阶段：固定 α（来自第 2 步）
第二阶段：只在"两路分歧大"的 query 上动态调权（overlap@10 低 + dense 分布不尖锐）
```
【论文结论】DAT 与 MARS-Gate 都指向"逐 query 定权"更优；但 MARS-Gate 也承认在个别数据集上**出现显著回退**（argument retrieval 那类）。**所以动态权重必须有回退开关。**

### 权衡与坑

- **坑 1：以为 RRF 免调参。** 【论文结论】RRF 对参数敏感，且域内/域外都输给调好的 CC。**"省事"的代价是把性能上限锁死了。**
- **坑 2：只测召回就宣布成功。** 【论文结论】生产部署报告：融合提召回，但 **rerank + 截断后 Hit@10 从 0.51 掉到 0.48**。**必须测端到端 Top-k。**
- **坑 3：在"已有一个强单系统"时强行融合。** 【论文结论】域内训练后融合通常降低效果，除非权重精心调过。**融合的前提是"互补且都不够强"。**
- **坑 4：忽略重叠度。** 两路 top-10 高度重叠时，融合几乎没有信息增量，只是**延迟翻倍**。
- **坑 5：把多查询扩展（multi-query）当成"免费召回"。** 它会**放大候选集与延迟**，而增益同样会被 rerank 吃掉（同上）。
- **坑 6：忘了稀疏侧在进化。** 【论文结论】LACONIC 这类学习型稀疏已把差距压到"索引内存少 71%"的程度，**融合配比需要随模型更新重调**。
- 【我的建议】判断顺序：**先证明两路互补（overlap 低）→ 再证明端到端有增益（同一条 rerank 下）→ 再考虑 CC vs RRF → 最后才谈动态权重。**

### 架构师视角

- **融合是"成本换召回"的交易，而召回只有在没被 rerank 吃掉时才有价值。** 所以它的验收指标必须是**最终 top-k** + **p95 延迟**，而不是任何中间召回。
- **RRF 的正确使用场景**：两路都不可信、没有标注、需要快速跑通。**有标注之后就该转向 CC**（它只需要一个参数）。
- **观测出口**：`overlap@10`（两路重叠）、`fusion_delta_at_final_k`（融合相对最好单路的最终 top-k 增益）、`fusion_latency_delta`、`alpha`（如果上 CC，它是需要被监控的超参）。
- **一句话**：**混合检索的价值不在"两种方法都用上"，而在"两路在不同 query 上各有所长"**——先量化这句话，再决定要不要付融合的成本。

## 今日前沿插入

> 只写有实质更新、且能核验来源的内容。

**① cosine 的适用性被归结为一个可测的几何量（arXiv:2606.29571）**
19 度量 × 19 编码器 × 7 数据集：方差铺得开时 cosine 最优；各向异性时排名类/L1 类明显更好（相对提升平均 ~20%）；**"最主导维度方差占比"这一个数与替代度量收益的相关性达 0.86（秩）/0.95（线性）**；投影掉主导方向后 cosine 恢复。
**为什么值得注意**：它把"要不要换相似度度量"从经验之争变成了**一个数的诊断**。

**② "相似≠相关"有了量化路径（arXiv:2604.16351）**
否定、角色互换等最小组合编辑**翻转语义但保留高相似度**；用结构负样本训练可改善可分性，却让零样本 NanoBEIR **nDCG@10 掉 8–9%（小模型）/最多 40%（中等模型）**。
**为什么值得注意**：修这个缺陷有明确代价，不是免费改进。

**③ RRF 的神话被系统性地检验（arXiv:2210.11934，TOIS）**
RRF **对参数敏感**；CC 的学习**对归一化不敏感**；**CC 在域内与域外均优于 RRF**；CC **只需少量样本**即可调好唯一参数。

**④ 融合的生产收益可能被 rerank 吃掉（arXiv:2603.02153）**
固定检索深度 + rerank 预算 + 延迟约束下，融合提召回但**最终 Hit@10 从 0.51 降到 0.48**，并引入额外延迟。
**为什么值得注意**：这是"中间指标涨、端到端跌"的典型案例，正好对应第 002 期的四层归因纪律。

**⑤ 学习型稀疏在逼近稠密（arXiv:2601.01684）**
LACONIC 8B 在 MTEB Retrieval 达 **60.2 nDCG**，**索引内存比同效稠密少 71%**，可跑在普通 CPU 上。
**为什么值得注意**：稀疏侧变强会改变"混合该怎么配比"的前提。

**趋势观察（非定论）**
2026 年检索侧的讨论重心正从"选稠密还是稀疏"转向"**逐 query 定权/路由 + 用端到端指标验收**"（DAT、MARS-Gate、生产部署报告都在这个方向上）。同时"相似度度量"本身开始被当作**可诊断、可校准的工程对象**（各向异性诊断、iso 校准、Cosine Adapter）。**属趋势观察。**
