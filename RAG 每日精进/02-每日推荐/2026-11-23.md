## 知识点 1：多跳与迭代检索（R3-08）

### 一句话结论

多跳检索不是"把一次检索重复 N 次"，而是**把一个需要 k 段互不重叠证据的问题，拆成有依赖顺序的子问题，并在每轮之后判断"还缺哪一块"**；所以它真正的设计难点是**停止条件**与**子问题生成**，而不是迭代次数。

### 为什么重要

**先看"为什么单轮一定不够"。** 一个多跳问题的证据链是 `A → B → C`：你只有先知道 A，才知道该去查 B。单轮检索拿到的是"与 query 语义最像"的文档，而**中间跳的实体在你提问时根本不在 query 里**——它不在，就召不回来。

**再看"多跳"这件事在评测上被长期低估的问题。**
【论文结论】*Rethinking Reasoning-Intensive Retrieval*（Zhao 等，ACL 2026 Long，2026.acl-long.1705）指出：**推理密集型检索的目标是"最大化下游推理效用"，而不仅是主题相似性**；但既有基准（以 Bright 为代表）有两个致命缺陷——**金标集窄**，且**在孤立环境里评估检索器**，这掩盖了检索器在真实 agent 工作流里的价值。他们提出的 **Bright-Pro** 为每个 query 提供四样东西：**专家标注的 reasoning aspects、正例文档、参考答案、评分 rubric**，并额外评估检索器**作为 agentic 搜索系统核心组件时的实际效用**。

→ 这对你有一个非常具体的含义：**如果你的多跳评测集里，"每个问题只对应一段证据"，那你测不出多跳能力**（这和上一期第 011 期讲的"证据稀疏会抹平切分差异"是同一个病）。

**再看"停止"这件事的可测量化。**
【论文结论】*Predicting Partial Answer Quality and Utility in Agentic Retrieval*（arXiv:2609.16453，2026-09）：**轨迹派生的信号可以预测中间答案状态，并支持早停**，从而减少迭代次数。
【论文结论】*Agentic Search in the Wild*（arXiv:2601.17617，2026-01，基于 1400 万+ 轨迹）：分析结论建议采用**重复感知的早停（repetition-aware early stopping）**、**意图自适应的检索预算**、以及显式的跨轮次整合。
→ 两条合起来的意思是：**"该不该再搜一轮"是可以从轨迹特征里学出来的**，而不是拍一个 `max_steps=5`。

**最后看"分解"的工程形态。**
【论文结论】PreQRAG（arXiv:2506.17493，SIGIR 2025 LiveRAG 参赛方案）：**先分类**——把问题分成**单文档型**与**多文档型**；单文档型走**改写**，多文档型走**分解成聚焦子问题**。分类+分治的策略在 LiveRAG 上拿到 Session 2 初赛第二。
→ 这条很实用：**不是所有问题都该分解**。先分型，再决定用改写还是分解，比"一律分解"便宜得多。

### 核心机制 / 数据流

**四种形态，成本与适用面递增：**

| 形态 | 机制 | 何时够用 | 主要风险 |
|---|---|---|---|
| 单轮 + 更大 k | 一次取更多块 | 证据集中、只是排名问题 | 越 k 越贵，且受上下文悬崖限制（第 009 期） |
| 查询改写/扩展 | 换个问法再检一次 | 词汇鸿沟 | 改写跑偏（第 014 期：表面改动即显著改变检索决策） |
| **显式分解（多跳）** | 拆子问题，按依赖顺序检索 | 证据链有明确先后 | 子问题生成错 → 连锁错；轮次成本 |
| **Agentic 检索** | 模型自己决定搜什么、何时停 | 开放研究型任务 | 不可控、成本方差大 |

**一条多跳链的数据流（以"三年营收 CAGR 是否达激励门槛"为例）：**

```
Q0: 三年营收 CAGR 是否达到激励门槛？
 ├─ Q1: 2022 年营收？        → 证据段 A
 ├─ Q2: 2025 年营收？        → 证据段 B
 ├─ Q3: 激励条款的门槛值？    → 证据段 C
 └─ 组合：CAGR = (B/A)^(1/3) - 1，再与 C 比较
每轮结束后要回答三个问题：
 ① 已获得哪些证据段（覆盖了哪些 reasoning aspect）
 ② 还缺哪一段（下一轮要查什么）
 ③ 是否已经够了（充分性判定）→ 够了就停
```

**"够不够"的三个可操作判据（按成本从低到高）：**

```
judge_1（规则）：本轮是否新增了"未覆盖的 reasoning aspect"？没有 → 停
judge_2（覆盖）：已覆盖的 aspect 数 / 问题所需 aspect 数 ≥ 阈值 → 停
judge_3（模型）：让模型判断"现有证据能否支撑一个确定答案"（sufficiency，第 002 期）
```
【我的建议】先用 `judge_1 + judge_2` 做 80% 的停止决策（便宜、可解释），只在两者冲突时调用 `judge_3`。

### 怎么做（3 步）

**第 1 步：建一个"真多跳"的评测集（20–30 条就够，但必须跨文档）。**

```
每条要有：
  - 问题（不能靠单段证据答出）
  - gold_evidence_spans：2–4 段，来自不同文档/章节
  - reasoning_aspects：这道题需要哪几个"面"（对齐 Bright-Pro 的思路）
  - 一个"单轮召回的命中率"基线（用来证明它真的需要多跳）
判据：单轮检索覆盖 gold spans 的比例 < 60% → 它是真多跳题
```
【论文结论】这正是 Bright-Pro 的构造方式：**reasoning aspects + 正例文档 + rubric**，而不是只标一个答案。

**第 2 步：实现"子问题驱动 + 充分性停止"的循环。**

```python
def multi_hop(q, retriever, max_rounds=4, aspect_target=1.0):
    aspects = plan_aspects(q)                 # 分解：这道题需要哪几个面
    covered, evidence, trace = set(), [], []
    for r in range(max_rounds):
        missing = [a for a in aspects if a not in covered]
        if not missing:                       # judge_1：没有新面要查 → 停
            break
        sub_q = next_subquery(q, missing[0], evidence)   # 依赖前轮证据生成
        hits = retriever.search(sub_q, k=10)
        new = [h for h in hits if h.id not in {e.id for e in evidence}]
        if not new:                           # 没有新证据 → 重复了，停
            trace.append(("no_new_evidence", r)); break
        evidence += new
        covered |= {a for a in missing if supports(new, a)}
        trace.append((r, len(evidence), len(covered) / len(aspects)))
        if len(covered) / len(aspects) >= aspect_target:  # judge_2：够覆盖 → 停
            break
    return evidence, trace
```
**注意 `next_subquery` 的质量决定成败**：它必须用**上一轮已确认的实体**去构造下一跳查询（而不是再问一遍原问题）。

**第 3 步：把"轮次"做成可观测的分布，而不是一个上限。**

```
观测：rounds_used 的分布（p50/p90/max）、每轮新增证据数、no_new_evidence 的比例
判据：
  - rounds_used 的 p90 远小于 max_rounds → 你的上限设得太高，浪费预算
  - no_new_evidence 比例 > 20% → 子问题生成在重复劳动，需要改分解策略
```

### 权衡与坑

- **坑 1：把"多轮"当"多跳"。** 同一个问题换个问法搜三次，不是多跳。**多跳的判据是"证据之间有无依赖"，不是"检索了几次"。**
- **坑 2：固定 `max_steps`。** 【论文结论】早停可以从轨迹信号学出来（arXiv:2609.16453 / 2601.17617）。**固定步数要么浪费（简单题也跑满）、要么截断（难题没搜完）。**
- **坑 3：子问题不依赖前轮结果。** 如果第 2 轮还在问原问题的子集，你只是在做"多次改写"，永远不会跳到下一跳。
- **坑 4：忘了去重。** 多轮很容易把同一段证据反复召回（`no_new_evidence` 比例飙升）。**每轮都要用第 006 期的哈希去重。**
- **坑 5：忽略"组合"这一步。** 多跳的最后一步是**把多段证据合成一个结论**（求和、算比率、比对阈值），这一步失败率很高且容易被归因到"生成不行"——其实是**证据没对齐单位/时间口径**（第 003 期 R0-05）。
- **坑 6：评测集不能测出多跳。** 【论文结论】既有基准常因金标窄、孤立评估而掩盖检索器价值（Bright-Pro 的出发点）；更早还有"可被 disconnected reasoning 作弊"的问题（CRUMQs 那篇指出既有基准可被"无真多跳推理"绕过，见下一节）。
- 【我的建议】**先做"分解 + 规则停止"，再考虑"学习式早停"**；前者两天能上线，后者需要轨迹数据积累。

### 架构师视角

- **多跳的预算是"乘法"不是"加法"**：轮次 × 每轮候选数 × 每轮上下文。**先把 `max_rounds` 和每轮 k 一起砍到最小可行，再谈效果**（第 003 期 R0-06 的乘数模型）。
- **它天然属于"该路由的架构"**：多数问题是单跳的，只有少数需要多跳。**路由（第 003 期 R9-01 的前身）比"全量上 agent"便宜一个数量级。**
- **观测出口**：`rounds_used_dist`、`aspect_coverage`（每题的 aspect 覆盖率）、`no_new_evidence_rate`、`multi_hop_share`（真实流量里需要多跳的比例——这个数决定你值不值得建这套东西）。
- **一句话**：**多跳检索的成熟度，不看它能搜几轮，看它能否在"证据够了"的那一刻停下来。**

### 自测 3 题

1. 你的评测集里，有多少题是"必须跨两段以上证据"的？如果不到 10 道，你怎么证明你的多跳能力？
2. 你的 `max_rounds` 是怎么定的？如果 `rounds_used` 的 p90 只有 2，而你把上限设为 6，你在为什么付费？
3. 第 2 轮的子问题，是用"上一轮确认的实体"生成的，还是又把原问题改写了一遍？这两种做法的结果差在哪？

## 知识点 2：相关性阈值与拒答（R3-09）

### 一句话结论

拒答有两种，难度天差地别：**"没证据所以不答"很简单，"有证据但证据是误导的所以不答"极难**——而后者才是生产事故的主要来源；2026 年的受控实验显示，**明确要求"证据不足就拒答"的提示，并不能阻止模型回答 41.6% 的误导性问题**。

### 为什么重要

**证据一：这是被量化过的失败，不是理论担忧。**

【论文结论】*Prompt-Based Abstention Fails Under Misleading Context*（Setiawan，AACL-IJCNLP 2026 Long，pp. 3368–3386，DOI 10.18653/2026.aacl-long.153）设计了一个成对基准 **GRAB-RAG**：**同一批问题**在四种上下文条件下测试——**supportive（支持）、degraded（降质）、missing（缺失）、misleading（误导）**，语料是 Natural Questions 与 HotpotQA。在误导条件下，他们把一段**金标段落改写成支持错误答案**，与其他检索段落放在一起。
三个小冻结模型（3.8B–8B）、五种拒答策略下的结果：
- **证据缺失时，模型能可靠地拒答**；
- **但在明确的拒答提示下，模型仍然回答了 41.6% 的误导性问题，其中 63% 的回答复述了被植入的错误实体**；
- **CoT 几乎没有额外帮助**；
- 生成侧的**冲突检查**把比例降到 13.3%，但**丢掉了大量正确答案**；
- **NLI 验证器**能挽回覆盖，但**当参数记忆与那段误导段落"就同一个错误答案达成一致"时会失效**。

作者给了一句我认为值得贴在墙上的总结：**"基于提示的拒答只问了'上下文是否充分'，没问'上下文是否正确'。"**

**证据二：缺失证据时的"过度回答"也被量化。**
【论文结论】一项针对"LLM 是否知道证据不足"的研究（Zhang 等，2026）报告：当前 LLM 在**基于证据的拒答**上仍有明显局限，**过度回答率（over-answer rate）在 65%–91%** 区间。
【论文结论】RefusalBench（Muhamed 等，2026，被上篇引用）在多文档查询上发现**拒答准确率不足 50%**。

**证据三：拒答可以被做成"打分问题"，而且比 softmax 置信更可靠。**
【论文结论】*Energy Landscapes Enable Reliable Abstention*（arXiv:2509.04482）：在 **260 万条**由指南派生的问题构成的语义语料上训练一个**能量模型（EBM）**，用能量景观决定"生成还是拒答"。在**语义上困难的近分布**案例上：**AUROC 0.961 vs softmax 基线 0.950**，**FPR@95 为 0.235 vs 0.331**；在简单负例上各方法相当，但**优势在安全关键的困难分布上最明显**。消融显示鲁棒性主要来自**能量打分头**。
→ 含义：**"拒答"应当是一个独立训练/独立校准的判别器，而不是复用生成模型的置信度。**

**证据四：评测集本身会"放水"。**
【论文结论】CRUMQs（arXiv:2510.11956）：现实场景里 RAG 常遇到"语料中缺信息或不完整"的复杂查询，系统必须能**拒答不可答/超范围的问题**；但既有基准**很少反映真实复杂度**——多跳题可被**"分离式推理"（disconnected reasoning）作弊**（不需要真的做多跳推理就能答对），或只需要简单事实回忆。他们提出一套自动、可控难度的流水线，构造**不可作弊、真实、无答案、多跳**的查询（CRUMQs），在两个常用 RAG 数据集上验证；相对既有基准，**cheatability 分数最多下降 81.0%**。
→ 这条直接接到你的评测设计：**如果你的"无答案"测试集是"随便编个语料外的问题"，模型靠常识就能答对，你测的其实是常识而不是拒答。**

### 核心机制 / 数据流

**四种条件与对应的能力要求（这张表是本节的核心）：**

| 上下文条件 | 模型默认行为 | 需要的能力 | 靠提示能解决吗 |
|---|---|---|---|
| supportive（支持） | 正确作答 | 生成 | —— |
| degraded（降质：残缺/噪声） | 勉强作答 | 充分性判定 | 部分可以 |
| **missing（缺失）** | **可靠拒答**（数据显示） | 阈值/覆盖判定 | 基本可以 |
| **misleading（误导）** | **照答不误（41.6%）** | **证据正确性判定** | **不行** |

**为什么"误导"这么难——三条机制：**
1. **提示约束的是"充分性"，不是"正确性"**：`if evidence is insufficient, say I don't know` 这句话对"证据很充分但内容是错的"完全无效。
2. **参数记忆会被"背书"**：当模型自己的记忆与误导段落**指向同一个错误答案**时，NLI 验证器也失效（论文明确报告）。
3. **错误答案往往"更具体"**：植入的错误实体是明确的名称/数字，而正确回答常需要"综合后不确定"，模型在不确定性下会偏向具体答案。

**拒答的三层实现（从便宜到贵，建议叠加）：**

```
L1 检索层：硬阈值 / 覆盖判定
   - 最高相似度低于阈值 → 直接拒（但要按 query 校准，第 012 期）
   - 覆盖的 reasoning aspect 数不足 → 拒
L2 校验层：证据一致性
   - 多段证据之间是否冲突（同一实体不同数值/时间）
   - 答案中的每个断言能否在证据里找到支撑（NLI / 引用对齐）
L3 生成层：受限生成
   - 强制逐句引用；无法引用则不得陈述
   - 冲突时输出"存在冲突"而非择一
   - 不确定时输出"未找到"而非"最可能"
```

### 怎么做（3 步）

**第 1 步：造你自己的"四条件成对集"（这是本节最值钱的资产）。**

```
取 30 条你已有金标的问题，为每条构造四个版本：
  supportive  ← 原 gold 段落
  degraded    ← 删掉关键句 / 加入无关噪声
  missing     ← 移除 gold 段落（只留无关段落）
  misleading  ← 把 gold 段落改写成支持一个错误答案（保留格式与措辞风格）
指标（分开报，不要合成一个总分）：
  refuse_rate_missing   目标 ≥ 95%
  refuse_rate_misleading 目标 ≥ 80%
  over_refusal_rate（本该答却拒）目标 ≤ 10%
```
【论文结论】GRAB-RAG 的做法就是"同一问题 × 四条件"，并且**误导条件是"编辑金标段落使其支持错误答案"**——这个构造方式可以直接抄。

**第 2 步：把"冲突检查"做成独立组件，而不是塞进 prompt。**

```python
def check_conflict(evidence, answer_claims):
    """返回 (conflicts, supported, unsupported)"""
    conflicts = []
    for claim in answer_claims:
        vals = {extract_value(e, claim.subject) for e in evidence
                if mentions(e, claim.subject)}
        vals.discard(None)
        if len(vals) > 1:                 # 同一主体出现多个不同值
            conflicts.append((claim, vals))
    return conflicts
```
【论文结论】论文报告生成侧冲突检查把误导回答率从 41.6% 压到 **13.3%**，但代价是**丢掉许多正确回答**。→ 所以它应当作为**"不确定时降级为澄清/标注"**的信号，而不是直接拒答。

**第 3 步：把拒答分成三种输出，而不是"答/不答"二元。**

```
① 确定回答（有充分且一致的证据）
② 有限回答 + 显式标注（证据存在但不完整/有冲突）：
   "根据 X（2024 版）为 A；另有 Y（2026 版）为 B，两者冲突，建议核实"
③ 明确拒答（无证据 / 证据不足）：
   "未在知识库中找到支持该结论的依据"
```
【我的建议】第 ② 类是被最多团队忽略、但对用户价值最高的一类——它把"我不知道"变成了"我知道哪里不确定"。

### 权衡与坑

- **坑 1：以为加一句"证据不足请拒答"就够了。** 【论文结论】误导条件下仍有 **41.6%** 被回答，CoT 帮助很小。**提示只能约束充分性，约束不了正确性。**
- **坑 2：用生成模型的置信度当拒答信号。** 【论文结论】EBM 的 AUROC 0.961 优于 softmax 0.950，FPR@95 0.235 vs 0.331——**独立校准的判别器更可靠**。
- **坑 3：为了压住误导而大面积拒答。** 【论文结论】冲突检查把 41.6% 降到 13.3%，但**丢掉大量正确答案**。**必须同时报"过度拒答率"**，否则你只是把错误从"答错"换成了"不答"。
- **坑 4：把"不可答"测试集造假。** 【论文结论】CRUMQs 指出既有基准可被 disconnected reasoning 作弊，cheatability 最多降 81%。**你的无答案题必须"看起来可答"，否则测不出拒答。**
- **坑 5：把拒答当兜底文案。** 拒答是**一条独立路径**，需要自己的评测集、自己的阈值、自己的观测（第 002 期 R0-04 已强调）。
- **坑 6：忽略"权限导致的不可答"。** 用户无权访问某文档时，正确答案就是"无法回答"，而不是"根据其他文档推测"（第 006 期 R1-06 / 第 013 期 R3-05）。
- 【我的建议】验收顺序：**先保 refuse_rate_missing（缺失必拒）→ 再压 over_refusal（别乱拒）→ 最后攻 misleading（最难）**。

### 架构师视角

- **拒答率是一个产品参数，不是技术参数。** 在医疗/金融/法务里，宁可多拒；在客服 FAQ 里，过度拒答会直接伤体验。**所以阈值必须按场景定，而且要写进 ADR。**
- **把"误导"当成对抗场景来设计**：它会出现在**用户上传的文档**、**过期的制度**、**被人为篡改的网页**里——这正是第 013 期成本攻击、第 006 期可采性治理的同一族问题。
- **观测出口**：`refuse_rate_missing`、`refuse_rate_misleading`、`over_refusal_rate`、`conflict_detected_rate`、`citation_unsupported_rate`（引用无法支撑断言的比例）。
- **一句话**：**一个不会拒答的系统，它的"不知道"会以"看起来很像真的"的形式出现**——这比直接报错危险得多。

## 今日前沿插入

> 只写有实质更新、且能核验来源的内容。

**① 拒答研究的关键转折：从"证据够不够"到"证据对不对"（AACL-IJCNLP 2026，2026-11）**
GRAB-RAG 用"同一问题 × 四条件（支持/降质/缺失/误导）"的成对设计，量化出：**缺失时能拒答，误导时仍有 41.6% 被回答且 63% 复述植入的错误实体**；冲突检查降到 13.3% 但牺牲大量正确答案；NLI 验证器在"参数记忆与误导段落同向"时失效。→ https://aclanthology.org/2026.aacl-long.153/
**为什么值得注意**：它把"拒答"从一个提示词技巧，变成了一个需要独立判别器的**系统能力**。

**② 拒答可以被独立训练且优于 softmax 置信（arXiv:2509.04482）**
260 万条指南问题上训练能量模型：困难近分布案例 **AUROC 0.961 vs 0.950**、**FPR@95 0.235 vs 0.331**；优势主要来自能量打分头。

**③ "无答案"评测集本身在放水（arXiv:2510.11956）**
CRUMQs 指出既有基准可被"分离式推理"作弊，提出自动构造不可作弊、真实、无答案、多跳查询的流水线，**cheatability 最多下降 81.0%**。

**④ 多跳评测从"孤立检索器"转向"agent 工作流内的效用"（ACL 2026 Long，2026-07）**
Bright-Pro：为每个 query 提供**专家标注 reasoning aspects + 正例文档 + 参考答案 + rubric**，并评估检索器在 agentic 搜索系统中的实际效用；批评既有基准"金标窄 + 孤立评估"。→ https://aclanthology.org/2026.acl-long.1705/

**⑤ 迭代检索的"停"可以学出来（arXiv:2609.16453 / arXiv:2601.17617）**
前者：轨迹派生信号可预测中间答案质量并支持**早停**、减少迭代；后者基于 **1400 万+ 轨迹**建议采用**重复感知早停**与**意图自适应检索预算**。

**趋势观察（非定论）**
2026 年 M3 尾部这两个话题（多跳、拒答）正在收敛到同一句话：**系统的可信度来自"决定不做事"的能力**——不搜了、不答了、或者答但标注不确定。对应的工程形态是**独立的判别组件 + 分层评测集**，而不是继续堆 prompt。**属趋势观察。**
