## 知识点 1：文档解析全链路（R1-01）

### 一句话结论

解析要做的是**把一页图像还原成一棵可寻址的文档树**（块 + 类型 + 层级 + 页码 + 坐标），而不是产出一坨纯文本；中间表示（IR）的字段设计，决定了你后面能不能做层级切分、能不能回溯到原页、能不能定位 L1 失败。

### 为什么重要

- **解析是 L1「检索不到」的第一现场。** 表格被拍平成一行乱序文字、双栏被交错拼在一起、页眉页脚混进正文，这些错误在检索阶段表现为“召回到了但答不出”，你会误判成 embedding 模型不行或 rerank 不够，然后在错误的层上加杠杆。
- **“解析不好”是可分解的。** OmniDocBench（CVPR 2025）把解析拆成版面检测、OCR、表格识别、公式解析、阅读顺序五个可分别打分的子任务，共 1651 页、10 种文档类型、5 种版式、5 种语言。这意味着你可以定位到“我的表格 TEDS 只有 0.4”而不是笼统地说“换个解析工具试试”。

### 核心机制 / 数据流

一条完整的解析链路有六段，每段都有明确的输出契约：

| 段 | 干什么 | 输出契约 | 常见失败 |
|---|---|---|---|
| ① 文档分类 | 判原生文本层 vs 扫描件（部分页可能是混合的） | `page_kind: text / scanned / mixed` | 整本按一种模式处理，扫描页抽出空文本 |
| ② 版面检测 | 切区域并分类：标题 / 正文 / 表格 / 图 / 页眉页脚 / 脚注 / 公式 | `blocks: [{bbox, type}]` | 栏间 gutter 没识别，跨栏合并成一块 |
| ③ 阅读顺序 | 给块排序 | `order: [block_id...]` | 非矩形/环绕版式排序崩，脚注插进正文中间 |
| ④ 内容识别 | OCR 文本、表格转 HTML/CSV、公式转 LaTeX | `content` 按 type 分支 | 密集小字漏行、自回归重复 |
| ⑤ 文档树组装 | 按标题层级把块挂到树上，标注父子 | `node: {level, parent, children}` | 只输出平铺 Markdown，层级全靠后面猜 |
| ⑥ 质量门（QC） | 落库前拦截坏页 | `qc: {char_per_page, empty_ratio, dup_ratio}` | 没有 QC，坏页静默入库，半年后才发现 |

一句话把 ⑤ 说清楚：**你要的产物是 IR，不是 Markdown。** Markdown 可以是从 IR 渲染出来的一种视图，但反过来不行——Markdown 不保页码、不保 bbox、不保块类型，出了 bad case 你无法回答“这句话来自第几页哪一块”。

### 怎么做

1. **先量后选，别先选工具。** 从你的真实语料里抽 200 页，统计三个数：**文本层可用率**（PyMuPDF 能直接抽出多少字符/页）、**表格页占比**、**双栏及以上页占比**。三率都低 → 扫描件为主，直接上 VLM 解析；文本层好、表格少 → 纯文本转换 + 版面规则就够；表格多 → 表格能力是选型的第一权重，别被整体 OCR 分数骗了。
2. **建一个 30 题的下游金标集，用它做解析回归。** 每题标注 `gold_doc + gold_page + gold_span`，评分看**下游 QA 正确率**，不看解析指标。换任何解析工具都先跑这个集——arXiv:2604.04948 的核心结论就是这个：元数据增强与层级感知切分对最终准确率的贡献，**大于换转换框架本身**（Docling + 层级切分 + 图像描述 94.1%，naïve PDFLoader 86.2%，人工整理 Markdown 91.3%）。
3. **定义你的 IR schema，并把它当成内部标准。** 最小可用字段：
   ```
   Block = {
     doc_id, version, page, bbox[x0,y0,x1,y1],
     type: heading|para|table|figure|formula|footnote|header_footer,
     level: 0..6,        # 标题层级，非标题为 None
     order: int,         # 阅读顺序
     text,               # 或 table_html / latex
     parent_id,          # 文档树父节点
     source_hash         # 内容指纹，用于去重与增量
   }
   ```
   后续切分只读 IR，不再碰 PDF。这样换解析器时，切分/索引/检索一行不用改。

### 权衡与坑

- **纯文本转换 vs VLM 解析是一道明账。** pymupdf4llm、PyPDF 这类方案秒级、无 GPU、几乎零成本，但丢结构；MinerU2.5（1.2B）、dots.ocr、PaddleOCR-VL（0.9B）、SmolDocling（256M）这类 VLM 保结构，但单页延迟高一个到两个数量级、要 GPU、而且会出**自回归重复**这种灾难性失败（一整页刷成同一行）。选型时把“每页成本”和“每页延迟”直接算进 R0-06 的成本模型里，别只比准确率。
- **坑 1：把 Markdown 当唯一产物。** 一旦你只有 Markdown，页码和 bbox 就没了，引用溯源只能做到“来自这个文件”，做不到“来自第 12 页第 3 段”。而带链接的引用（R0-04 的第 7 个组件）恰恰是 RAG 相对纯生成的核心优势。
- **坑 2：只测解析指标，不测下游。** 表格 TEDS 涨了 0.1，但你的业务问题是“这份合同违约金怎么算”，TEDS 跟它对不上。解析指标只用来定位子任务，验收永远看下游。
- **坑 3：没有 QC 门。** 至少要拦三类页：字符数异常低（扫描页没抽出字）、字符数异常高（重复解码）、块类型分布异常（整页只有一个 table 块）。这三条规则加起来不到 30 行代码，但能拦住绝大多数静默失败。

### 架构师视角

把解析层设计成**一个接口 + 多个实现 + 一个回归集 + 一张 QC 报表**：

- 接口只暴露 `parse(file) -> Iterator[Block]`，上游（切分）对具体解析器无感知；
- 实现按文档类型路由（原生 PDF 走快路径，扫描件走 VLM），这本身就是 R0-06 里“per-query 路由级联”在离线侧的同构做法；
- 回归集是资产，不是测试脚本——它是你判断“这次升级值不值”的唯一依据；
- QC 报表按天聚合，出问题先看报表，不要一上来就翻单页。

这样你换解析器的成本是“跑一次回归集”，而不是“重跑全量索引 + 重新调 prompt”。

### 自测（先别翻答案）

2. 假设有人提议“把 pymupdf4llm 换成 MinerU2.5”，你用什么数据决定同不同意？请说出至少两个必须看的指标，并说明为什么不能只看解析 benchmark 分数。

## 知识点 2：版面分析与阅读顺序（R1-02）

### 一句话结论

多栏文档里最贵的错误不是 OCR 认错字，而是**阅读顺序错**：它会把两段不相干的文字粘成一个“语义单元”，而 embedding 和 rerank 都无法识别这种错误——它们只会觉得“这段话说得有点怪”。

### 为什么重要

- **顺序错误是“不可见”的错误。** 字符错误肉眼可见，顺序错误在纯文本里完全看不出来，直到你读答案时发现“这句话缺了主语”。而检索层的一切指标（recall、precision）都是对的，因为召回的那一块确实包含答案的一半。
- **它有硬数字，而且比想象中严重。** 2026-07 的 *Reading Order Inference for Complex Document Layouts* 在 OmniDocBench 多栏英文子集（140 页）上测得：图方法 88% macro edge accuracy，递归 XY-cut（PaddleOCR PP-StructureV3）75%，LayoutReader 只有 25%（词级 vs 行级粒度错配导致迁移失败）。也就是说，“业界默认做法”在复杂版式上仍有四分之一的边是错的。

### 核心机制 / 数据流

三条技术路线，对应三种失败模式：

1. **几何递归切分（XY-cut 及其变体）。** 找页面上的水平/垂直空白投影，递归切到最小单元，再按“先上后下、先左后右”排序。优点是无训练、可解释、极快；缺点是**只认矩形**——遇到环绕式版式（正文被注释围在中间，如 Glossa Ordinaria）、非凸区域、跨栏图表就崩，且贪心选边会产生级联的“edge-theft”（把本该属于 B 栏的行抢给 A 栏）。
2. **学习式序列模型（LayoutReader 一类）。** 把（文本 + 坐标）编码后逐词预测顺序。在训练分布内很强，但**粒度错配**是致命伤：训练在词级、推理在行级，就会出现上面 25% 那种断崖。
3. **图方法 + 语言模型打分（2026 新路线）。** 每条 OCR 行 = 一个节点，边分 = 两个轻量 LM 信号的加权集成（causal LM 的条件似然 + BERT 的 NSP），全局顺序 = **度约束有向路径覆盖**；为了避免贪心选边的级联错误，用 **max-regret** 规则优先做“机会成本最高”的承诺。它是 training-free 的，镜像翻转下误差 <1 个百分点（XY-cut 2 点，LayoutReader-T 最多 8 点）。

另一条相关的解释框架是**两跳瓶颈**（arXiv:2605.19866）：VLM 解析一页要先做 Hop1（分类并定位版面实体）再做 Hop2（抽取内容）；Hop1 一失败，Hop2 就塌成漏内容、结构畸形或重复解码。解法是在解码器外先跑一个轻量 RT-DETR 检测器，把结果用 DocTags 词汇序列化后**和整页图像一起**注入 prompt（不裁剪页面，保留全局图作为检测噪声时的 fallback）。效果：1 万页 OOD 基准上 markdown F1 从 0.37 → 0.92，代价只有 +15% 墙钟延迟、中位 74 个 prompt token。

### 怎么做

1. **先剥模板，再谈顺序。** 页眉、页脚、页码、水印是“每页重复出现的文本行”。规则很简单：按（页面顶部/底部区域 + 跨页高重复率）聚类，重复率超过阈值（如 60% 的页都出现）就标记为模板块。剥掉它们，能消掉一大类“正文里莫名插进一行页码”的错误。**注意别过度**：真实章节标题在同一文档里也可能重复，所以只对页顶/页底带做，且要求位置方差极小。
2. **按 gutter 分栏，栏内按 y 排序。** 用垂直投影找栏间空白（gutter），得到栏边界；每栏内部再按块的 y 坐标排序，跨栏元素（整宽表格、通栏图）单独提到“跨栏块”列表里，插在它上方最近的栏结束处。这一步能吃掉绝大多数双栏错误，成本接近零，**应该在引入任何模型之前先做**。
3. **用“边界抽查”量化顺序质量。** 从解析结果里随机抽 50 个块边界（块 i 的结尾 + 块 i+1 的开头），人眼看其中 20 个是否语义连贯，算一个**边界错误率**。这个数字比任何 benchmark 都更贴近你的语料，而且能在半小时内得到。边界错误率 > 10% 就说明顺序环节需要换方案。

### 权衡与坑

- **去页眉页脚过度 = 删掉真标题。** 很多报告的章节标题就印在页顶，且格式与页眉高度相似。判据不要只看“位置 + 重复率”，再加一条“字号显著大于正文”，或者干脆保留但打 `type=header` 标签、在切分时排除而不是在解析时删除——**打标签比删除安全**，因为标签可回退。
- **caption 归属。** 图表的标题可能在图上方也可能在下方，表格的标题通常在**上方**（这也是表格抽取里 caption 常被漏掉的原因）。归属错了，用户问“这张图说明了什么”时你召回到的是图的 OCR 残片而不是标题。
- **跨页结构。** 跨页续表、跨页段落（上一页末尾的半句话接下一页开头）必须显式合并，否则你在切分时会把一个完整论证劈成两块，两块各自都不足以回答任何问题。
- **别为了顺序上大模型。** 图方法（LM 打分 + 路径覆盖）是 training-free 的，可以先在一个 140 页子集上验证再决定是否进生产；直接上 VLM 端到端解析会把“顺序问题”和“识别问题”耦合成一个不可分离的黑盒。

### 架构师视角

阅读顺序这件事的正确姿势是**分层防御**，而不是选一个最强的方法：

- 第一层：确定性规则（模板剥离 + gutter 分栏）——免费，覆盖 80% 的页；
- 第二层：结构信号（字号、缩进、编号模式）——便宜，处理标题层级；
- 第三层：模型（图方法或 VLM 的 layout prior）——昂贵，只对第一二层置信度低的页启用；
- 第四层：**监控**——边界错误率作为持续指标，而不是一次性验收。

这四层和 R0-06 的“路由级联”是同一个思想：昂贵的手段只用在必要的地方。另外，顺序错误应该有一个**可观测出口**：给每个块存 `order_confidence`，检索命中低置信块时在答案里降权或加提示，这比事后归因便宜得多。

## 今日前沿插入

> 只写有实质更新、且能核验来源的内容；没有就写“本期无重大更新”，不要硬凑。

- **【论文结论】解析框架的胜负，取决于下游而不是解析指标。** *From PDF to RAG-Ready*（arXiv:2604.04948，2026-03-30 v1 / 05-25 v2，Applied Sciences 16 (2026) 5069）在 36 份葡语行政文档（1706 页）上用 50 题、LLM-as-judge、每配置 50 次独立运行做了系统对比：naïve PDFLoader 86.2%，人工整理 Markdown 91.3%，**Docling + 层级切分 + 图像描述 94.1 ± 1.6%**（超过人工整理）。表格类问题的基础切分与层级切分相差 **33 个百分点**；探索性 GraphRAG 只有 82%，低于基础 RAG。它的结论对架构师最有用的一句是：**元数据增强与层级感知切分的贡献大于换转换框架本身**。
- **【论文结论】阅读顺序在复杂版式上仍远未解决，而且默认方案比想象中差。** *Reading Order Inference for Complex Document Layouts*（arXiv:2607.01018，2026-07-01）用 training-free 的图方法（行=节点、LM 打分边、度约束路径覆盖 + max-regret）在 OmniDocBench 多栏英文子集上做到 **88% macro edge accuracy**，而递归 XY-cut 为 **75%**、LayoutReader 为 **25%**（词级/行级粒度错配）。环绕式 Glossa 版式上差距更大：95% vs 50%。
- **【论文结论】VLM 解析的失败可以被“提前消解”，而不必换模型。** *Structured Layout Priors*（arXiv:2605.19866）把失败归因为 Hop1（定位版面实体）失败拖垮 Hop2（抽取内容），用外挂 RT-DETR + DocTags 序列化注入 prompt 解决：markdown F1 **0.37 → 0.92**，中文表格 TEDS **0.01 → 0.36**，ViDoRe V3 上的无限循环解码失败全面下降，代价为 **+15% 延迟 / 中位 74 token**。这个“先解 Hop1”的思路可以直接搬到你的 QC 门里。
- **【趋势观察】解析模型在快速“小参数化 + 端到端化”。** 同一批 2025–2026 工作都在压缩模型并合并流水线：MinerU2.5（1.2B，粗到细两阶段，arXiv:2509.22186）、PaddleOCR-VL（0.9B、109 种语言，arXiv:2510.14528）、dots.ocr（单 VLM 联合学版面检测/文本识别/关系理解，arXiv:2512.02498，另提 126 语言的 XDocParse）、SmolDocling（256M，端到端 DocTags，arXiv:2503.11576）。**这是趋势，不是定论**——这些数字多数来自作者自评与同一基准，跨域泛化仍需你自己用 30 题金标集验证。
- **【趋势观察】基准饱和的声音开始出现。** LlamaIndex 2026-02 的博文称 OmniDocBench 已趋饱和、评测方法过于刚性（[链接](https://www.llamaindex.ai/blog/omnidocbench-is-saturated-what-s-next-for-ocr-benchmarks)），Datalab 随后发布 OmniParseBench，把解析评测改成 16,288 个是/否问题、覆盖 2,937 页。这类厂商博客只作为方向信号，不作为结论。
