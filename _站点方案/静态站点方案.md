# 静态站点方案

> 目标：把仓库里挑出来的 markdown 发布成一个公开站点，部署在 GitHub Pages。
> 本文档对应的是**已经建好并在本地跑通的站点**，不是纸上设计。所有数字都是在你这 23 篇真实文档上实测的。
> **已经上线：<https://toccoa.github.io/ai-docs/>**（20 篇 / 40 张图 / 22 个页面），推送 `main` 即自动部署。

---

## 一、结论

**用 VitePress，不要自己写。**

理由不是"开源框架更省事"这种泛泛之谈，而是你这份内容有三个特征，正好都在 VitePress 的默认行为里：

| 你的情况 | VitePress 的默认行为 |
|---|---|
| 23 篇原始 md，纯内容、无版本、无多语言 | 零配置可跑，20 篇全量 `build complete in 1.8s` |
| 图片相对路径引用（`![](图片/xxx.png)`） | 沿用 md 的相对路径，自动哈希进 `assets/` |
| 中文内容 | `lang: 'zh-CN'` 直接切换字体栈与 UI 文案；本地搜索内置 `Intl.Segmenter` 中文分词 |

自己写的话，光是「md → html + 目录 + 搜索 + 深浅色 + 移动端」这一套，就是两三天起步，而且搜狗式的自己实现搜索一定会踩中文分词。

**唯一需要自己写的**是一个 101 行的侧边栏生成脚本（`site/.vitepress/sidebar.mts`），已经写好并在你的真实文件名上跑通了。

## 二、目录结构

**两个板块，一天一个文件夹**：

```
AI 文档/
├── package.json / node_modules/ / .github/workflows/deploy.yml
├── scripts/
│   ├── publish.mjs                ← 发布：复制 + 转 WebP + 重算链接
│   └── optimize-images.mjs
│
├── site/.vitepress/               ← 【站点】只放脚手架，不放文章
│   ├── config.mts                 ← 配置 + 未发布链接降级插件
│   ├── sidebar.mts                ← 扫 content/ 自动生成目录
│   └── theme/{index.ts,custom.css}
│
├── content/                       ← 【已发布】只放挑选进来的
│   ├── index.md                   ← 首页（手写）
│   ├── RAG 学习路线图/
│   │   ├── index.md               ← 板块首页（手写）
│   │   ├── 00-RAG知识地图.md
│   │   ├── 01-学习进度.md
│   │   ├── 02-每日推荐/2026-11-09.md · 11-10 · 11-11
│   │   ├── 04-索引.md
│   │   └── 05-前沿资料/2026-11-10-记忆栈-四层与dreaming.md
│   ├── 每日 AI Agent 技术精选/
│   │   ├── index.md               ← 板块首页（手写）
│   │   ├── 2026-11-09/
│   │   ├── 2026-11-10/            ← 当天 9 篇：日报 / 精讲 / 翻译 / 知识地图
│   │   └── 2026-11-11/
│   └── 图片/ · Anthropic-Agent-Memory-图片/   ← 全站共享，不按天复制
│
└── (原始 md 与图片目录)            ← 完全不参与构建，一个字节没动
```

全站只有三个文件需要手写：`content/index.md`（首页）和两个板块的 `index.md`。其余文章位置、侧边栏、链接全由脚本生成。

**加内容 = 把 md 丢到源目录，跑一次 `publish.mjs`**，站点代码永远不用改。

## 三、为什么这么分（三条实测约束）

这一节是全文最重要的部分，因为这三条都是踩出来的，不是设计出来的。

### 3.1 `node_modules` 必须在仓库根，不能放进 `site/`

`config.mts` 里写的是 `srcDir: '../content'`，即正文目录在项目根**之外**。如果 `node_modules` 待在 `site/` 里：

```
[vite]: Rollup failed to resolve import "vue/server-renderer"
        from "/…/content/原文翻译-Demystifying-Evals-for-AI-Agents.md"
```

原因很朴素：Node 从 `content/xxx.md` 向上找 `node_modules`，会依次检查 `content/`、仓库根、上一级……**永远走不到 `site/node_modules`**。我把软链换成真实的 109 MB `node_modules` 副本，同样失败，所以这不是符号链接的锅。

**解法**：`package.json` 和 `node_modules` 放仓库根，`.vitepress` 留在 `site/`，命令显式传根目录：

```json
"docs:build": "vitepress build site"
```

产物落在 `site/.vitepress/dist/`。

### 3.2 文章一换目录，正文里的相对链接就断（死链 = 构建失败）

这是最反直觉的一条，而且在改成「按板块 + 按日期分目录」之后变得更容易踩。

实测（旧版平铺结构）：把 4 篇里的 2 篇放进 `content/`，构建报错退出：

```
(!) Found dead link ./%E6%B7%B1%E5%BA%A6%E7%B2%BE%E8%AE%B2-LangChain-Eval-Driven-Development
    in file 深度精讲-Anthropic-Demystifying-Evals-for-AI-Agents.md
build error: [vitepress] 4 dead link(s) found.
```

因为精讲文末尾有"系列导航"，链接指向另外两篇精讲——它们没被发布，于是全成死链。**VitePress 默认把死链当致命错误。**

现在结构变了，问题变成两个：

| 情况 | 处理 |
|---|---|
| 链接指向的文章**已发布、只是换了位置** | `publish.mjs` 重算相对路径（见第四节），构建前就修好 |
| 链接指向的文章**从来没发布过** | `config.mts` 的 markdown-it 规则把它降级成灰字 + 悬停提示"该文章尚未发布到本站" |

第二条是兜底，不是主力：一旦"某篇暂时不发"，它的反向链接会被降级而不是 404。已双向验证：只发布 2 篇时降级 4 条；4 篇全发布时降级 0 条、链接原样保留——不会误伤正常链接。

## 四、发布一篇新文章的流程

复制、改名、改链接这一步已经脚本化了，**不要手工 `cp`**：

```bash
# 全部重发（按规则自动分流到两个板块）
node scripts/publish.mjs --all

# 发指定的几篇
node scripts/publish.mjs "深度精讲-xxx.md" "原文翻译-xxx.md"

# 落点不对时手动指定（板块/日期 都可任意给）
node scripts/publish.mjs "某篇.md" --to "每日 AI Agent 技术精选/2026-11-12"

# 只想看会落到哪、还没发哪些
node scripts/publish.mjs --list

# 日报里出现了新的知识点？把知识地图上的链接补上（幂等，跑几次都一样）
node scripts/link-knowledge-map.mjs

npm run docs:dev          # 本地看一眼
git add -A && git commit -m "add: xxx" && git push
```

**落点规则**（`destRelOf()`）：

| 源文件 | 落到 |
|---|---|
| `RAG 每日精进/00-RAG知识地图.md` | `content/RAG 学习路线图/00-RAG知识地图.md`（子目录原样保留） |
| `RAG 每日精进/02-每日推荐/2026-11-09.md` | `content/RAG 学习路线图/02-每日推荐/2026-11-09.md` |
| `深度精讲-LangChain-xxx.md` | `content/每日 AI Agent 技术精选/<日期>/深度精讲-LangChain-xxx.md` |

日期怎么定：**文件名里有 `YYYY-MM-DD` 就用它，没有就用文件的修改时间**（本地时区）。跑 `--all` 时会逐条打印 `<源文件> → <落点>`，落点不对就用 `--to` 覆盖。

注意正文里的 `> 发布：2026-01-09` 是**原文的发布日**，不是入库日，不能用它归类。

`publish.mjs` 干五件事，且**只读原始文件、从不写回**：

1. 按上表把 md 复制进 `content/`
2. 把它引用的图片复制到共享的 `content/图片/…`（**不按天复制**），顺手转成 WebP
3. 图片和文章链接都是相对路径，位置一变就断——所以按"先算出所有落点、再逐篇重写"的两遍法，把正文里每个相对链接的目标改到新位置（只改 `](…)` 里的目标，正文里同名的普通文字不动）
4. 把 `[^1]: 原文链接：…` 改写成 `> 原文链接：…`，绕开"脚注让构建失败"（见 5.2，只改副本）
5. 报告找不到的图片

**侧边栏不需要维护任何表**。`sidebar.mts` 每次启动/build 时重扫 `content/`：

- 顶层目录 = 板块；`SECTION_ORDER` 决定先后
- 带数字前缀的（`00-` `01-` `02-` …）按数字排，文件和子目录共用一套序号，所以 RAG 那条线是原样的顺序
- 日期目录（`2026-11-10`）新的排前面；展开后一天里的几篇固定按「日报 → 精讲 → 翻译 → 知识地图」，规则就是文件顶部那个 `RULES` 数组，加一行即可

```ts
const RULES = [
  { text: '开发日报', tests: [/开发日报-/, /^日报-/] },
  { text: '深度精讲', tests: [/^深度精讲-/, /-精讲-/] },
  { text: '原文翻译', tests: [/^原文翻译-/, /-全文翻译-/] },
  { text: '知识地图', tests: [/知识地图/] },
]
```

用**数组**而不是单条正则，是因为命名有两种句式：`深度精讲-xxx` 和 `Anthropic-Agent-Memory-精讲-xxx`——类别词一个在头一个在尾，单条正则一定漏一种。

标题取首个 `# `，再去掉 `深度精讲：` 这类前缀、截断到 34 字，完整标题挂在 `title` 上（VitePress 的 `text` 字段按 HTML 渲染、不转义）。同一天里精讲和翻译会重名，脚本检测到重名就自动把前缀加回来（`深度精讲｜xxx` / `原文翻译｜xxx`）。

## 五、八个坑，都不报错（或报错方式很误导）

按危险程度排序。前三个中招后**没有任何报错**，只是内容悄悄少了一块。

### 1. `{{ }}` 会被当 Vue 表达式执行，把文字吃掉

`{{DATE}}`、`{{TITLE_1}}` 这类占位符在 md 里会被 Vue 插值，渲染成**空字符串**。实测产物是 `<li></li>`——句子凭空消失，构建零警告。

`RAG 每日精进/03-模板.md` 全篇是 20 多个这种占位符。已在 `srcExclude` 里排除它和所有 `README.md` 作为兜底，但**根本解法是模板文件别进 `content/`**。

### 2. 脚注语法 `[^1]:` 会让构建直接失败

`原文翻译-LangChain-Eval-Driven-Development.md:147` 用了脚注：

```markdown
[^1]: 原文链接：https://github.com/langchain-ai/deepagents/tree/main/libs/evals
```

VitePress **默认不带 `markdown-it-footnote`**，于是 `[^1]:` 被当成"链接引用定义"，整个 URL 被解析成相对路径，然后报死链、构建失败。

如果以后要发布这篇，把那两处改成引用块即可。**这个改写已经内置在 `scripts/publish.mjs` 里了**，所以 `content/` 里的副本天生没有这个问题，原文也不用动：

```markdown
> 原文链接：https://github.com/langchain-ai/deepagents/tree/main/libs/evals
```

### 3. `README.md` 不是目录首页，而且 `nav` 死链不会被检查

`RAG 每日精进/README.md` 的路由是 `/RAG 每日精进/README`，不是 `/RAG 每日精进/`。只有 `index.md` 才是目录首页。

更麻烦的是：**VitePress 的死链检查只看正文链接，不看 `nav` 和 `sidebar`**。我把 nav 指向一个根本不存在的路径，构建依然 `build complete`、零警告，只有点进去才 404。所以 nav 只能手动核对——现在 nav 里只留了首页，就是为了避免这个。

### 4. `base` 写错 = 白屏，且没有任何报错

部署到 `https://<user>.github.io/<repo>/` 这种项目站点，`base` 必须是 `'/repo/'`，不是 `'/'`。写错的症状是首页能开出白底、但 CSS/JS 全 404。

已用环境变量兜住，两边都不用改代码：

```ts
base: process.env.DOCS_BASE || '/'
```

workflow 里注入 `DOCS_BASE: /${{ github.event.repository.name }}/`，本地默认 `'/'`。**如果换成用户站点（`<user>.github.io`），把 workflow 里那行改成 `'/'`。**

### 5. `lang` 只影响字体和文案，不会让排版变好

我分别用 `en-US` 和 `zh-CN` 构建同一页，产物只差 3 处，CSS 实际差异只有两条：

```css
:root:where(:lang(zh)){ --vp-font-family-base: "Punctuation SC", "Inter", … }
:lang(zh){ --vp-code-copy-copied-text-content: "已复制" }
```

也就是说它补了中文标点字体、把"复制"提示换成中文。**它不负责中文行内空格**——曾经以为会，实测不会。已经设成 `zh-CN`，剩下的中文字形回退（PingFang / 雅黑）交给系统，够用。

### 6. 中文搜索够用，但三字术语会漏

本地搜索索引是 MiniSearch 格式（`@localSearchIndexroot.*.js`），全部 21 篇进来时是 **772 KB / 445 条记录**。中文分词用浏览器内置的 `Intl.Segmenter`，实测：

```
"证据链" → 证据 | 链
"闭环"   → 闭 | 环
"归因"   → 归 | 因
```

两字以内的查询都能命中，但 `证据链` 这种三字术语整词搜会漏。**先用默认配置上线**，真觉得不行再加 `miniSearch.options.processTerm` 或换 Pagefind。这一项不阻塞任何事。

### 7. 链接目标里有空格，必须用 `<>` 包起来

你的文件名普遍带空格和中文（`RAG 每日精进/00-RAG知识地图`）。写成普通链接：

```markdown
[RAG 知识地图](RAG 每日精进/00-RAG知识地图)      ← 不渲染，原样输出这串字符
```

markdown-it 在空格处就判定链接结束。两种写法才对：

```markdown
[RAG 知识地图](<RAG 每日精进/00-RAG知识地图>)
[RAG 知识地图](RAG%20每日精进/00-RAG知识地图)
```

前一种会被 VitePress 正确解析并生成 `href="./RAG 每日精进/00-RAG知识地图.html"`。**症状是页面上直接显示 `](` 这些字符**，没有任何报错，所以只能靠肉眼。

顺带一条与之相关的实现细节：判定"这条链接指向的文章发了没有"时，相对链接要相对**当前 md 所在目录**解析，`/` 开头的站内绝对链接才相对 `content/` 根。一开始两者都按 `content/` 根算，结果 `RAG 每日精进/04-索引.md` 里 4 条正常链接被误判成未发布、首页 3 条被误判——**误判的后果是正常链接被降级成灰字，看起来像"忘了发"**。已经按 `env.path` 取当前目录修正，并用"移走一篇再恢复"的回归验证过（降级 2 → 0）。

### 8. 单换行是否换行：`breaks` 的取舍

原文大量使用"一行一条元信息"的块引用：

```markdown
> 原文：https://…
> 作者：Mikaela Grace、Jeremy Hadfield…
> 定位：**补读经典**。
```

markdown 默认把连续行并成一段，渲染出来是挤成一坨的"原文：… 作者：… 定位：…"。开了 `markdown.breaks: true` 后每条独占一行，读起来清楚得多。

代价是**所有**软换行都变 `<br>`。先量过再开的：排除代码围栏后，全站只有 **9/435（2.1%）** 的段落是手工折行的多行段落，且多为两句，影响可忽略。如果哪天补进来大量按 80 列折行的英文原文，把这一行删掉即可。

## 六、部署到 GitHub Pages

**已经上线：<https://blog.093681.xyz/>**（自定义域名，Cloudflare 代理 → GitHub Pages）

- 仓库：<https://github.com/Toccoa/ai-docs>（public，`main`）
- 部署方式：Actions，`https://github.com/Toccoa/ai-docs/actions/workflows/deploy.yml`
- 站点源：Settings → Pages → Source = **GitHub Actions**；Custom domain = `blog.093681.xyz`
- **`base` 必须是 `/`**：站点挂在域名根路径。CI 里 `DOCS_BASE: /`，本地默认也是 `/`
- 旧地址 `https://toccoa.github.io/ai-docs/` 由 GitHub 自动 301 到新域名，不用管

### 6.1 自定义域名为什么一开始是 404

现象：DNS 已经指向 Cloudflare，`curl` 却拿到 404，响应体是 GitHub 自己的 `Site not found · GitHub Pages`。

原因：**GitHub Pages 按 Host 头找站点**。域名只做了 DNS 指向还不够，必须在 Settings → Pages → Custom domain 里登记，GitHub 才认领这个 Host。没登记时它一律回 `Site not found`，和"路径写错"长得一模一样。

两个连带坑：

1. **登记完还必须重新部署一次**。设完 custom domain 不会自动重建，页面要等下一次 `push` 才生效（我当时正好推了 `DOCS_BASE` 的改动，顺手触发了）。
2. **`base` 不改就是白屏**。站点原来按 `/ai-docs/` 构建，HTML 里的资源是 `/ai-docs/assets/...`；挂到域名根后这些请求全部 404，页面能打开但没有样式。所以登记域名和把 `DOCS_BASE` 改成 `/` 必须一起做。

### 6.2 开着 Cloudflare 代理时，GitHub 的 HTTPS 校验过不了

Pages 设置页会一直显示 `DNS Check in Progress`，并且 `Enforce HTTPS` 灰着不可勾（提示 "your domain is not properly configured to support HTTPS"）。

因为 GitHub 校验的是 DNS 记录里能不能看到指向 `toccoa.github.io` 的 CNAME；而 CF 开了橙色云之后，返回的是 CF 自己的 A 记录（`172.67.x` / `104.21.x`），GitHub 看不到 CNAME，于是校验一直不通过。

不影响访问——HTTPS 是 Cloudflare 那一层提供的（证书 `*.093681.xyz`，Let's Encrypt，由 CF 自动续期）。要彻底消掉这个警告，办法是把 CF 里 `blog` 那条记录临时改成 **DNS only（灰云）**，等 GitHub 签发证书、`Enforce HTTPS` 可勾之后再打开橙云，并把 CF 的 SSL 模式设成 **Full (strict)**。

另一个遗留：现在 `http://blog.093681.xyz/` 直接 200（不跳 HTTPS）。在 CF 打开 **Always Use HTTPS** 即可；不要指望 Pages 的 `Enforce HTTPS`，它一直是灰的。

`.github/workflows/deploy.yml` 的版本号对齐官方当前推荐（`checkout@v5`、`setup-node@v6`、`node-version: 24`、`configure-pages@v4`、`upload-pages-artifact@v3`、`deploy-pages@v4`），分 `build` 和 `deploy` 两个 job。

**顺序不能反**：先让仓库里有内容、再把 Pages 的 Source 切成 GitHub Actions，最后才可能有成功部署。我第一次推的时候 Pages 还是 disabled，`build` job 里 `actions/configure-pages@v4` 直接 `HttpError: Not Found`，`deploy` 被 skip——**这个报错完全没提"Pages 没开"**，很容易误判成 workflow 写错。

**`package-lock.json` 必须提交**。workflow 用的是 `npm ci`，没有 lockfile 会直接失败（`npm ci can only install with an existing package-lock.json`）。现在 `npm install` 已经在仓库根生成了它。

另外 `.gitignore` 已经排除 `node_modules/` 和 `site/.vitepress/dist/`。dist 千万不要提交——你的图片有 8.6 MB，构建产物进 git 历史后永远删不掉。

## 八、还没做的（按需再说）

1. ~~**图片压缩**~~ 已做。`scripts/optimize-images.mjs` 把 `content/` 里的 png/jpg 转成 WebP，并把 md 里的引用一起改掉；`publish.mjs` 复制完图片也会自动转。参数是 `MAX_WIDTH = 2400`、`QUALITY = 88`，实测 26 张图 8.6 MB → 2.7 MB（省 69%），dist 12 MB → 6.4 MB。
   - **为什么是 2400 而不是原图 3840**：正文栏最宽 688 CSS px，3 倍屏也就 2064 px；2400 够放大看，再大的像素只是拖慢加载。配图里的中文小字在 2400 px / q88 下仍然清楚（已逐张看过）。
   - **原始 png 一个字节没动**，只转 `content/` 下的副本。所以仓库里现在是「原始 8.6 MB + 副本 2.7 MB」，比之前的「原始 + 8.6 MB 副本」还小了 6 MB。
   - 手动跑：`npm run images`；只看能省多少：`node scripts/optimize-images.mjs --dry`。
2. **frontmatter**。原始 md 全都没有 YAML 头，标题只能靠首个 `# `。如果以后要加日期排序、标签、摘要，可以在复制进 `content/` 时顺手生成——**改副本，不动原文**。

## 九、日常怎么用

```bash
node scripts/publish.mjs "新文章.md"                  # 1. 发布（自动分流 + 转 WebP + 修链接）
node scripts/link-knowledge-map.mjs                  # 2. 日报有知识点 ID 时，知识地图补链接
npm run docs:dev                                     # 3. 本地看，http://localhost:5173
git add -A && git commit -m "add: 新文章" && git push  # 4. 推上去，自动部署
```

推完 1 分钟左右，<https://blog.093681.xyz/> 就是新的。

`publish.mjs` 每次跑完会顺手比对一遍知识地图：发现有知识点已经在日报里讲过、地图上却没链接时，会打印一行
`💡 知识地图有新的知识点可以补链接：node scripts/link-knowledge-map.mjs`（只提示，不改你的原文）。

**知识地图回链是怎么挂的**：日报里的知识点标题写成 `## 知识点 1：RAG 四层失败模型（R0-03）`，
`link-knowledge-map.mjs` 就从括号里的 `R0-03` 找到地图里同 ID 的那一行，在「知识点」列后面补一个
`📄 001 期` 的链接（`00-RAG知识地图.md` + 锚点）。锚点按 VitePress 的 slug 规则算（小写、去掉标点、
空格转 `-`），实测 6/6 对得上。已经挂过的不会重复挂，内容删了也会自动摘掉。

**两个板块各自怎么长**：

- **RAG 学习路线图**：成体系的一条线。把新文件放到 `RAG 每日精进/` 下对应的数字目录，`publish.mjs` 会保持这个结构搬过去，侧边栏按数字自动排好。板块首页那张表是手写的，需要时改 `content/RAG 学习路线图/index.md`。
- **每日 AI Agent 技术精选**：情报流。文件名里带日期（`AI-Agent-开发日报-2026-11-12.md`）就会自动落到 `2026-11-12/`；当天没目录会新建。不带日期的按文件修改时间归，跑的时候会打印落点，不对就加 `--to`。

落地页 `content/index.md` 上的「从哪里读起」是我写的推荐路径，想换直接改那个文件。

要看构建过程和日志：

- Actions：<https://github.com/Toccoa/ai-docs/actions>
- 构建失败的常见原因只有三种：`package-lock.json` 没同步（`npm ci` 报错）、脚注没被改写（死链）、`content/` 里有指向不存在文件的链接。

**本地看效果时注意**：`vitepress preview` 会把文件列表缓存住。改完 `content/` 重新 build 后，如果你复用了同一个 preview 进程，浏览器拿到的可能是**上一版**的 HTML/资源（表现为侧边栏点不动、搜索框没反应、图片 404）。换端口重启，或直接 `npm run docs:dev`。
