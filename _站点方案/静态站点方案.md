# 静态站点方案

> 目标：把仓库里挑出来的 markdown 发布成一个公开站点，部署在 GitHub Pages。
> 本文档对应的是**已经建好并在本地跑通的站点**，不是纸上设计。所有数字都是在你这 23 篇真实文档上实测的。
> **已经上线：<https://toccoa.github.io/ai-docs/>**（20 篇 / 40 张图 / 22 个页面），推送 `main` 即自动部署。

---

## 一、结论

**用 VitePress，不要自己写。**

理由不是"开源框架更省事"这种泛泛之谈，而是你这份内容有三个特征，正好都在 VitePress 的默认行为里：

| 你的情况 | VitePress 的默认行为 |
|---|---|
| 23 篇原始 md，纯内容、无版本、无多语言 | 零配置可跑，20 篇全量 `build complete in 1.8s` |
| 图片相对路径引用（`![](图片/xxx.png)`） | 沿用 md 的相对路径，自动哈希进 `assets/` |
| 中文内容 | `lang: 'zh-CN'` 直接切换字体栈与 UI 文案；本地搜索内置 `Intl.Segmenter` 中文分词 |

自己写的话，光是「md → html + 目录 + 搜索 + 深浅色 + 移动端」这一套，就是两三天起步，而且搜狗式的自己实现搜索一定会踩中文分词。

**唯一需要自己写的**是一个 101 行的侧边栏生成脚本（`site/.vitepress/sidebar.mts`），已经写好并在你的真实文件名上跑通了。

## 二、目录结构

现在是**两个独立文件夹 + 仓库根的脚手架**：

```
AI 文档/
├── package.json                  ← 依赖与命令（docs:dev / docs:build）
├── node_modules/                 ← 必须在仓库根，理由见第三节
├── .gitignore
├── .github/workflows/deploy.yml  ← 推送即发布
│
├── site/                         ← 【站点】只放脚手架，不放文章
│   └── .vitepress/
│       ├── config.mts            ← 站点配置 + 未发布链接降级插件
│       ├── sidebar.mts           ← 扫 content/ 自动生成目录
│       └── theme/
│           ├── index.ts
│           └── custom.css        ← 未发布链接的灰字样式等
│
├── content/                      ← 【已发布内容】你挑选进来的文章
│   └── index.md                  ← 首页（已建）
│
└── (其余原始 md 与图片目录)        ← 完全不参与构建，一个字节都没动
```

`site/` 和 `content/` 的分工是硬的：**收藏夹里加一篇文章 = 往 `content/` 复制一个文件**，站点代码永远不用改。

## 三、为什么这么分（三条实测约束）

这一节是全文最重要的部分，因为这三条都是踩出来的，不是设计出来的。

### 3.1 `node_modules` 必须在仓库根，不能放进 `site/`

`config.mts` 里写的是 `srcDir: '../content'`，即正文目录在项目根**之外**。如果 `node_modules` 待在 `site/` 里：

```
[vite]: Rollup failed to resolve import "vue/server-renderer"
        from "/…/content/原文翻译-Demystifying-Evals-for-AI-Agents.md"
```

原因很朴素：Node 从 `content/xxx.md` 向上找 `node_modules`，会依次检查 `content/`、仓库根、上一级……**永远走不到 `site/node_modules`**。我把软链换成真实的 109 MB `node_modules` 副本，同样失败，所以这不是符号链接的锅。

**解法**：`package.json` 和 `node_modules` 放仓库根，`.vitepress` 留在 `site/`，命令显式传根目录：

```json
"docs:build": "vitepress build site"
```

产物落在 `site/.vitepress/dist/`。

### 3.2 只发布一部分文章，构建会**直接失败**

这是最反直觉的一条。实测：把 4 篇里的 2 篇放进 `content/`，构建报错退出：

```
(!) Found dead link ./%E6%B7%B1%E5%BA%A6%E7%B2%BE%E8%AE%B2-LangChain-Eval-Driven-Development
    in file 深度精讲-Anthropic-Demystifying-Evals-for-AI-Agents.md
build error: [vitepress] 4 dead link(s) found.
```

因为精讲文末尾有"系列导航"，链接指向另外两篇精讲——它们没被发布，于是全成死链。**VitePress 默认把死链当致命错误。**

这对你的场景是致命的：你的核心诉求就是"挑选发布"，而挑选本身就会造成死链。

三种应对，我选了第三种：

| 方案 | 结果 |
|---|---|
| 整个系列一起发布 | 失去了"随便挑"的自由 |
| `ignoreDeadLinks: true` | 构建能过，但点进去 404，读者一脸问号 |
| **构建期把死链降级成灰字**（已采用） | 构建通过，读者看到的是划掉的标题 + 悬停提示"该文章尚未发布到本站" |

实现是 `config.mts` 里一个约 25 行的 markdown-it 规则：遇到 `link_open` 时检查目标 md 是否存在于 `content/`，不存在就把标签换成 `<span class="link-unpublished">`，只留文字。

已双向验证：**只发布 2 篇时降级 4 条**；**4 篇全发布时降级 0 条、链接原样保留**——不会误伤正常链接。

### 3.3 配置改变时，`dist` 位置也跟着变

统一结论：`site/.vitepress/dist/`。上传 `site/` 之外的任何路径都是空目录。

## 四、发布一篇新文章的流程

复制这一步已经脚本化了，**不要手工 `cp`**（会漏图片、会漏脚注改写）：

```bash
# 发一篇（路径写原笔记里的相对路径，可一次给多个）
node scripts/publish.mjs "深度精讲-xxx.md"

# 或者把当前能发的全发一遍（现在是 20 篇 / 40 张图）
node scripts/publish.mjs --all

# 本地预览，左侧目录自动多一项
npm run docs:dev

# 满意就推送，GitHub Actions 自动发布
git add content/ && git commit -m "add: xxx" && git push
```

`scripts/publish.mjs` 干四件事，且**只读原始文件、从不写回**：

1. 把 md 复制进 `content/`，保持原来的相对位置（`RAG 每日精进/…` 仍是子目录）
2. 把它引用到的本地图片一起复制过去，**相对路径因此不变**——这是图片能显示的唯一原因
3. 把 `[^1]: 原文链接：…` 改写成 `> 原文链接：…`，绕开"脚注让构建失败"（见 5.2，只改副本）
4. 打印两种你会在意的提示：哪张图没找到、哪条链接指向了还没发布的文章

**侧边栏不需要维护任何表**。`sidebar.mts` 每次启动/build 时重扫 `content/`，规则是：

- 子目录里的文件 → **目录名就是系列名**（`content/RAG 每日精进/` 整个成为一个分组，子目录再嵌套成"每日推荐"这样的小节）
- 顶层的单文件 → 按文件名前缀归组，规则在文件顶部的 `RULES` 数组里，加一行就能支持新系列：

```ts
const RULES = [
  { text: '深度精讲', tests: [/^深度精讲-/, /-精讲-/] },
  { text: '原文翻译', tests: [/^原文翻译-/, /-全文翻译-/] },
  { text: '开发日报', tests: [/开发日报-/, /^日报-/] },
  { text: '知识地图', tests: [/知识地图/] },
]
```

这里用**数组**而不是单条正则，是因为你的命名有两种句式：`深度精讲-xxx` 和 `Anthropic-Agent-Memory-精讲-xxx`——类别词一个在头一个在尾。单条正则一定会漏掉其中一种。

标题取首个 `# `。你的真实 H1 有 40–60 字（`深度精讲：Demystifying evals for AI agents（Anthropic Engineering · 2026-01-09 / 修订 2026-10-18）`），直接塞进 260px 的侧边栏会换行撑爆。脚本做了截断到 34 字，并把完整标题挂在 `title` 属性上（VitePress 的 `text` 字段按 HTML 解析，不转义，所以 `<span title="…">` 有效）。

## 五、八个坑，都不报错（或报错方式很误导）

按危险程度排序。前三个中招后**没有任何报错**，只是内容悄悄少了一块。

### 1. `{{ }}` 会被当 Vue 表达式执行，把文字吃掉

`{{DATE}}`、`{{TITLE_1}}` 这类占位符在 md 里会被 Vue 插值，渲染成**空字符串**。实测产物是 `<li></li>`——句子凭空消失，构建零警告。

`RAG 每日精进/03-模板.md` 全篇是 20 多个这种占位符。已在 `srcExclude` 里排除它和所有 `README.md` 作为兜底，但**根本解法是模板文件别进 `content/`**。

### 2. 脚注语法 `[^1]:` 会让构建直接失败

`原文翻译-LangChain-Eval-Driven-Development.md:147` 用了脚注：

```markdown
[^1]: 原文链接：https://github.com/langchain-ai/deepagents/tree/main/libs/evals
```

VitePress **默认不带 `markdown-it-footnote`**，于是 `[^1]:` 被当成"链接引用定义"，整个 URL 被解析成相对路径，然后报死链、构建失败。

如果以后要发布这篇，把那两处改成引用块即可。**这个改写已经内置在 `scripts/publish.mjs` 里了**，所以 `content/` 里的副本天生没有这个问题，原文也不用动：

```markdown
> 原文链接：https://github.com/langchain-ai/deepagents/tree/main/libs/evals
```

### 3. `README.md` 不是目录首页，而且 `nav` 死链不会被检查

`RAG 每日精进/README.md` 的路由是 `/RAG 每日精进/README`，不是 `/RAG 每日精进/`。只有 `index.md` 才是目录首页。

更麻烦的是：**VitePress 的死链检查只看正文链接，不看 `nav` 和 `sidebar`**。我把 nav 指向一个根本不存在的路径，构建依然 `build complete`、零警告，只有点进去才 404。所以 nav 只能手动核对——现在 nav 里只留了首页，就是为了避免这个。

### 4. `base` 写错 = 白屏，且没有任何报错

部署到 `https://<user>.github.io/<repo>/` 这种项目站点，`base` 必须是 `'/repo/'`，不是 `'/'`。写错的症状是首页能开出白底、但 CSS/JS 全 404。

已用环境变量兜住，两边都不用改代码：

```ts
base: process.env.DOCS_BASE || '/'
```

workflow 里注入 `DOCS_BASE: /${{ github.event.repository.name }}/`，本地默认 `'/'`。**如果换成用户站点（`<user>.github.io`），把 workflow 里那行改成 `'/'`。**

### 5. `lang` 只影响字体和文案，不会让排版变好

我分别用 `en-US` 和 `zh-CN` 构建同一页，产物只差 3 处，CSS 实际差异只有两条：

```css
:root:where(:lang(zh)){ --vp-font-family-base: "Punctuation SC", "Inter", … }
:lang(zh){ --vp-code-copy-copied-text-content: "已复制" }
```

也就是说它补了中文标点字体、把"复制"提示换成中文。**它不负责中文行内空格**——曾经以为会，实测不会。已经设成 `zh-CN`，剩下的中文字形回退（PingFang / 雅黑）交给系统，够用。

### 6. 中文搜索够用，但三字术语会漏

本地搜索索引是 MiniSearch 格式（`@localSearchIndexroot.*.js`），全部 21 篇进来时是 **772 KB / 445 条记录**。中文分词用浏览器内置的 `Intl.Segmenter`，实测：

```
"证据链" → 证据 | 链
"闭环"   → 闭 | 环
"归因"   → 归 | 因
```

两字以内的查询都能命中，但 `证据链` 这种三字术语整词搜会漏。**先用默认配置上线**，真觉得不行再加 `miniSearch.options.processTerm` 或换 Pagefind。这一项不阻塞任何事。

### 7. 链接目标里有空格，必须用 `<>` 包起来

你的文件名普遍带空格和中文（`RAG 每日精进/00-RAG知识地图`）。写成普通链接：

```markdown
[RAG 知识地图](RAG 每日精进/00-RAG知识地图)      ← 不渲染，原样输出这串字符
```

markdown-it 在空格处就判定链接结束。两种写法才对：

```markdown
[RAG 知识地图](<RAG 每日精进/00-RAG知识地图>)
[RAG 知识地图](RAG%20每日精进/00-RAG知识地图)
```

前一种会被 VitePress 正确解析并生成 `href="./RAG 每日精进/00-RAG知识地图.html"`。**症状是页面上直接显示 `](` 这些字符**，没有任何报错，所以只能靠肉眼。

顺带一条与之相关的实现细节：判定"这条链接指向的文章发了没有"时，相对链接要相对**当前 md 所在目录**解析，`/` 开头的站内绝对链接才相对 `content/` 根。一开始两者都按 `content/` 根算，结果 `RAG 每日精进/04-索引.md` 里 4 条正常链接被误判成未发布、首页 3 条被误判——**误判的后果是正常链接被降级成灰字，看起来像"忘了发"**。已经按 `env.path` 取当前目录修正，并用"移走一篇再恢复"的回归验证过（降级 2 → 0）。

### 8. 单换行是否换行：`breaks` 的取舍

原文大量使用"一行一条元信息"的块引用：

```markdown
> 原文：https://…
> 作者：Mikaela Grace、Jeremy Hadfield…
> 定位：**补读经典**。
```

markdown 默认把连续行并成一段，渲染出来是挤成一坨的"原文：… 作者：… 定位：…"。开了 `markdown.breaks: true` 后每条独占一行，读起来清楚得多。

代价是**所有**软换行都变 `<br>`。先量过再开的：排除代码围栏后，全站只有 **9/435（2.1%）** 的段落是手工折行的多行段落，且多为两句，影响可忽略。如果哪天补进来大量按 80 列折行的英文原文，把这一行删掉即可。

## 六、部署到 GitHub Pages

**已经上线：<https://toccoa.github.io/ai-docs/>**

- 仓库：<https://github.com/Toccoa/ai-docs>（public，`main`）

- 本地与 CI 的 `base` 分开：本地 `/`，CI 用 `DOCS_BASE=/${{ github.event.repository.name }}/`

`.github/workflows/deploy.yml` 的版本号对齐官方当前推荐（`checkout@v5`、`setup-node@v6`、`node-version: 24`、`configure-pages@v4`、`upload-pages-artifact@v3`、`deploy-pages@v4`），分 `build` 和 `deploy` 两个 job。

**顺序不能反**：先让仓库里有内容、再把 Pages 的 Source 切成 GitHub Actions，最后才可能有成功部署。我第一次推的时候 Pages 还是 disabled，`build` job 里 `actions/configure-pages@v4` 直接 `HttpError: Not Found`，`deploy` 被 skip——**这个报错完全没提"Pages 没开"**，很容易误判成 workflow 写错。

**`package-lock.json` 必须提交**。workflow 用的是 `npm ci`，没有 lockfile 会直接失败（`npm ci can only install with an existing package-lock.json`）。现在 `npm install` 已经在仓库根生成了它。

另外 `.gitignore` 已经排除 `node_modules/` 和 `site/.vitepress/dist/`。dist 千万不要提交——你的图片有 8.6 MB，构建产物进 git 历史后永远删不掉。

## 八、还没做的（按需再说）

1. **图片压缩**。现在 26 张图 8.6 MB，平均 330 KB，单篇最大 6.3 MB。GitHub Pages 单文件上限 100 MB，当前完全没压力。但每天加图的走法建议以后加一步 `sharp` 转 WebP，能砍 70%。
2. **frontmatter**。原始 md 全都没有 YAML 头，标题只能靠首个 `# `。如果以后要加日期排序、标签、摘要，可以在复制进 `content/` 时顺手生成——**改副本，不动原文**。
3. **表格横向滚动**。日报速览表是 7 列，窄屏会被压扁。`custom.css` 里已经给单元格设了 `min-width: 5em` 兜底，真嫌挤再包一层滚动容器。
4. **原始笔记一起进仓库了**（按你的要求）。仓库里既有 23 篇原始 md 与 8.6 MB 图片，也有 `content/` 下的副本，约 17 MB。副作用是同一批图片存了两份——将来嫌大，可以把原始目录移出仓库，站点不受影响。

## 九、日常怎么用

```bash
node scripts/publish.mjs "新文章.md"   # 1. 发布（连图片一起）
npm run docs:dev                      # 2. 本地看一眼，http://localhost:5173
git add -A && git commit -m "add: 新文章" && git push   # 3. 推上去，自动部署
```

推完 1 分钟左右，<https://toccoa.github.io/ai-docs/> 就是新的。要看构建过程和日志：

- Actions：<https://github.com/Toccoa/ai-docs/actions>
- 构建失败的常见原因只有三种：`package-lock.json` 没同步（`npm ci` 报错）、脚注没被改写（死链）、`content/` 里有指向不存在文件的链接。

样式或分组不合预期时，改 `site/.vitepress/` 下的文件就行，跟原始笔记完全隔离。

### 这台机器上做过的一次性配置

- 本机的 `~/.ssh/id_ed25519.pub` 已作为 **`MacBook Pro (dsh)`** 加到 GitHub 账号（指纹 `SHA256:rJlARz8YYcyeLxIBITtpEJGGy3b23q0wltC9fqxe538`）。不想留了就在 Settings → SSH and GPG keys 里删掉。

