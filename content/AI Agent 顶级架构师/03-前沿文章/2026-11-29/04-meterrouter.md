## 为什么今天读这篇

大多数"路由"工作优化的是"这道题该用哪个模型"，隐含假设是"一个智能体、一次调用"。这篇论文把路由扩展到多智能体：它要同时决定**招几个智能体、每个智能体扮演什么角色、每个角色用哪个模型、谁连到谁、什么时候停**，并且这一切要满足一个按查询给定的货币预算——这带来三个对架构决策者重要的结论。第一，它证明了"成本"在多智能体里是**结构性**的而不是"单价 × token 数"——同样的准确率可以通过"缩减通信边"或"降低模型档位"两条完全不同的路径达到，两者的成本结构不同。第二，它给出一个具体的数字参照：在五个基准、三个模型档位上，它与最强 MAS 基线打平（66.72% 对 66.80%），但成本只有后者的约 1/5.5（2.56 vs 14.15 ×10⁻³ 美元/查询），且比 LLM-Debate 便宜约 4 倍。第三，它把"预算"变成了一等输入：同一个训练好的模型，扫一遍预算 B 就能得到一整条成本–准确率曲线——这比"训练多个不同规模的系统"要实用得多。

## 三句话摘要

1. 查询回答的成本由四件事联合决定：招多少智能体、每个智能体的角色与所配 LLM、以及它们之间的通信拓扑；现有路由器大多只隐式处理成本，而固定的"准确率–成本偏好"无法表达"这一次查询我愿意付多少"。
2. MeterRouter 按剩余预算逐步合成协作图（每步选角色 → 选骨干 → 选入边 → 决定是否终止），先用成功执行图做模仿初始化，再用 GRPO 变体联合精调，奖励偏好正确答案并惩罚花费与预算超支。
3. 在五个基准与三档模型池上，它达到与最强多智能体系统相当的准确率（66.72%），成本比最强 MAS 路由器低 82%，并把准确率–成本前沿推到单智能体系统上限之外，同时把花费适配到指定预算、极少超支（各预算下合规率 ≥ 99.98%）。

## 译文

### 摘要

基于大语言模型（LLM）构建的多智能体系统（MAS）优于单智能体系统，但智能体之间的通信带来可观的 token 开销。虽然给每个智能体都配一个大模型很常见，但这导致资源利用低效，使系统远离帕累托前沿。回答一个查询的成本由以下因素共同设定：招多少智能体、每个智能体被分配的角色与 LLM、以及它们之间的通信拓扑。大多数现有路由器只隐式地处理成本，而非把它作为显式的优化约束。固定的准确率–成本偏好也无法表达调用方愿意为某个特定查询付多少钱。我们提出 MeterRouter，一个预算感知的动态路由器：它以查询与按查询给定的货币预算为条件，通过选择每个智能体的角色、LLM、入边与终止时机，增量式地合成一个协作图。我们先用模仿成功执行图来初始化路由器，然后用 Group Relative Policy Optimization（GRPO）的一个变体联合精调其决策，其奖励偏好正确答案、惩罚花费与预算超支。在五个基准与一个三档 LLM 池上，MeterRouter 是（1）准确的：性能与最强的 MAS 相当；（2）经济的：以比最强 MAS 路由器低 82% 的成本达到该准确率，并把准确率–成本前沿推进到单智能体系统上限之外；（3）可控的：按指定预算调整花费，且极少超支。

### 1 引言

基于大语言模型（LLM）的智能体在攻克超出封闭推理与文本边界的复杂任务上展现了出色能力（Schick et al., 2023），并具备上下文感知记忆（Zhang et al., 2024）、工具使用（Qin et al., 2024）等外部能力。然而单智能体架构在执行多步推理（Wei et al., 2022；Valmeekam et al., 2023）、适应动态环境（Yao et al., 2023）、或在长时域上保持连贯（Park et al., 2023；Sun et al., 2026）时常常吃力。为应对这些挑战，多智能体系统（MAS）已成为主导范式，它通过精心设计的智能体间通信拓扑、集体智能（Chen et al., 2024c；Wang et al., 2025a）、专门化角色分配（Hong et al., 2024；Qian et al., 2024）与动态错误恢复（Shinn et al., 2023；Du et al., 2024；Gou et al., 2024），持续优于单智能体。

随着高度易得且异构的 LLM 格局快速扩张，依据能力与成本选择合适的 LLM 越来越受到研究界关注（Yue et al., 2025；Yang et al., 2026；Cai et al., 2025）。尽管 LLM 能力总体随模型规模提升，更小的模型能降低计算成本（Feng et al., 2025）。此外，统一依赖单一模型会带来严重的运营脆弱性，导致服务中断或需求尖峰（Chen et al., 2024a）。LLM 路由被提出用于为每个查询分配合适的 LLM（Dai et al., 2024；Ding et al., 2024；Ong et al., 2025；Feng et al., 2025；Zhang et al., 2026）。通过策略性地分配异构 LLM 来利用模型多样性，是构建 MAS 的一条有前景的路径。

MAS 的协作性能收益依赖于智能体间的信息传递、交换与内化（Zhang et al., 2025a）。这种广泛存在于提示词层面、跨越智能体之间与自我评估的通信引入可观的 token 开销（Wang et al., 2024a），从而在协作协同与 token 效率之间形成根本性权衡。为应对这一点，MAS 拓扑设计已从静态、手工设计的图，转向更灵活、更稀疏的任务自适应拓扑合成范式（Wang et al., 2025b；Zhang et al., 2025b；Li et al., 2026a）。然而这些成本效率方案只在结构编排层面运作，统一分配同质 LLM，未利用异构 LLM。这引出一个关键问题：**如何用异构骨干构建一个预算感知、拓扑自适应的 MAS，在成本效率下优化任务性能？**

对分工难以界定的复杂任务，包含链在内的固定通信拓扑无法对协作智能做出有意义的贡献（Zhang et al., 2025a）。相反，稀疏的任务自适应图能减少冗余角色与边（Zhang et al., 2025b；Li et al., 2026a）。然而独立于模型选择来设计这些拓扑，仍可能导致次优的 MAS 构建。为避免把这两个选择割裂，我们提出 MeterRouter（图 1）：一个联合优化拓扑生成与"LLM 到角色"分配的框架。通过按剩余预算动态裁剪智能体拓扑（Li et al., 2026a）与 LLM 分配，MeterRouter 优化准确率–成本权衡，在取得有竞争力任务性能的同时大幅降低货币消耗。我们的主要贡献如下：➊ **异构 LLM 的自主 MAS 编排**：我们设计 MAS 路由，即动态生成拓扑并分配每个智能体的角色、骨干与入边，系统性地消除静态预定义模板固有的运营冗余与次优 LLM 分配。➋ **预算感知与动态调整**：我们引入一个灵活实用的多智能体框架，按用户为每次查询定义的预算定制。MeterRouter 不采用截断输出的做法，而是用动态剩余预算追踪器自适应重分配资源，实现成本高效的路由。➌ **帕累托优化**：我们引入 MeterRouter，一个平衡任务性能与 token 成本的联合路由机制。在双源降本策略驱动下，它把结构性通信节省与异构容量分配节省结合起来，最小化运营开销。

图 1：MeterRouter 概览。路由器增量式构建 MAS，在计量器追踪的剩余预算下（上、中）选择每个智能体的角色、骨干与入边，或停止。它通过预算条件模仿（阶段 1）与组相对 RL（阶段 2）训练（下）。

### 2 相关工作

**协作拓扑。** MAS 已从固定的交互启发式转向拓扑优化。这一进程沿两个关键轴发生：任务自适应性与结构灵活性。早期框架依赖静态的规范图，如 CoT（Wei et al., 2022）、Reflexion（Shinn et al., 2023）、LLM-debate（Du et al., 2024）与 MACNET（Qian et al., 2025）。这些网络根本性地决定推理性能，但仍与任务无关且计算低效。动态任务自适应框架通过利用执行反馈来引导通信轨迹，超越僵化的启发式（Hong et al., 2024；Dang et al., 2025；Wu et al., 2024）。为消除手工拓扑工程，基于模板的优化框架应用可学习的边重加权与剪枝机制，把冗余的通信拓扑蒸馏为稀疏结构（Zhuge et al., 2024；Wang et al., 2025b；Zhang et al., 2025a）。在模板修改之上更进一步，图生成范式构建自主拓扑：G-Designer（Zhang et al., 2025b）用图自编码器学习任务自适应的协作结构，而 ARG-Designer（Li et al., 2026a）用自回归模型增量式构图。然而现有 MAS 框架常常过度配置计算资源——给所有智能体统一分配顶级 LLM——导致过量的 token 消耗（Yue et al., 2025）。

**LLM 路由。** LLM 路由通过为查询分配合适的 LLM 来优化成本与回答质量之间的帕累托前沿。早期范式依赖顺序级联，如 FrugalGPT（Chen et al., 2024a），它迭代查询模型直到满足置信阈值；或基于预测查询难度（Ding et al., 2024）与人类偏好（Ong et al., 2025）的二元路由。在认识到跨 LLM 集成回答优于单一 LLM 之后，近期工作从二元模型选择转向多选路由与输出融合（Dai et al., 2024；Chen et al., 2024b；Feng et al., 2025；Zhang et al., 2026）。把路由扩展到 MAS，MasRouter（Yue et al., 2025）整合了拓扑选择、角色分配与 LLM 路由，但被限制在从一个图目录中选择。ProgRouter（Li et al., 2026b）在工作流流水线上做逐步 LLM 路由。

### 3 问题表述

#### 3.1 符号建立

**搜索空间。** $\mathcal{R}$ 表示 $N_{r}$ 个可用角色的池（例如程序员、分析师），$\mathcal{M}$ 表示 $N_{m}$ 个可用 LLM 骨干的池，每个 LLM 骨干携带一对价格 $(c^{\mathrm{in} }_{m},c^{\mathrm{out} }_{m})$，单位为美元/输入 token 与美元/输出 token。更详细的符号形式见附录 A。

**智能体与边。** 我们把多智能体系统表示为一个有向无环图（DAG）$\mathcal{G}=(\mathcal{V},\mathcal{E})$。节点集 $\mathcal{V}=\{v_{1},v_{2},\cdots,v_{N}\}$ 表示 $N$ 个交互智能体的集合，智能体 $v_{i}$ 是一个实例，配有一个 LLM 骨干 $m_{i}$ 并被赋予特定的角色功能与专长 $r_{i}$，记作 $v_{i}=\{r_{i},m_{i}\},\ r_{i}\in\mathcal{R},\ m_{i}\in\mathcal{M}$。边 $\mathcal{E}\subseteq\mathcal{V}\times\mathcal{V}$ 表示通信通路。一条边 $e_{ji}=(v_{j},v_{i})$ 意味着智能体 $v_{i}$ 是智能体 $v_{j}$ 所传信息的接收方。智能体 $v_{i}$ 的直接前驱集合记为 $\mathcal{N}_{in}(v_{i})=\{v_{j}\mid(v_{j},v_{i})\in\mathcal{E}\}$。

**预算感知。** 对查询 $\mathcal{Q}$，用户有一个支付意愿或预算约束 $B$。本文考虑的成本是货币成本：

$$
C_{i}=c^{\mathrm{in} }_{m_{i} }T^{\mathrm{in} }_{i}+c^{\mathrm{out} }_{m_{i} }T^{\mathrm{out} }_{i}.\tag{1}
$$

剩余预算 $b_{i}$ 是智能体 $i$ 之前剩下的钱，记为：

$$
b_{i}=B-\sum_{j<i}C_{j}.\tag{2}
$$

**观测。** 因此执行智能体 $i$ 会返回一个观测。给定信息 $y_{i}$ 的字节数 $\lvert\tilde{y}_{i}\rvert_{\mathrm{B} }$，记为：

$$
o_{i}=\Big(\ \lvert\tilde{y}_{i}\rvert_{\mathrm{B} },\ T^{\mathrm{in} }_{i},\ \lvert y_{i}\rvert_{\mathrm{chars} },\ T^{\mathrm{out} }_{i}\Big),\tag{3}
$$

其中 $T^{\mathrm{in} }_{i}$ 是发给 $v_{i}$ 的消息的 token 数，$\lvert\tilde{y}_{i}\rvert_{\mathrm{B} }$ 是 $v_{i}$ 传给其后继的消息的字节大小（后继读取它需要付费），而智能体 $i$ 输出消息 $y_{i}$，长度为 $\lvert y_{i}\rvert_{\mathrm{chars} }$ 个字符。$T^{\mathrm{out} }_{i}$ 是输出的 token 数。一条轨迹 $\xi$ 记录该图及其执行所产生的一切：回答 $y_{i}$、LLM 提供方上报的 token 数 $T^{\mathrm{in} }_{i}$ 与 $T^{\mathrm{out} }_{i}$，以及按调用计的成本 $C(\xi)=\sum_{i=1}^{N}C_{i}$。

#### 3.2 预算感知编排

**优化目标。** 令 $\mathcal{P}$ 为查询–预算对的分布。理想的预算感知 MAS 应能在给定预算约束下同时考虑性能与边际成本，优化策略以最大化效用：

$$
\begin{aligned}
\max_{\theta}\quad & \mathbb{E}_{(\mathcal{Q},B)\sim\mathcal{P} }\mathbb{E}_{\xi\sim\pi_{\theta}(\cdot\mid\mathcal{Q},B)}\left[U(\mathcal{Q},B,\xi)\right]\\
\text{s.t.}\quad & \mathbb{E}_{\xi\sim\pi_{\theta}(\cdot\mid\mathcal{Q},B)}\left[C(\mathcal{Q},\xi)\right]\leq B,\quad\forall\,(\mathcal{Q},B)\sim\mathcal{P},
\end{aligned}\tag{4}
$$

其中 $\pi_{\theta}$ 是由路由器与执行环境诱导的策略分布。该效用形式化了回答质量与货币成本之间的权衡。我们引入效用函数：

$$
U(\mathcal{Q},B,\xi)=S(\mathcal{Q},\xi)-\gamma\frac{C(\xi)}{B},\tag{5}
$$

其中 $S(\mathcal{Q},\xi)\in\{0,1\}$ 表示回答是否正确，$\gamma$ 是反映成本敏感度弹性的调节参数。$\gamma$ 越大，对花费的惩罚越重。

**MAS 生成。** 在我们的工作中，MeterRouter 不依赖固定的图模板与确定性的模型选择，而是把 MAS 构造成任意 DAG，以考虑更一般的情形。为此，MeterRouter 在剩余预算下逐步选择每个智能体的角色、骨干与入边，增量式地扩展专家团队。为实现这一点，我们学习一个随机构造策略 $\pi_{\theta}$。它诱导出可行编排图上的分布，记作 $P_{\theta}(\mathcal{G}\mid\mathcal{Q},B,\mathcal{R},\mathcal{M})=P_{\theta}(\mathcal{G}\mid\mathcal{S})$。我们把这个分布分解为一串可处理的、条件决策的序列。在每一步，策略要么终止，要么在给定当前状态的条件下新增一个智能体及其角色、骨干与入边：

$$
P_{\theta}(\mathcal{G}\mid\mathcal{S})=\prod_{i\in\mathcal{I} }\underbrace{\pi_{\theta}(\tau_{i}\mid s_{i})^{I_{i}^{\tau} } }_{\text{终止} }\prod_{i=1}^{\lvert\mathcal{V}\rvert}\left[\underbrace{\pi_{\theta}(r_{i}\mid s_{i})}_{\text{角色} }\underbrace{\pi_{\theta}(m_{i}\mid r_{i},s_{i})}_{\text{骨干} }\prod_{j<i}\underbrace{\pi_{\theta}\left(e_{ji}\mid r_{i},m_{i},\mathbf{e}_{>j,i},s_{i}\right)^{I_{ji}^{e} } }_{\text{边} }\right]\tag{6}
$$

这里 $\mathcal{I}$ 表示已到达的构造步。指示变量 $I_{i}^{\tau}$ 与 $I_{ji}^{e}$ 把由结构约束或预算约束确定性强加的决策，从策略概率中排除。生成第 $i$ 个智能体之前的状态为：

$$
s_{i}=\left(\mathcal{Q},B,b_{i},\mathcal{G}_{<i},o_{<i}\right),\tag{7}
$$

它通过包含查询 $\mathcal{Q}$ 的信息、剩余预算 $b_{i}$、既有图 $\mathcal{G}_{<i}$ 与先前步骤的观测 $o_{<i}$，保持从先前交互中积累的知识与经验。

构造中有三类决策：**智能体生成**，预测角色并从第 4.2 节详述的可行集 $\mathcal{M}_{i}^{m}\subseteq\mathcal{M}$ 中选择骨干；**边生成**，把新进入的智能体与既有智能体相连；以及**终止**，停止构造。

### 4 MeterRouter

基于自回归图生成范式，图生成被设计为实现这种顺序生成过程。MeterRouter 把 $\pi_{\theta}$ 实例化为一个小型循环网络（§4.1），通过追踪剩余预算使智能体意识到可用资源上限（§4.2）。它分两个阶段训练，在推理时以"生成–执行"循环运行（§4.3）。

#### 4.1 模型架构

**输入表示。** 所有文本条件信息（查询、角色描述与骨干）都被映射为稠密向量表示。查询由冻结的 sentence-BERT 文本编码器映射为固定维向量 $\mathcal{Q}\to\mathbb{R}^{D}$ 以提取语义信息，随后做层归一化（LN）。$f_{B}$ 表示对数预算的 $d$ 维嵌入，$\tilde{f}_{\mathcal{Q} }$ 融合查询与预算：

$$
f_{\mathcal{Q} }=\operatorname{MLP}\big(\operatorname{LN}(\operatorname{Enc}(\mathcal{Q}))\big),\quad
f_{B}=\operatorname{MLP}\big(\log B\big),\quad
\tilde{f}_{\mathcal{Q} }=\operatorname{MLP}\big([f_{\mathcal{Q} },f_{B}]\big).\tag{8}
$$

类似地，每个可用智能体角色 $r\in\mathcal{R}$ 被转换为 $z_{r}=\operatorname{MLP}\big(\operatorname{LN}(\operatorname{Enc}(r))\big)$，与查询共享同一个 $\operatorname{MLP}$。它们被收集进角色嵌入矩阵 $\mathbf{Z}\in\mathbb{R}^{\lvert\mathcal{R}\rvert\times d}$。对每个 LLM $m\in\mathcal{M}$，模型信息与其价格拼接：

$$
z_{m}=\operatorname{MLP}\big([\operatorname{Enc}(m),\log c^{\mathrm{in} }_{m},\log c^{\mathrm{out} }_{m}]\big).\tag{9}
$$

把价格编码进隐向量，意味着每个骨干既由其描述、也由其成本来表征。下面的边策略还会显式接收接收方的输入价格。

**状态表示。** 一个门控循环单元（GRU）聚合目前已生成智能体的角色–骨干联合编码 $\{[z_{r_{j} },z_{m_{j} }]\}_{j<i}$，形成历史嵌入 $f^{(i)}_{\mathrm{hist} }$（见式 21）。计量器以一个成本向量 $\phi_{i}$ 进入，它持有已花与剩余预算的份额、以及已用与剩余智能体上限的份额，构成方式为

$$
\phi_{i}=\Big[\frac{B-b_{i} }{B},\,\frac{b_{i} }{B},\,\frac{i-1}{N_{\max} },\,\frac{N_{\max}-i+1}{N_{\max} },\,\psi(B)\Big]\tag{10}
$$

其中 $\psi(B)$ 见式 23，是把对数预算重新缩放、使训练区间 $[B_{\min},B_{\max}]$ 映射到 $[-1,1]$ 的结果。

$f^{(i)}_{\mathrm{cont} }$ 通过一个动态门组合预算条件化的查询，把历史信息与当前信息结合，给出全部上下文信息与成本：

$$
f^{(i)}_{\mathrm{cont} }=(1-g_{i})\cdot f^{(i)}_{\mathrm{hist} }+g_{i}\cdot\tilde{f}_{\mathcal{Q} }+\operatorname{MLP}(\phi_{i}),\quad
g_{i}=\sigma\!\left(\frac{f^{(i)}_{\mathrm{hist} }\cdot\tilde{f}_{\mathcal{Q} } }{\sqrt{d} }\right),\tag{11}
$$

其中 $\sigma$ 表示 sigmoid 函数。式 22 中的 $f^{(i)}_{\mathrm{edge} }$ 通过收集上一个智能体的入边、连同"已扫描前驱"的掩码，并用 MLP 编码，来捕捉其连通模式。

另一个 $\mathrm{GRU}$ 随后根据上下文信息与上一个智能体的连通性，更新节点级状态 $h^{(i)}_{\mathrm{node} }$，记作

$$
h^{(i)}_{\mathrm{node} }=\operatorname{GRU}\Big(\operatorname{MLP}\big([f^{(i)}_{\mathrm{cont} },\,f^{(i)}_{\mathrm{edge} }]\big),\,h^{(i-1)}_{\mathrm{node} }\Big).
$$

**角色。** 一个度量学习模块把隐状态 $h^{(i)}_{\mathrm{node} }$ 投影为"节点意图"嵌入，以预测节点预测分数 $\omega^{i}_{\mathrm{node} }$。$\operatorname{softmax}(\cdot)$ 函数把分数转换为角色选择的概率分布：

$$
\omega^{i}_{\mathrm{node} }=\frac{\operatorname{MLP}(h^{(i)}_{\mathrm{node} })^{\top}\operatorname{MLP}(z_{r})}{\sqrt{d} },\qquad
\pi_{\theta}(r_{i}=r\mid s_{i})=\operatorname{softmax}_{r\in\mathcal{R} }\big(\omega^{i}_{\mathrm{node} }\big).\tag{12}
$$

**骨干。** 角色固定后，路由器分配一个骨干。可行集 $\mathcal{M}^{m}_{i}$ 中的每个候选被独立打分为 $\omega_{m}^{i}$，因此不会有角色落到负担不起的骨干上。$\mathbf{l}_{m}=(\ell_{m}^{\mathrm{in} },\ell_{m}^{\mathrm{out} })$ 表示该骨干在 $\mathcal{M}$ 上标准化后的对数价格。二元组 $\boldsymbol{\psi}(B,b_{i})=(\psi(B),\psi(b_{i}))$ 在同一对数美元尺度上报告分配预算与已实现余额。由于 $b_{i}$ 由计费用量计算，它作为执行反馈进入骨干决策：

$$
\omega_{m}^{i}=\operatorname{MLP}\big([h^{(i)}_{\mathrm{node} },z_{r_{i} },z_{m},f_{B},\mathbf{l}_{m},\boldsymbol{\psi}(B,b_{i})]\big),\quad
\pi_{\theta}(m_{i}\mid r_{i},s_{i})=\operatorname{softmax}_{m\in\mathcal{M}^{m}_{i} }\Big(\omega_{m}^{i}\Big).\tag{13}
$$

**边。** 在 $r_{i}$ 与 $m_{i}$ 固定后，路由器选择与哪些既有智能体 $v_{<i}$ 相连。用一个 GRU 更新隐状态，初值取自节点级状态。对既有智能体 $\{j=i-1,\dots,1\}$，按此逆序扫描，边 GRU 在每一步根据前一个边决策与前驱的长度向量更新状态：

$$
\begin{aligned}
h^{(i,i)}_{\mathrm{edge} }&=\operatorname{MLP}\big(\big[h^{(i)}_{\mathrm{node} },z_{r_{i} },z_{m_{i} }\big]\big),\\
h^{(i,j)}_{\mathrm{edge} }&=\operatorname{GRU}\Big(\operatorname{MLP}\big(\big[e_{j+1,i},z_{r_{j} },z_{m_{j} }\big]\big)+\operatorname{MLP}\big(\boldsymbol{\ell}_{j\to i}\big),\,h^{(i,j+1)}_{\mathrm{edge} }\Big).
\end{aligned}\tag{14}
$$

其中长度向量 $\boldsymbol{\ell}_{j\to i}$ 由观测 $o_{j}$ 与接收方 $m_{i}$ 按式 24 构建，用以描述这条边的资源使用。状态 $h^{(i,j)}_{\mathrm{edge} }$ 随后预测连向智能体 $j$ 的分数，给出边 $e_{ji}$ 的概率：

$$
\omega^{i,j}_{\mathrm{edge} }=\operatorname{MLP}(h^{(i,j)}_{\mathrm{edge} }),\qquad
\pi_{\theta}\big(e_{ji}=1\mid r_{i},m_{i},\mathbf{e}_{>j,i},s_{i}\big)=\sigma\big(\omega^{i,j}_{\mathrm{edge} }\big).\tag{15}
$$

当 $v_{i}$ 必须闭合该图时，来自当前汇点（sink）的边被固定为 $1$ 而非采样。

**终止。** 团队规模由节点状态与预算决定，因此停止可以响应成本向量 $\phi_{i}$ 中不断缩小的余额。终止策略在第 $i$ 步开始时被评估。当可负担集合 $\mathcal{M}^{m}_{i}=\emptyset$ 时终止被强制。终止概率为：

$$
\pi_{\theta}(\tau_{i}=1\mid s_{i})=\sigma\big(\operatorname{MLP}([h^{(i)}_{\mathrm{node} },f_{B}])\big).\tag{16}
$$

**设计理由。** 由于一个智能体的成本 $C_{i}$ 只有在其执行之后才已知，且式 17 中的可行集 $\mathcal{M}^{m}_{i}$ 依赖剩余预算 $b_{i}$，MeterRouter 逐个构建并执行智能体，并把 $b_{i}$ 送入每一个决策头。在每一步内，决策顺序遵循成本的产生方式：终止先来，因为它只依赖剩余预算；角色先于骨干，因为一个智能体所需容量取决于其角色；骨干先于边，因为读取前驱 $v_{j}$ 的成本约为 $c^{\mathrm{in} }_{m_{i} }T^{\mathrm{out} }_{j}$，而边头通过式 24 中的长度向量 $\boldsymbol{\ell}_{j\to i}$ 看到这一点。预算通过对预算的相对份额与对数尺度进入，每个角色或骨干由可行集上的共享函数打分，因此一个模型即可适用于任意规模的预算与 LLM 池。

#### 4.2 计量器

除在策略条件中追踪剩余预算之外，我们还把生成限制在可负担预算之内。因此预算感知由两侧构成。一侧把负担不起的骨干从动作集中移除；另一侧把剩余的钱转换为对即将发出的调用的硬 token 上限。两者都运行在一个刻意保守的、基于字节的估价器上；本节的全部常数与估价器形式见附录 B。

**可负担骨干集。** 令 $\widehat{T}_{i}$ 表示若节点 $i$ 接收来自每个已完成前驱的全部消息时，它将消耗的输入 token 数的上界估计。令 $F_{m}(T)=c^{\mathrm{in} }_{m}T+c^{\mathrm{out} }_{m}q_{\min}$ 为在 $m$ 上执行一次调用、产出预定义最小可接受补全常数 $q_{\min}$ 的地板成本。则：

$$
\mathcal{M}^{m}_{i}=\Big\{m\in\mathcal{M}\;:\;F_{m}\big(\widehat{T}_{i}\big)+R_{i}\leq b_{i}\Big\},\tag{17}
$$

其中 $R_{i}$ 为任一后继的地板成本预留。若 $\mathcal{M}^{m}_{i}=\emptyset$，该步终止。若在第一个智能体之前就没有可负担的 LLM，则该查询被标记为预算受阻（budget-blocked），且不发出任何模型调用。

**价格化补全上限。** 一旦角色、骨干与边被固定，输入消息就确定了，剩余预算便成为补全的硬上限。因此该上限决定节点 $i$ 在剩余预算内可输出多长：

$$
q_{i}=\min\Big\{T_{\max},\;\Big\lfloor\frac{b_{i}-\hat{\rho}_{i}-R_{i} }{\mu_{i} }\Big\rfloor\Big\},\qquad
\mu_{i}=c^{\mathrm{out} }_{m_{i} }+\nu_{i}\,\kappa_{\mathrm{r} }\,c^{\mathrm{in} }_{\underline{m} },\tag{18}
$$

其中 $T_{\max}$ 是每次调用允许的最大补全 token 数，$\hat{\rho}_{i}$ 是估计的输入费用，若仍有后继义务则 $\nu_{i}=1$，$\underline{m}$ 是最便宜的骨干，$\kappa_{\mathrm{r} }$ 把输出 token 转换为它们在下游所变成的输入 token。边际价格 $\mu_{i}$ 有助于对"输出将被再次读取"的那些智能体精确收紧上限。在该估价器下，受保护的轨迹按构造满足 $C(\xi)\leq B$。该估价器是一个上界。

#### 4.3 策略流程

MeterRouter 分两个独立阶段训练，以在良好初始化与对完整动作空间的探索之间取得平衡。第一阶段，策略从一组预生成的监督 MAS $\mathcal{D}_{\mathrm{SFT} }$ 中学习先验 MAS 分布，目标函数是作用在角色与边决策上的加权负对数似然（式 25），思路受 Li et al. (2026a) 启发，如算法 2 所示。该损失没有预算项或骨干项，所以预算只通过 $\mathcal{D}_{\mathrm{SFT} }$ 中的标签进入。

为构建 $\mathcal{D}_{\mathrm{SFT} }$，对每个查询 $\mathcal{Q}$，表 11 所列预定义池 $\mathcal{T}$ 中的每个模板 $t$ 被执行 $K$ 次。每次运行均匀抽取角色，且每个智能体都使用中等价位的骨干。这些运行只执行一次，然后在固定对数间隔网格的每个预算 $B$ 上按经验效用被重新打分：

$$
\begin{gathered}
\hat{u}_{t}(\mathcal{Q},B)=\frac{1}{K}\sum_{k=1}^{K}S(\mathcal{Q},\xi_{t,k})-\frac{\gamma}{B}\cdot\frac{1}{K}\sum_{k=1}^{K}C(\xi_{t,k}),\\
t^{\star}(\mathcal{Q},B)=\arg\max_{t\in\mathcal{T}:\ \hat{c}_{t}\leq B}\ \hat{u}_{t}(\mathcal{Q},B),\qquad\hat{c}_{t}=\frac{1}{K}\sum_{k=1}^{K}C(\xi_{t,k}).
\end{gathered}\tag{19}
$$

我们总是把最大化 $\hat{u}_{t}(\mathcal{Q},B)$ 且成本低于 $B$ 的模板放入 $\mathcal{D}_{\mathrm{SFT} }$，详见算法 1。由于标签随 $B$ 变化，$\mathcal{D}_{\mathrm{SFT} }$ 把每个查询与它在每个预算下最高效用的可负担模板配对。骨干策略在这一阶段被冻结，因此监督塑造的是拓扑与角色，骨干分配留给第二阶段。

第二阶段用同策略强化学习（RL）精调策略，因为其答案可以快速判分，从而学习骨干分配与对执行反馈的响应。对每个训练查询 $\mathcal{Q}$，从 $[B_{\min},B_{\max}]$ 对数均匀地抽取一个预算 $B$ 以获得更好的泛化能力。当前策略 $\pi_{\theta_{\mathrm{old} } }$ 随后在该共同预算下生成并执行一组 $G$ 条轨迹 $\{\xi_{g}\}_{g=1}^{G}$。每条轨迹按效用 $U_{g}=U(\mathcal{Q},B,\xi_{g})$ 打分，其在自己组内的优势记为：

$$
A_{g}=U_{g}-\frac{1}{G}\sum_{g^{\prime}=1}^{G}U_{g^{\prime} }.
$$

令 $\mathcal{K}(\xi)$ 收集 $\xi$ 由策略做出的全部决策，$\rho_{d}(\theta)=\pi_{\theta}(d)/\pi_{\theta_{\mathrm{old} } }(d)$ 为分给决策 $d$ 的 $\pi_{\theta}$ 与 $\pi_{\theta_{\mathrm{old} } }$ 之比。策略以截断代理目标更新：

$$
\mathcal{L}_{\mathrm{RL} }=-\,\mathbb{E}_{\mathcal{Q},B,\,\xi_{1:G}\sim\pi_{\theta_{\mathrm{old} } } }\Bigg[\frac{1}{G}\sum_{g=1}^{G}\frac{1}{Z}\sum_{d\in\mathcal{K}(\xi_{g})}\min\Big\{\rho_{d}(\theta)A_{g},\ \operatorname{clip}\big(\rho_{d}(\theta),1-\epsilon,1+\epsilon\big)A_{g}\Big\}\Bigg],\tag{20}
$$

其中 $Z$ 是第一阶段的演示中决策数的均值，是一个一次性固定的常数。该目标函数沿用 Dr. GRPO（Liu et al., 2025），以奖励效用改进，并隔离 LLM 提供方对 $\xi$ 似然的贡献——那部分不依赖 $\theta$ 且完全是黑盒。通过考虑比值 $\rho_{d}$，我们因而得到整条轨迹的精确似然比。所有参数都在这一阶段训练。细节见算法 3。

推理时参数被冻结，路由器只接收查询 $\mathcal{Q}$ 与预算 $B$。它通过从 $\pi_{\theta}$ 采样在线构建多智能体系统，每一步的决策都基于 MAS 结构与此前所有回答。由于每个智能体在执行并计量之后才做下一个决策，后续每个决策都能基于先前调用实际花了多少钱、返回了什么。答案是最后一个智能体的输出。MeterRouter 把预算 $B$ 作为输入，因此扫一遍 $B$ 就能从同一个训练好的模型得到一族沿成本–准确率曲线的 MAS。详细信息见算法 4。

### 5 实验

#### 5.1 实验设置

**数据集。** 我们在三类任务上评估 MeterRouter：（1）通用推理，用 MMLU-Pro（Wang et al., 2024b）、MuSR（Sprague et al., 2024）与 BBEH（Kazemi et al., 2025）；（2）数学推理，用 Omni-MATH-2（Ballon et al., 2026）；（3）代码生成，用 MBPP+（Liu et al., 2023）。对每个基准，我们把查询划分为互不相交的训练、验证与测试集（表 5）。Omni-MATH-2、MMLU-Pro 与 BBEH 各有 1,000 条测试查询，MuSR 与 MBPP+ 则把训练与验证划分之后剩余的全部查询作为测试集（516 与 138）。

**基线。** 我们把 MeterRouter 与四组方法比较：（1）单智能体方法，即朴素提示与 Chain-of-Thought 提示（Wei et al., 2022）；（2）固定多智能体拓扑，包括 Chain、Tree 与 Complete Graph（Qian et al., 2025）以及 LLM-Debate（Du et al., 2024）；（3）动态 MAS，包括 AutoGen（Wu et al., 2024）、GPTSwarm（Zhuge et al., 2024）与 AgentPrune（Zhang et al., 2025a）；（4）LLM 路由方法，包括 GraphRouter（Feng et al., 2025）、RouterDC（Chen et al., 2024b）、MasRouter（Yue et al., 2025）与显式纳入预算的 BAMAS（Yang et al., 2026）。

**骨干 LLM。** 我们用 gpt-oss-20b、gpt-oss-120b 与 MiniMax-M3 构建一个三档 LLM 池（表 6）。它们的规模从 gpt-oss-20b 的 200 亿总参数增长到 MiniMax-M3 的约 4,280 亿。两个 gpt-oss 模型支持 128K-token 上下文，MiniMax-M3 最多支持 100 万 token。每 token 价格随档位上升：从 gpt-oss-20b 到 MiniMax-M3，输入价格从每百万 token 0.06 美元涨到 0.30 美元，输出价格从 0.19 美元涨到 1.20 美元。该模型支持可扩展的 LLM 池（附录 D.6）。

**实现。** 文本编码器是 all-MiniLM-L6-v2（Wang et al., 2020），每个系统至多 $N_{\max}=5$ 个智能体。角色集沿用 ARG-Designer（Li et al., 2026a）的风格。所有 LLM 调用温度 0.2，每次调用至多 $T_{\max}=32{,}768$ 个补全 token。我们在 $B\in\{1,5,50\}\times10^{-3}$ 上评估，并对 Omni-MATH-2 与 BBEH 增加 $B=4\times10^{-3}$，因为这两个基准的准确率在 $1$ 与 $5\times10^{-3}$ 之间变化最剧烈。每个基准的检查点由验证集选出，我们报告测试集上的结果。所有 LLM 都通过 Ollama Cloud API 访问。

**成本–准确率权衡。** MeterRouter 平均每次查询花费 $2.56\times10^{-3}$ 美元，比 LLM-Debate 少约 $4\times$，比 MasRouter 少约 $5.5\times$。图 2 显示它位于全部五个基准与总体平均的帕累托前沿上，因此没有任何基线同时更准确又更便宜。在总体前沿上，MeterRouter 处在"额外花费不再划算"的那个点上：gpt-oss-120b 上的 LLM-Debate 成本约高 $4\times$，准确率却低 0.02 个百分点。与 BAMAS 相比——后者基于档位的预定义偏好系统性地偏向高档模型（MiniMax-M3）——我们的方法能在中低档模型表现更好时选择它们。

我们再做两个消融以分离两个阶段。第一，为分离图构造与 LLM 分配，我们用单一骨干（gpt-oss-120b）训练 MeterRouter，于是它能构图但不能选模型（附录 D.2）。它只比完整模型低 3.19 个百分点，并且比同骨干的 Chain、Tree 与 Complete Graph 基线更准确且更便宜。第二，我们固定拓扑、只用 RL 训练 LLM 分配（附录 D.3）。该变体位于图 6 的成本–准确率前沿上，说明 RL 单独就能学出高效分配。然而固定拓扑要付出 7.03 到 7.51 个百分点的准确率代价，是"只用单一骨干"所付代价的两倍以上。因此图构造贡献了大部分增益，LLM 分配补上其余部分。

**预算合规。** 几乎每个查询都留在预算之内。在每个测试预算下，预算内比率至少 99.98%（表 8）。罕见超支的原因是：对所有 LLM 使用同一个基于字节的估计，而各 LLM 对输入 token 的计数方式不同。在调用前用每个 LLM 自己的分词器计数输入 token，会使估计变得精确而无需改变框架。届时每次调用都将满足 $C_{i}\leq c^{\mathrm{in} }_{m_{i} }T^{\mathrm{in} }_{i}+c^{\mathrm{out} }_{m_{i} }q_{i}\leq b_{i}$，因此没有查询能超出其预算。附录 D.4 报告每个查询是因学习到的停止、智能体上限还是预算而结束，以及回答被截断或超预算的频率。

**智能体上限。** 智能体上限对准确率影响很小，因为它很少被触及。如图 4 中 MMLU-Pro 所示，大多数运行在达到智能体最大数之前就通过学习到的停止策略终止。在 $N_{\max}\in\{4,5,6\}$ 上，平均准确率变化不到一个百分点（65.85% 到 66.72%，$N_{\max}=5$ 时最高），因此策略自己决定图规模，不依赖调过的上限。

**预算分配。** 图 4 考察在 $N_{\max}=4$ 时 MeterRouter 在 Omni-MATH-2 与 MMLU-Pro 上如何分配额外预算——这是生成的系统随预算变化最大的两个基准。两个基准花掉额外预算的方式不同。在 Omni-MATH-2 上，路由器在每个预算下都为约 92% 的智能体保留 gpt-oss-120b，但构建更大的系统：智能体平均数从 $B=5\times10^{-3}$ 时的 1.22 升到 $5\times10^{-2}$ 时的 3.13，42.5% 的查询使用四个智能体。在 MMLU-Pro 上，团队规模保持在 1.4 个智能体附近，预算转而买了更强的骨干：MiniMax-M3 上的智能体份额从 $B=10^{-3}$ 时的 59% 升到 $5\times10^{-3}$ 时的 93%。右侧面板显示成本在每个水平上都留在预算内，但其分布随预算变化：紧预算下花费聚集在 $B$ 附近，而在 $B=5\times10^{-2}$（预算不再具有约束力）时，各查询之间的差异更大。

图 3：MeterRouter 如何在 OmniMath-2 与 MMLU-Pro 上使其生成的 MAS 适配按查询预算 $B$。左：按使用智能体数划分的查询份额。中：分配给各骨干 LLM 的智能体份额。右：每次查询成本的对数尺度分布。每个小提琴图覆盖从最小到最大成本。图 4：OmniMath-2 上按问题难度（Easy <4，Medium 4–5.5，Hard ≥5.5）的预算使用。左：MeterRouter 在各预算下的准确率。右：从 $B=5\times10^{-3}$ 到 $B=5\times10^{-2}$ 的变化。

**按难度看增益。** Omni-MATH-2 为每个查询赋予一个难度等级，图 4 按难度与预算拆解 MeterRouter 的准确率。左侧面板显示在每个预算下准确率都随难度下降，且预算在更难的问题上更重要。右侧面板显示更大的预算连同更大的智能体团队在中等与困难问题上提升准确率，但在容易问题上收益很小。

**价格变化与可扩展 LLM 池。** MeterRouter 处理新的 LLM 价格与新 LLM，无需对其架构做任何改动。在 MMLU-Pro 上，经价格配对训练后，随着 gpt-oss-120b 的价格从 $0.1\times$ 涨到 $10\times$，把 gpt-oss-120b 分配给第一个智能体的查询份额从 92.1% 降到 0.0%（附录 D.5）。用第四个骨干 Qwen3.8-27B 重新训练后，路由器在 Omni-MATH-2 上增益 2.1 个百分点、在 BBEH 上增益 2.5 个百分点，成本分别高出 8% 与 2%，且仍留在帕累托前沿上（附录 D.6）。

### 6 结论

我们提出了 MeterRouter，它在货币预算下为每个查询构建一个多智能体系统，逐个选择每个智能体的角色、骨干 LLM 与入边连接。由于每次调用都在下一个决策之前被计量，路由器按实际成本花费剩余预算，超支罕见。在五个基准上，它以远低于最强多智能体基线的成本在平均准确率上与之匹敌，并位于成本–准确率帕累托前沿上。

### 伦理声明

本工作旨在通过预算感知路由提升多智能体语言模型系统的成本效率与可及性。我们的实验使用公开基准，并聚焦于在冻结语言模型之间的路由。我们不预期所提出的路由方法会带来特定的伦理问题。然而 MeterRouter 可能继承其底层模型的偏见、事实错误与有害输出。因此负责任部署应包含适当的安全措施、对发送给外部提供方的查询的隐私保护，以及在敏感应用中的人工监督。

## 与路线图的挂接

- **A1-01（模型能力光谱与选型）**：本文把选型问题从"一个查询选一个模型"扩展成"一个查询选一组（角色, 模型）对"。这对分层选型的启示是：真正的分层不发生在请求入口，而发生在**图内部**——同一个查询里，有的节点值得用高档模型（如 Omni-MATH-2 上多数节点保留 gpt-oss-120b），有的节点换成中低档几乎不掉分。因此"先分层，再谈选型"这句话在实践中应该改写成"先确定哪些节点是质量瓶颈，再给非瓶颈节点降档"。
- **A1-06（模型路由与级联降级）**：本文的贡献在于把"判据"本身变成了学习目标。传统级联用置信度阈值作为判据；MeterRouter 直接用"剩余预算 + 已实现的计费成本"作为判据，并且这个判据在每个决策头里都被显式消费（$\phi_i$、$\psi(B,b_i)$）。这印证了路线图里的那句话——**路由器的判据本身就是架构资产**：换模型池、换价格，架构不用变，只需要重新训练判据。
- **A5-05（成本爆炸与预算分配）**：这是本文最直接对应的知识点。"预算要按任务分配，不是按 agent"在这里得到了一个可执行的形态：预算是**按查询**给定的，而 agent 数量、角色、骨干、边都是在这个单一预算内被决定的变量。值得注意的是"双源降本"的拆解——结构节省（少连边）与容量节省（降档）贡献了不同量级的效果，而消融显示结构贡献更大（固定拓扑掉 7.03–7.51 点，单骨干只掉 3.19 点）。如果你的多智能体系统成本失控，先看拓扑，再看模型档位。

## 三个自测问题

1. 论文的效用函数是 $U=S-\gamma C/B$，其中 $S\in\{0,1\}$ 是二值的。这个设计在多智能体场景下有什么风险？如果一个"部分正确"的回答被记为 0 分，路由器会倾向于什么样的策略？
2. 消融显示"固定拓扑 + RL 只学模型分配"就落在成本–准确率前沿上，但准确率掉 7 个点以上。请解释：为什么一个"在前沿上"的方法仍然可能是错误的选择？这说明了单看帕累托前沿会漏掉什么？
3. 预算合规率是 99.98% 而非 100%，原因被明确归为"所有 LLM 共用一个基于字节的估计器"。这个工程细节说明：在多模型路由系统里，哪一个看似无关的组件实际上决定了预算保证能否成立？
