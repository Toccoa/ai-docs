## 知识点 1：五类污染源（E0-05）

### 一句话结论

`分数 = 真值 + 偏差(模型, harness, 环境, 评分器, 抽样) + 噪声`。这五项里，只有第一项是你通常想测的；其余四项在比较时必须被固定或被量化。

### 为什么重要

前面两期已经给出了四个数：harness 差 **29.9pp**、资源配额差 **6pp**、部署形态差 **34pp**、不同 provider 的同一模型通过数 **11/24 vs 13/24**。它们不是"极端情况"，它们是**同一件事的四个侧面：Agent 评测里，模型之外的部件贡献了大量方差**。

如果这五个源不被命名，就会出现两种典型误判：

- **把系统收益当成能力提升**：换了个更好的 agent harness，分数涨了，对外说"模型更强了"。
- **把环境差异当成能力差异**：两个团队跑同一模型差 5 个点，实际是容器内存配额不同。

### 核心机制

| 源 | 机制 | 怎么发现 | 怎么固定/缓解 |
|---|---|---|---|
| **模型** | 权重版本、推理参数、provider 量化、上下文上限 | 记录精确版本 + provider | 固定 provider；报告写全参数 |
| **harness** | 工具接口、上下文管理、终止条件、重试策略、提示词模板 | 换 harness 跑同一批题 | 固定 harness 版本；跨 harness 不比较历史分数 |
| **环境** | 资源配额、依赖版本、网络策略、并发、镜像 | 同配置重跑；看 infra error 率 | 镜像 digest；配额设"下限+上限"两参数 |
| **评分器** | judge 模型替换、rubric 措辞、解析 bug、长度/位置偏差 | 换 judge 重评；与人对照 | 固定 judge 版本；原子二元 rubric；失败要响 |
| **抽样** | 任务难度分布、rollout 次数、聚类方式 | 换任务子集重算；看 CI 宽度 | 分层抽样；pass@k 与 pass^k 并报；按任务聚类 |

三个容易被忽略的细节：

- **provider 也是模型的一部分**。HF 的例子里，同一个 gpt-oss-120b，换 provider 后通过数从 11/24 变 13/24，而且"第一次回复就宣布完成"的比例从 19/24 变 22/24。这不是噪声，是系统差异。
- **环境错误会伪装成模型失败**。资源紧时容器被 OOM kill，分数下降，但失败归因写的是"模型不会做"。
- **评分器会静默失效**。Anthropic 明确提醒：judge 坏掉时可能仍在错误地累计分数，没有告警你永远不知道。

### 怎么做

**第一步：画一张混淆变量表**，五行，每行写"当前值 / 是否固定 / 谁知道"。

**第二步：做一个"两固定三记录"的最小实验**（成本最低的方差分解）：

1. 同配置重跑一遍 → 得到**抽样 + 环境噪声**的底噪；
2. 固定模型与环境，换 harness → 得到 **harness 效应**；
3. 固定 harness 与环境，换模型 → 得到**模型效应**。

三次实验就能粗略排出"哪个源最大"。如果底噪已经接近你想测的差异，后面的实验都不用做了——先加样本量。

**第三步：在报告的脚注里写清楚**：哪些固定了、哪些没固定、没固定的可能带来多大偏差。

### 权衡与坑

- **全固定成本极高**，而且常常做不到（第三方 API 的延迟、云厂商的超卖）。实务上用"**两固定三记录**"：固定 harness 与环境，记录模型、评分器、抽样参数。
- **固定了不等于控制了**。同一镜像在不同机器上跑，资源超卖策略不同，仍然会漂。
- **别把"噪声"当成"可以忽略"**。二项置信区间本身就有 1–2 个百分点宽；基础设施方差是**叠加**在它之上，不是包含在内。
- **换评分器后不要接着画趋势线**。judge 版本变了，旧分数就不可比，应该断开或重算。

### 自测题

1. 两个团队用同一模型跑同一基准，差 5 个百分点。列出你会依次排查的四个源，以及每个源的排查成本。
2. 为什么"同配置重跑一遍"是所有方差分解里性价比最高的一步？
3. 如果你的评测底噪（重跑差异）已经是 4 个百分点，而你宣称某改动带来 3 个点提升，这个结论成立吗？该怎么改实验？

## 知识点 2：评测成本模型（E0-06）

### 一句话结论

一次 rollout 的真实成本是 **token + 环境时长 + 人审 + 机会成本** 四项之和；而**样本量决定了你能检测到的最小差异**——所以正确的顺序是"先定要看的效应大小，再反推预算"，而不是"先跑，跑完看差多少"。

### 为什么重要

- 成本直接决定**评测频率**：跑一次 $225 的评测，你只会在发布前跑；跑一次 $47 的，你可以每天跑。
- 成本决定**样本量**，样本量决定**结论强度**。Anthropic 给的经验下限是：复杂多轮评测 **100 项**起步，简单单轮 **1000 项**起步。
- 成本决定**你敢不敢做对照实验**。做不起对照，就只能做观测，而观测结论不能写"导致"。

### 核心机制

**成本公式：**

```
C = n_tasks × k × ( tokens_per_rollout × p_token
                  + env_minutes × p_env
                  + p_human_review × minutes_review × p_review )

总预算 = C × (1 + 返工率)
```

**最小可检测效应（MDE）的直觉：**

```
SE ≈ sqrt( p(1-p) / n_effective )
n_effective ≈ n_tasks        （同一任务的 k 次 rollout 不独立，按任务聚类）
```

举例：p = 0.6、n_tasks = 100 时，SE ≈ 0.049；95% CI 约 ±10 个百分点。**想稳定看出 3 个点的差异，100 道题远远不够**——除非用配对比较。

**配对比较为什么是"免费的功效"**：让两个模型跑**同一批题**，对**逐题差值**算区间，而不是拿两个聚合分各算各的。题目的难度差异被消掉了，同样的样本量能看到更小的效应。

**预算怎么分**（经验比例，可按团队调整）：

| 用途 | 比例 | 说明 |
|---|---:|---|
| 回归集（每次 PR/每日） | 70% | 稳定、可重复、只增不删 |
| 能力集（每周/每月） | 20% | 覆盖新场景，季度换血 |
| 探索/对抗（按需） | 10% | 找新失败模式，允许不稳定 |

### 怎么做

1. **先写 MDE**："我要能分辨 3 个点的差异" → 反推 n_tasks 与 k。
2. **算一次真实账单**：拿最近一次评测的 token 数、环境分钟数、人审分钟数，套上面的公式，算出"每题每次"的单价。
3. **用测试选择压成本**：20% 预算 + Category Partition，可以在 0.8pp 误差内估成功率（$225 → $47）。
4. **把成本写进报告**：读者需要知道这个结论值多少钱，才能判断该不该信。

### 权衡与坑

- **省钱的三种方式，各自引入偏差**：少跑任务（抽样偏差）、少跑 rollout（低估不稳定）、用小模型预筛（筛掉的可能是难例）。任何一种都要在报告里说明。
- **人审是最容易被低估的成本**。30 条标注看似半小时，加上对齐 rubric、处理分歧，往往是半天。
- **"多跑几次"不能替代"换更好的题"**。样本量压的是随机误差，压不掉构念错误。
- **不要为了跑满预算而跑**。跑 1000 道无区分度的题，不如跑 100 道有区分度的。

### 自测题

1. 你的评测每题每次成本 $0.4，每任务跑 3 次。想检测 2 个点的差异（p≈0.6），大概需要多少道题？用配对比较呢？
2. 为什么"用小模型预筛任务"会系统性高估成功率？
3. 老板问"这套评测一年要花多少钱"，你会用哪四个乘数回答？

## 今日观察

1. **"评测很贵"是个可以被拆解的判断。** 拆成四项之后你会发现，真正贵的往往不是 token，而是人审与返工；而这两项恰好是最容易被自动化掉一部分的。
2. **成本与可信度是同一条曲线的两端。** 想更可信就要更多样本、更多对照、更多人工校准，每一项都加钱。所以"这个结论值多少钱"应该和"这个结论有多可信"一起被报告。
3. **预算约束会反过来塑造方法论。** 跑不起全量，才会去想测试选择；跑不起对照，才会去用配对比较。方法论很多时候是预算的产物。
