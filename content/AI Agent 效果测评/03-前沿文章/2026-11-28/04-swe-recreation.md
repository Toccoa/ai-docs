## 为什么今天读这篇

这篇基准把"只给像素、不给源码"**写进了任务规格本身**：agent 拿不到 DOM、源码、日志、后端，只能像人一样看渲染画面、点鼠标、敲键盘——接口边界一变，"做没做成"就不再是一个通过率能回答的问题。于是评分被拆成四族指标：保真度（做对没有）、转化度（看没看到）、接地度（交互是否真产生了效果）、过程分（花了多少力气）。这是"任务规格决定评分方式"最干净的示范：它没有换任务来制造难度，而是**通过收窄允许动作，把"发现能力"本身变成了考点**。对要自己设计 Agent 评测的人，它另外给了两个可以直接抄的零件：**四级分级得分**，和**强制引用像素证据帧的 judge**。它的克制同样值得注意：所有结论都被明确标为"描述性"，不宣称因果。

## 三句话摘要

1. 任务是**主动黑盒复刻**：agent 面对一个从未见过的真实网站或 Android 应用，只能通过渲染像素 + 指针/键盘交互去探索，然后在不可见的功能清单（54 个应用、**1,446** 条隐藏需求）约束下写出可运行复刻件；交互边界由 runtime 强制，不靠提示词约束。
2. 五个前沿系统在 42 个目标上端到端跑完，最强组合（Kimi Code + Kimi K3）只拿到 **0.530** 加权保真度、**22.9%** 需求被完整复现（应用等权平均），且两个领先者的最大得分档是"部分完成"——**远未解决**。
3. 指标把"没发现"和"发现了但没实现"分开：网页侧自动化/循环类需求微平均得分最低（**0.058**），浏览/导航类最高（**0.487**）；4 位 GUI 专家抽 **20 个样本**复核 judge，**>95%** 的判定被认为正确，但作者强调整体结果只是描述性的。

## 译文

### 1 引言

语言模型 agent 正在从两侧学习与软件打交道。一侧是网页与电脑操作 agent，它们在活的界面里执行长指令；另一侧是编码 agent，它们把截图、规格说明、issue 变成可运行程序。但两条线都建立在一个不太被说出口的假设上：**agent 是被告知要达成什么的**——无论通过明示目标、给定设计稿，还是演示行为。而人类开发者日常面对的是一种更难的处境：一个没有说明书、完全陌生的产品。他们的解法是**用**这个产品，直到理解到足以自己把它造出来。agent 能不能做同样的事，基本还没被检验过。

近期工作朝这个设定靠近过，但都在两种方式中的一种上差了一步。**交互式复刻类基准**把静态截图换成录制的交互视频或标注过的状态转移，然后沿固定轨迹给复刻件打分——证据更丰富了，但"该看哪些行为"是别人替你选好的。**同期的一项工作**允许 agent 自己去探查一个运行中的参考实现，但那是通过代码与工具层访问其内部——它让 agent 读机器，而不是读屏幕。两者都没有回答那个问题：agent 能否像人一样**理解**一个软件。

我们研究的正是这件事，形式是**主动黑盒应用复刻**。agent 拿到一个它从未见过的运行中应用，只允许以人类用户的方式与之交互：它看到渲染后的像素，通过指针与键盘动作，**没有** DOM、源码、日志或后端的访问权。在这个类人接口内，它探索应用、造出可运行的复刻件，并在被评测之前自查。之所以只留像素与指针，是因为这是每个网站和应用都暴露的唯一接口——而在原生、canvas 渲染、远程或受保护的前端里，结构化钩子往往缺失或不可用；不依赖这些钩子的 agent，原则上**人能用哪里它就能用哪里**。扣掉这些捷径，也正是这个任务能真正测自主性的原因：没有结构化的界面地图，也没有人写的提示，agent 必须自己规划探索，并自己判断"学够了没有、可以动手了"。

让任务变真实的这份自由，同时也让它变难——难的方式恰恰是"给定轨迹"会掩盖掉的。因为观测由 agent 自己选，失败可以从三个不同位置进入：**它可能从未发现某个能力；它可能看错了看到的东西；它也可能理解了行为却没能实现出来。** 每一种风险都被三件事放大：部分可观测性；视觉反馈的因果含糊（屏幕上同一处变化，可能来自局部 UI 状态、共享数据、校验，或持久化）；以及**双重意义上的长时程**——先是探索会话本身长，然后是待复刻的有状态工作流也长。所以成功取决于三样能力：自主探索、可持续的长程规划与工具使用、以及把零散观测**编译**成一个功能上忠实的程序。

为度量这些能力，我们提出 **SWE-Recreation**，一个建立在真实网站与移动应用上的基准。每个目标都带一份隐藏的、人工撰写的检查清单，覆盖完整的功能工作流。每条需求都指定：一个具体功能、一段**有序**的交互步骤、以及成功完成时应出现的可观测结果与状态变化——例如先筛选再编辑一个持久化集合，或创建一个对象并在多个视图间确认其一致性。一份显式的**排除集**覆盖任何单机都无法忠实复现的行为：多用户、支付、实时、生成式特性。**一个固定的 judge 模型**通过同样类人的接口评测每个复刻件，但它的交互是**自适应**的：不回放预定义脚本或固定轨迹，而是自己导航复刻件、逐一执行每条指定工作流、把结果行为与预期结果比对，并为每个评级**引用像素证据**。这种自适应评测既能容纳不同的应用结构、也能容纳行为等价的实现，而不必为每个任务手工定制评测脚本；同时它还能把"功能复刻件"和"静态假界面"区分开。在头部保真度之外，我们的指标还区分"agent 发现了什么"与"它实现了什么"，并暴露那些**看起来能用**的输出，从而定位"从感知到代码"这条路径上究竟断在哪一环。

对五个前沿 agent 系统的评测显示，这个任务远未解决：最强者在应用等权平均下达到组合加权保真度 **0.530**，完整复现的需求**不到四分之一**。Kimi 与 DeepSeek 在两个平台分层中都领先，但其余排序随应用组合变化。在网页侧，需求级分析把"低得分"和"低探索证据"分开了：自动化与循环类拿到最低平均得分，浏览与导航类最高，而数学依赖类即使有探索证据也可能失败。

我们的贡献有三点：

- **一个任务**。我们形式化了"主动黑盒应用复刻"：agent 必须仅通过类人接口发现一个陌生应用的功能并重建它，没有特权访问，也没有人写的引导。
- **一个基准**。我们在 **54** 个真实网页与移动应用上构建 SWE-Recreation，含 **1,446** 条隐藏需求，专门压测多步状态变化、跨视图一致性与持久化，并给出"单机不可复现行为"的排除边界。
- **一套评测协议与研究**。我们把功能评级与事后探索估计结合起来，并提供可审计的需求级分析：功能难度、探索证据、以及"在已被证据触达的条件下"的实现情况。

### 2 相关工作

**使用软件的 agent。** 在强多模态模型驱动下，agent 越来越常通过界面操作真实软件：网页 agent 在活的与可复现的网站上跟随指令；电脑操作 agent 把范围扩到桌面与长时程跨应用任务；另有工作针对移动应用与通用助理。一条支撑线提供这类控制所需的感知能力——屏幕解析、网页接地、原生 GUI 动作模型——通常围绕"推理—行动"循环组织。**在所有这些工作中，agent 都被交给一个目标，并被判定能否在已存在的界面里执行该目标；它从不需要先恢复、再复现界面背后的规格。**

**构建软件的 agent。** 互补的一条线要求 agent 生产软件，但依据是**显式规格**：UI-to-code 把截图或设计稿变成前端代码并与原件比对；网站与应用生成类基准从自然语言需求或产品简报出发；编码 agent 在既有仓库里解 issue、实现特性。**这些设定中目标都是被供给的**——截图、原型、需求文档或 issue——所以挑战在于对已知规格的忠实实现。**在我们的设定里，规格是被扣住的，藏在运行中的应用内部**：agent 必须先用交互把它发现出来，然后才能实现它。

**从观测复刻，以及我们的设定。** 与我们最近的是"从观测到的行为复刻"：Interaction2Code 与 InterWebCoder 以标注过的状态转移为条件；IWR-Bench、Video2Code、WebVR 提供录制的交互视频，并沿固定轨迹或视觉评分表给复刻件打分——在这些工作中，**观测都是替模型选好的**。RecreationWorld 则让 agent 探查运行中的参考实现，但通过代码与工具层访问，这与更大范围内"可扩展 agent 环境"的推进方向一致。**SWE-Recreation 的不同在于：agent 只通过类人接口工作，也不接受任何人写的脚手架，因此探索与规划本身就在被考之列**；我们的指标进一步把"发现"与"实现"分开。评分方面，我们建立在 LLM-as-judge 与 agent-as-judge 评测之上：单一 judge agent、模型与配置一致，且每个评级都必须引用像素证据。

### 3 任务形式化

设 `A*` 为源应用，`W = {w_1, …, w_N}` 为一个隐藏的工作流集合，忠实的复刻件必须支持其中每一条。agent 的一次运行通常包含四部分：探索 `A*`、生成可运行复刻件 `Â`、自查，随后进入评测阶段，由评测按 `W` 给 `Â` 打分（见第 5 节）。**`W` 从不向 agent 揭示。**

**类人接口。** 每一步，agent 只能观测一张渲染后的截图与光标位置，只能通过**坐标级**的指针与键盘输入行动（网页侧：点击、拖拽、滚轮、键入；移动侧：点按、滑动、键入、返回）。它拿不到 DOM、无障碍树、源码、网络流量、存储、URL 或选择器；动作回执**只报告动作是否被接受，从不报告它命中了什么**。这条边界由 runtime 强制，而不是靠指令约束。

**自主性。** 探索是开放式的：不提供任务清单、演示、探索计划或笔记格式，只设一个宽松到实际上不构成约束的动作数与时间上限；探查什么、以及什么时候算"学够了"，完全交给 agent。

**输出与范围。** 复刻件由 agent 观测到的东西加上公开的虚构素材（见第 4 节）构成，并且**只按可观测行为评判**：每条 `w_i`（含其状态变化与持久化）能否在屏幕上被执行完成。布局、文案、样式、框架都不在评分范围内，因此**行为等价的复刻件可以通过，而静态假界面不能**。无法在单机上忠实复现或验证的行为——多用户协作、支付、实时数据、生成式特性、外部集成——构成排除集 `X`，既不要求 agent 做，也不计分。

### 4 基准构建

**目标应用。** SWE-Recreation 覆盖 **54 个真实应用：28 个活的网站 + 26 个 Android 应用**，分为六个类别（表 1）。网页侧覆盖社交与内容平台（如知乎、Reddit、YouTube）、生产力与协作工具（如 Notion、Trello、Google 日历）、电商与旅行服务、创意画布（如 Excalidraw、diagrams.net、JS Paint），以及数学、地图与媒体类（如 Desmos、Google 地图、Spotify）；移动侧补充开源的生产力、媒体、工具与游戏应用（如 Joplin、VLC、AnkiDroid、扫雷）。我们挑选的是**有状态、长时程行为丰富**的应用——筛选、编辑持久对象、让同一条记录在多个视图间保持一致——而不是静态展示类应用。由此产生的非确定性与预训练暴露问题在第 A 节讨论。

**检查清单与排除项。** 检查清单由**人在环路**的流水线构建。标注员手工操作每个应用，记录 **20–40** 张截图，覆盖其主要功能与状态转移；一个视觉语言模型（gpt-6-astra）据这段轨迹起草清单；第二位标注员对着运行中的应用核对，删除含糊或不可测的条目。每条需求都指定有序步骤、用**自然语言**（而非机械断言）书写的预期结果，以及持久化与多用户参与两个标记。网页目标还额外带一份标注员撰写的排除清单，记录每个被排除的界面区域、处理方式与理由；**同一份文件同时定义清单与排除项**，因此探索和评测共用同一条边界。

**环境。** 移动目标运行在预装了该应用的容器化 Android 系统中，网页目标运行在受限浏览器里。两种环境中，**MCP 服务器都是 agent 通往设备的唯一桥梁**，只暴露原语工具（截图、点按或点击、滑动或滚轮、键入），同时隐藏所有设备层机制。生成阶段，agent 会拿到一份固定脚手架，以及一个素材包——共享的公开素材加每个目标的虚构内容，因此不需要真实用户数据。网络访问被允许但不必须，不指定任何网页技术栈；移动复刻件则必须指向一个固定的原生技术栈，以产出可安装的应用。

**统计。** 表 1 与图 8 汇总了数据集。54 个应用共 **1,446 条需求，平均每个网站约 30 条、每个移动应用约 23 条**，其中**大约每五条就有一条**要求在重载或重启后保持状态。**438 条网页排除项**由 **213 条硬排除、113 条默认排除、96 条条件排除**组成，另有 **16 条条件纳入**，用于保留某个本被排除的界面中一小块可测的部分；移动目标在构造上就是离线、单用户的，因此不需要排除项。

### 5 评测协议与指标

#### 5.1 协议

judge 通过类人接口在复刻件 `Â` 上逐条执行隐藏工作流 `w_i`，并将其行为与一个参考实例比对。**自适应功能测试**既容纳行为等价的实现，又能暴露"死界面"。

一个**代码层**强制四件事：必须引用观测帧、评级词表封闭、需求覆盖完整、报告 schema 固定；语义判断仍归 judge。**同一个固定模型给所有系统打分**，从而避免更换评测器、也避免自我评测，但这并不消除 judge 偏差。持久化类需求要拿满分，必须同时具备"改动前""已改动""重载或重启后"三段证据。

#### 5.2 记号

对给定目标，令 `R` 为其计分需求集，去掉排除项后 `N = |R|`；令 `R_p ⊆ R` 为被标记为持久化的子集。对每条 `r ∈ R`，judge 返回评级 `g_r ∈ G = {full, partial, placeholder, broken}`、一段理由 `ρ_r`，以及一组被引用为证据的复刻件截图 `E_r`。另一个**独立的覆盖 judge** 在事后运行于探索关键帧上（不影响 agent），对存在覆盖判定的需求返回 `c_r ∈ {0,1}`，对正判定还给出一张证据帧 `f_r`。这里 `c_r = 0` 的含义是**未被证据表明触达过**，而不是"已证实没有探索过"；缺失的判定按未定义处理。正判定也可能只表明找到了入口或走了部分工作流，而非完整执行。令 `O ⊆ R` 表示有可用判定的需求集。评级按下式换算成分数：

```
ω(g) = 1      g = full
ω(g) = 0.5    g = partial
ω(g) = 0.25   g = placeholder
ω(g) = 0      g = broken
```

#### 5.3 指标

我们按"想问什么"给指标分组：**保真度**评估功能结果；**转化度**把探索证据与实现联系起来；**接地度**描述视觉与交互的代理量；**过程分**记录探索投入、自查与平台可靠性。

##### 5.3.1 保真度（Fidelity）

**加权保真度（WFS）** 汇总需求得分：

```
WFS = (1/N) · Σ_{r∈R} ω(g_r)
```

**评级占比（F/P/Pl/B）** 暴露它的构成：`s_g = (1/N) · Σ_{r∈R} 1[g_r = g]`，对 `g ∈ G`。

**持久化保真度（P-WFS）** 把得分限制在持久化需求上：`P-WFS = (1/|R_p|) · Σ_{r∈R_p} ω(g_r)`；当 `R_p` 为空时未定义。

**非功能率（NFR）** 是被评为 placeholder 或 broken 的比例，可跨平台比较。补充性的**网页幻觉率（IR）** 进一步把"理由文本里描述了假造的、纯装饰的或无效行为"计入，通过 `ψ(ρ_r)` 判定，其中 `G_× = {placeholder, broken}`：

```
IR = (1/N) · Σ_{r∈R} 1[ g_r ∈ G_× ∨ ψ(ρ_r) ]
```

##### 5.3.2 转化度（Conversion）

**探索覆盖率（ECov）** 是在可用判定中"被证据表明触达"的比例：`ECov = (1/|O|) · Σ_{r∈O} c_r`。`O` 为空时未定义；**缺失的判定不算作零**。

**发现→实现率（D2I）** 是在已触达条件下的平均得分：

```
D2I = Σ_{r∈O} c_r · ω(g_r)  /  Σ_{r∈O} c_r
```

没有正触达判定时 D2I 未定义。这些指标**不做因果归因**；WFS 也不必等于二者之积，因为未被触达或未被观测到的需求同样可能拿到分数。

##### 5.3.3 接地度（Grounding）

设 `T` 为探索动作数、`M` 为观测数，`δ_m` 为相邻帧的像素变化量，阈值 `ε = 0.002`。**帧数（Frames）** 为 `Σ_m 1[δ_m > ε]`，统计的是**发生变化的观测**，而不是全局唯一状态数。**有效动作率（EAR）** 与**无效动作率（IAR）** 为：

```
EAR = (1/M) · Σ_{m=1..M} 1[δ_m > ε]
IAR = (1/T) · Σ_{t=1..T} ι_t
```

其中 `ι_t = 1` 表示动作被拒绝或抛错。EAR 的分母是**观测数**；视觉变化不一定意味着有用的探索，输入被接受也不保证命中了正确目标。

**覆盖率折减的视觉相似度（VSim）** 使用 ℓ2 归一化的 CLIP ViT-L/14 嵌入 `φ`，以及 `b_r = 1[g_r ≠ broken]`：

```
v_r = c_r · b_r · max_{e∈E_r} φ(f_r)ᵀ φ(e)
VSim = (1/N) · Σ_{r∈R} v_r
```

空的最大值集合取 0。对外导出的评分器在没有探索锚点时直接给零，这与 ECov/D2I"排除缺失判定"的处理不同。我们沿用这些分数、**不重算嵌入**；这个被覆盖率与评级双重门控的量**不是纯感知准确率**。

##### 5.3.4 过程分（Process）

**步数（Steps）** 与**时间（Time）** 分别统计探索动作数与墙钟分钟数，**只度量探索期的交互成本**。**自我修正轮次（SCR）** 统计初始评审之后记录到的复刻件修订次数。**平台归因失败（PAF）** 统计崩溃数加上使环境退化的动作数。平台缺陷会被修复并重跑；**平台正常时的失败仍算能力结果**。PAF 描述的是评测可靠性，不是 agent 能力。

### 6 实验

#### 6.1 设置

我们在同一接口、同一素材、同样实际上不构成约束的交互上限下，端到端评测**五个模型—框架组合**（表 2），不给任务提示，不给特权访问。固定 judge 为 **GPT-6-Astra**，它不在被评测系统之列。**分数刻画的是整个系统**，包括其规划、工具使用与上下文管理。均衡研究覆盖 **16 个共同网站 + 全部 26 个 Android 应用 = 42 个目标、1,111 条需求、210 次运行、5,555 个评级**，每个系统对每个目标跑一次。基准本身仍是 **54 个应用、1,446 条需求**。目标等权，因此"组合"均值把网页层与 Android 层按 **16 : 26** 加权，而不是 1 : 1。Opus 另外三次网页结果单独保留。缺失的诊断项被排除。通过显式的 Android 任务键连接，D2I 被扩展到两个平台；语义分类仍只限网页侧，因为 Android 侧没有经过验证的规格 ID 映射。

#### 6.2 LLM judge 的人工校验

四位受过硕士或博士训练的 GUI 领域专家，通过抽取 **20 个样本**人工复核 LLM judge 的判定。**被复核的判定中超过 95% 被专家认为正确**，这为自动评测器在受复核案例上的可靠性提供了证据。

#### 6.3 保真度

表 2 报告组合的应用宏平均结果。**Kimi 以 0.530 的 WFS 与 22.9% 的满分占比领先**，其后是 **DeepSeek（0.472）、GLM（0.362）、GPT-6-Sol（0.352）、Opus（0.277）**。对两个领先者而言，**部分完成（partial）仍是最大的一档**（图 4–5）。P-WFS 用的是另一个子集，因此它与 WFS 接近**并不能**证明"能用的行为普遍经得起重载"。

#### 6.4 转化度

跨平台看，WFS 与 ECov 的相关为 `r = 0.53`（`n = 208`），与 D2I 的相关为 `r = 0.79`（`n = 199`），部分原因是 **D2I 与 WFS 共享同一批评级**（图 3）。这些合并后的关联也反映了不同的平台混合比例，**不能识别因果效应**。

因此，联合分布才能把"对已观测行为的实现不足"与"探索证据的缺口"区分开——单看聚合保真度做不到这一点。

#### 6.5 接地度

Kimi 拥有最高的组合 VSim（**0.295**）与 EAR（**0.535**），而 Opus 的 VSim 为 **0.118**、EAR 为 **0.376**（表 2–3）。这些相互重叠的代理量**并不能隔离出感知错误**。GPT-6-Sol 的 EAR 高于 DeepSeek（**0.507 对 0.484**），但 WFS 更低（**0.352 对 0.472**）：**仅有视觉变化并不能证明探索有用**。五个待定案例解决后，**全部 130 个 Android 视觉分数**均可获得。

把这些诊断量合起来读，即使单项比率看起来不错，不同系统也呈现出不同的交互画像；**没有任何单一代理量足以概括探索质量**。

#### 6.6 过程分

DeepSeek 平均 **167.9** 个探索步，Kimi 为 **133.9**，其余系统为 **59.4–102.5**（表 3）。Kimi 平均用时 **112.9 分钟**，DeepSeek 为 **45.1 分钟**，所以**更长的动作轨迹不一定意味着更长的实际耗时**。在可获得的记录中 IAR 为零；组合 PAF 每个目标至多 **0.143**。

两个领先者的特征是更长的动作轨迹，但"投入—迭代—保真度"之间的关系要先做控制实验，才能作因果解读。

#### 6.7 目标级分析

对 **513** 条网页需求做语义编码后发现：**自动化/循环类微平均得分最低（0.058），浏览/导航类最高（0.487）**。自动化类**没有任何被触达的配对**，因此 D2I 未定义；**数学依赖类在 31.7% 覆盖率、D2I 为 0.333 的情况下，得分仍只有 0.232**（图 6）。应用等权平均保留了这些端点，但不一定保留中间排序（附录 B）。

**清单构成会限制难度结论**：Trello 的 36 条需求中有 **26 条**涉及自动化；而 Desmos Geometry 的均值 **0.203**、极差 **0.066**，说明其得分普遍偏低。它的交集合成链**在 5 个触达判定中有 2 个为正的情况下仍拿到零分**；Squoosh 的"返回并加载"工作流**在 4 个中有 2 个正判定的情况下拿到满分**。这些对照只作示例，**不用于识别原因**；更细的需求级细节见附录 C.2。

### 7 结论

SWE-Recreation 检验 agent 能否仅通过类人接口探索并重建陌生软件。五个系统最多达到组合 WFS **0.530**；Kimi 与 DeepSeek 在两个平台分层中都领先，而其余排序取决于应用组合。跨两个平台的评级与联合触达证据，把"实现不足"与"探索证据缺口"分开了。要解释这些描述性规律，还需要重复运行、独立标注与受控干预。

## 与路线图的挂接

- **E1-02（任务规格化）**：这篇是"规格四件套"的极端版本——**允许动作被 runtime 收窄到只剩像素与指针**，成功判据被写成可观测的屏幕行为，而"什么不算通过"用显式排除集 `X` 单独定义。它示范了一件事：**规格不是任务的描述，而是判分的边界**；把接口边界写进规格，难度和可判定性同时被改变。
- **E2-04（LLM-as-judge 的工程化）**：一个可以照抄的 judge 骨架——单一固定模型 + 封闭评级词表 + **强制引用观测帧** + 固定报告 schema + 覆盖完整性校验，语义判断留给模型、结构性约束交给代码层。再用 4 位专家抽 20 个样本做一致率校验（>95%），这是"judge 也要被评测"的最小成本落地方式。
- **E3-06（部分成功与分级得分）**：四级评级（1 / 0.5 / 0.25 / 0）加三个补充量（NFR、IR、P-WFS），把"部分完成占主导"这件事实从一句感叹变成了可分解的结构。同时它暴露了分级得分的新偏差：**placeholder 给 0.25 分，等于给"看起来像那么回事的空壳"付钱**，所以才需要幻觉率 IR 来把这部分单独标出来。
- **E4-03（软件工程）**：SWE-bench 家族考的是"在已知规格下改对代码"，这里把规格本身藏进运行中的应用，于是考点前移到**发现规格**。D2I 是这一族基准最缺的那把尺子：它回答"失败是因为没找到，还是因为找到了却写不出来"。
