# 04｜比任务更难：从技术难度到组织难度

> **来源**：arXiv 2611.03494 ｜ **提交**：2026-11-02 ｜ **作者**：Victor Barres、Aden Barton、Nicolai J. Foss、Henrik M. Nielsen
> **原文**：<https://arxiv.org/abs/2611.03494>

> **挂接知识点**：E0-02、E1-02、E1-03、E4-06

## 为什么今天读这篇

它回答了一个我们在做评测时不愿意面对的问题：**为什么模型在榜上越来越强，进了公司却不好用？** 答案不是"模型不够强"，而是**评测把"任务"当成了分析单元，而有经济价值的工作发生在组织里**。作者用一套组织理论分类法审了 522 个知名基准，结论是不到四分之一声称覆盖了任何组织维度。这是一篇会让你重新审视自己评测集"缺了什么"的论文。

## 三句话摘要

1. **技术难度与组织难度是两个独立维度**：技术上很硬的任务可能组织上很简单（材料齐全、无需协作），技术上很简单的任务也可能组织上很难（要审批、要跨部门对齐）。
2. 在 522 个知名基准中，只有 **23%（118 个）声称覆盖任何一个组织维度**，其中 60 个只覆盖了一个；**不到五分之一单独测量**了某个组织维度。
3. 组织维度即使被覆盖也高度单一：有权威结构的 86 个基准里全部是"正式权威"，真实权威只有 4 个；信息结构里"知识掌握在同事手里"的情况，272 个基准中只有 19 个。

## 译文

### 摘要

AI 基准在衡量 AI 系统完成日益困难的技术任务方面取得了显著进展。然而，许多基准把**技术任务**当作分析单元，而有经济价值的工作大量发生在**组织**之中，任务嵌入在一套关系系统里。在组织内，任务的成功不仅取决于解决技术难度，还取决于**驾驭活动的相互依赖、分散的知识、有差异的权威、时间约束、冲突的利益，以及任务进行中不断变化的环境条件**。因此我们主张：**组织任务难度是 AI 能力中一个独立的、尚未被充分认识的维度**；现有基准方法为"AI agent 能多有效地完成真实组织工作"提供了不完整的基础。我们借鉴组织理论，发展出一套**工作结构分类法**，刻画 agent 在组织工作中面对的条件。用这套分类法分析现有基准，我们发现组织维度的覆盖有限且不均衡：**不到四分之一的知名基准声称覆盖其中任何一个维度**。因此我们主张，AI 基准应逐步超越"技术上困难的任务"，转向系统评估 agent 驾驭"有经济价值的工作所赖以发生的组织条件"的能力。

### 1. 问题：基准缺少描述组织条件的词汇

AI agent 越来越多地被用在组织里，但 AI 基准**缺少描述它们所处组织条件的词汇**。现有分类法（如 O*NET）能丰富地描述"工作由什么构成"，却没有对应的东西来描述"任务执行所处的组织环境"。这带来两个后果：第一，**技术任务能力的提升，不必然伴随驾驭组织中的相互依赖、权威与信息结构的能力同等提升**；第二，没有这样的分类法，基准就无法系统刻画它所代表的组织情境、识别它遗漏了哪些重要情境，也无法定位模型成功或失败的来源。

本文的三个贡献：

1. **区分技术任务难度与组织任务难度**，为"为什么模型在技术上明确的基准上快速进步，却可能无法等价地转化为组织内的表现"提供一个概念框架。
2. 提出一套**初步分类法**来表征工作的组织维度，为基准构建、覆盖评估与比较提供共同语言。
3. 用这套分类法**评估现有 AI 基准的组织覆盖**。

合起来，这些贡献指向一个转向：**把 AI 评测的单元，从"孤立的任务"转向"任务在组织中被执行的方式"。**

### 2. 两种难度是独立的

技术难度与组织难度的区分，有助于解释为什么某些技术上相对直白的任务，在组织内却很难完成。两者常常同时存在于同一个任务中，但**可以独立变化**：

- 一个技术上要求很高的任务，如果执行者掌握了相关信息、有权行动、且无需与他人协调，那么它在**组织上是简单的**。
- 反过来，一个技术上简单的任务，如果信息分散在多个行动者之间、必须获得批准、或者成功依赖与他人产出的协调，那么它在**组织上是困难的**。

这种独立性意味着：**简化技术任务，并不必然简化它所处的组织环境；反之亦然。** 由此得到四种任务类型（技术难/易 × 组织难/易）。

### 3. 分类法：四层，六个维度

我们把工作的组织嵌入分成四层：

1. **工作结构**：活动的相互依赖、信息结构、权威结构、时间结构、激励结构，以及环境动态性。
2. **协调需求**：由工作结构产生。
3. **治理机制**：用来应对这些需求。
4. **绩效结果**：这些需求被满足的程度，塑造组织（或单元）层面的结果。

分类法主要聚焦第一层——**行动者（无论人或 AI）面对的组织条件**——并识别出六个维度：

| 维度 | 含义 | 在基准里的典型缺席方式 |
|---|---|---|
| **任务相互依赖** | 活动之间的依赖关系（串行、并行、汇聚） | 任务被设计成单人独立可完成 |
| **信息结构** | 信息是分散的、矛盾的、默会的，还是集中且明确的 | 相关信息在任务开始时一次性给全 |
| **权威结构** | 谁有权做决定、批准链、权限边界 | 只给"书面政策"，没有真实的审批链 |
| **时间结构** | 截止时间、时序依赖、任务进行中的条件变化 | 无时限、无先后依赖 |
| **激励结构** | 各方利益是否一致、是否需要谈判或对齐 | 假设所有参与者目标一致 |
| **环境动态性** | 任务进行中相关条件的变化 | 环境在 rollout 期间静止 |

关键点：**维度不是可以打分的标尺。** 例如，让更多行动者参与，并不必然意味着更高的组织难度——如果他们的活动基本独立，难度并不会上升。**是依赖关系的构型，而不是数量，塑造组织难度。**

### 4. 编码方法

- 用三种方式抽样基准，以捕捉"领域在关注什么"：产业界追踪的、研究界认可的、前沿实验室模型卡里报告的。
- 用 **Claude Opus 5.5（中等推理强度）** 按分类法定义对每篇基准论文编码。
- 对六个维度区分三级证据：**提及**（提到但未纳入）、**声称**（作为基准的一部分）、**测量**（有单独报告的结果）。
- 每个正向标签都必须有论文中的**逐字引用**支撑。
- 第二至第四层（协调需求、治理机制、绩效结果）的编码被视为**探索性**的，因为论文很少把这些写清楚。

这个"提及 / 声称 / 测量"的三分很重要：**一个组织条件出现在基准里，和它被单独测量，是两件不同的事。**

### 5. 结果

**覆盖极低。** 在 522 个知名基准中，**只有 23%（118 个）声称覆盖六个维度中的任何一个**，其中约一半（60 个）只覆盖了一个。

**在上升，但仍低。** 2023 年之前发布的 49 个基准中，只有 **1 个**声称覆盖了组织维度；2026 年发布的 129 个中有 **33%（42 个）**。这一上升部分反映了指数选择追踪的对象变化（近期版本更强调 agent 基准）。

**即使覆盖，也高度单一。** 对每个被声称的维度，我们还记录它覆盖了哪些子成分，结果**大多数声称只依赖该维度的一种形态**：

- **信息结构**几乎完全依赖"矛盾信息"与"分散信息"，"默会知识"只在两个基准中出现。
- **权威**：在 86 个声称有权威结构的基准中，**全部**代表"正式权威"，"真实权威"只出现在 **4 个**里；而现实中权威很少是一条事先写好的规则——可能是多条重叠的、明示与默会交织的权威链，还会动态变化（比如采购金额越过限额就需要经理批准）。
- **与他人协作**几乎完全缺席：需要的信息掌握在同事或组织其他成员手里的情况，在 272 个声称有信息结构的基准中只有 **19 个**。

**后续层更少被写清。** 对约三分之一的被声称维度，论文会说明某种治理机制或评分器检查；**激励是最不发达的**。当治理机制被明确写出来时，通常也非常简单——书面规则或指引、一个联系同事的聊天频道、一个共享追踪表：**提示词本身被当成了治理。**

要特别小心一个解释陷阱：**缺失标签不等于基准里没有这个条件**，只意味着它没有被正式规定。在 235 个被声称的维度中，论文明确说"没有治理机制"的只有 8 个案例，143 个案例是**根本没提**。当基准没有规定治理机制时，agent 就退回到自己的判断，就像不完全合同把空白留给常识去填。

**单独测量更罕见。** 在所有知名基准中，**不到五分之一**单独测量了某个组织维度。一个组织条件可能隐含在基准里并反映在聚合分数中，但**这个分数不会告诉你失败来自技术任务还是来自围绕它的组织条件**。

**"看起来很组织化"的基准确实存在，但不 prominent。** 作为补充分析，作者刻意采用最宽松的选取规则：把六个会议上被归类为"组织类"或"游戏类"的基准全部编码（n = 523）。这些基准在每个维度、每一层上的组织内容都远多于知名基准——但它们很少是最受关注的那些。

**两个反例。** GDPval 与 Remote Labor Index 都建立在真实专业工作之上，但**两者都不声称覆盖六个维度中的任何一个**：在两者中，agent 都是独自工作，相关材料一开始就给全了。它们属于"技术困难"象限——这不意味着它们不真实，只意味着它们测的工作在**组织上不难**。而组织里还有很多更麻烦的工作：护士给一次常规剂量的药，技术上简单，但必须等医生开医嘱、药师核对；律师起草复杂合同并与客户和对方律师谈判，则在两个维度上都难。

### 6. 结论

组织条件在最受关注的基准中**大面积缺失**；即使被表征，也只有约一半的时候被测量。技术能力与组织能力应当被视为 AI 表现的**两个不同维度**，而不是同一能力标尺上的两个点。**技术基准上的进展，不必然意味着组织维度上的进展。**

作者给出的建设性方向：因为分类法刻画的是**组织环境**而不是 agent 本身，评测可以**保持底层技术任务近似不变，只变化组织维度**——从而系统评估 agent 的"组织导航能力"，衡量它不只是多会执行任务，还包括它作为一个嵌入组织的行动者表现如何。

## 与路线图的挂接

- **E0-02 构念效度**：这是"指标测的不是你想测的东西"在**任务层**的版本——不是指标错了，是**任务集本身不代表目标情境**。
- **E1-02 任务规格化**：六个维度可以直接变成任务规格里的可选字段（谁有权批准、信息在哪里、有没有时限）。
- **E1-03 数据集分层**：给你的回归集加一层"组织维度"标签，你会立刻看到它的偏斜。
- **E4-06 基准审计**：读榜单时多问一句"这个基准里的 agent 是独自工作，还是嵌在组织里"。

## 三个自测问题

1. 举一个你熟悉的 Agent 任务，说明它"技术难但组织易"或"技术易但组织难"。如果把它改造成组织难，任务规格要加哪三个字段？
2. 为什么"有权威结构"的 86 个基准里真实权威只有 4 个，会让这些基准上的高分**难以外推**到企业部署？
