## 为什么今天读这篇

每天都在跑回归评测的人，迟早会撞上同一个问题：**全量跑不起，抽样又不知道抽得对不对**。这篇论文把"从 500 道题里选 100 道"做成了一个可评估的工程问题，并且给出了两个目标下各自最优的策略族——**估成功率**用黑盒回归测试的改编策略，**找失败**用 LLM-judge 判难度。对任何要控制评测预算的人，这是 2026 年最实用的一篇。

## 三句话摘要

1. 把基准任务当测试用例，**在不执行 agent、不使用历史结果的前提下**，仅凭任务文本、元数据、代码片段与嵌入就能选出有代表性的子集。
2. 两个目标不可兼得：**估成功率**最强的是"类别划分"（Category Partition），**早期发现失败**最强的是"LLM-judge 判难度"。
3. 在 SWE-bench Verified 上，20% 预算即可把成本从 **$225 降到 $47**，成功率估计的绝对误差只有 **0.8 个百分点**。

## 译文

### 摘要

Agent 式软件系统正越来越多地用于开发流程，而对模型、提示词、脚手架、工具或执行环境的改动都要求反复测试。**选择一部分测试**可以降低测试成本，同时提供 agent 表现的快速估计，或尽早暴露失败以支持失败分析。尽管测试用例选择（TCS）已在深度神经网络和 LLM 代码模型上被研究过，既有工作并未直接针对 Agent 系统，而且往往需要专有 agent 拿不到的模型内部信息。

本文给出**首个针对 Agent 式软件系统的黑盒 TCS 实证研究**。我们把每个基准任务当作一个测试用例，通过把选择准则重新定义在任务描述、元数据、代码片段和嵌入表示上，来改编黑盒回归测试技术。我们还提出了一些新策略，用启发式特征或独立的 LLM-as-judge 评估来**估计任务难度**。我们提出的与改编的策略，都**不执行目标 agent、也不使用过去的结果**。

我们在 **10 个 AI agent 基准**（含 SWE-bench Verified）上评估了 **14 种选择策略**（含随机抽样），每个基准涉及 **12 到 101 个 agent**。我们同时评估"成功率估计"与"早期失败发现"两个目标。**没有单一策略在两个目标上都占优。** 改编的黑盒回归测试策略在成功率估计上最有效，其中 **Category Partition 在 20% 任务预算下，于 10 个基准中的 5 个上取得最低的中位误差**。LLM-as-judge 选择在早期失败发现上更有效。对 SWE-bench Verified 上的 GPT 5.2 Codex，Category Partition 只执行 **100 个而不是 500 个任务**，把执行成本从 **$225 降到 $47**，成功率估计的绝对误差为 **0.8 个百分点**。在同一预算下，LLM-as-judge 选择发现的失败几乎是随机抽样的两倍：**53.0% 的选中任务暴露失败，随机抽样为 27.4%**。

### 1. 引言

AI agent 越来越多地写代码、修问题、与网页交互、执行各类软件工程任务。它们的表现通常用标准基准来评估。随着 agent 演进，对底层模型、提示词、编排、工具或执行环境的改动都要求持续测试。但执行一个完整基准可能很贵：每个任务可能需要多次 LLM 调用、工具交互和代码执行，成本随基准规模增长。例如 SWE-bench Verified 有 500 个任务，SWE-Bench Pro 有 607 个。**如果选出的任务子集能支撑准确的表现估计或帮助尽早暴露失败，那么选择一部分任务就能降低成本、加快反馈。**

软件测试领域早就面对类似挑战：随着测试套件增长，每次改动后执行全部测试越来越贵。测试用例选择（TCS）通过选取测试子集来解决这个问题。近年来 TCS 也被用于深度神经网络和 LLM 代码模型，考虑两个目标：**从输入样本估计整体表现**，以及**选出能尽早暴露失败的输入**。

把 TCS 用到 Agent 系统上会带来新挑战。许多既有 DNN/LLM 测试选择技术依赖被测系统的信息，如置信度、不确定性估计、激活值、覆盖率或内部表示。**但对闭源模型或黑盒 agent，这些信息拿不到。** 而且 Agent 评测通常涉及生成式任务：agent 与工具和环境交互来完成任务，而不是预测一个类别标签。

本文把 Agent 软件系统的基准评测表述为一个测试用例选择问题：**每个基准任务是一个测试用例，每个候选 agent 是被测系统，未通过的任务是一次失败。** 与既有测试选择研究一致，我们考虑两个目标：从任务子集估计 agent 的全基准成功率；尽早暴露失败以支持失败分析。据我们所知，这是**首个针对 Agent 式软件系统的黑盒 TCS 实证研究**。

我们改编了 **7 种黑盒回归测试技术**（类别划分、边界值选择、文本多样性、聚类、自适应随机选择等），把选择准则重新定义在任务描述、元数据、代码片段和嵌入表示上。我们还提出 **6 种新的任务难度策略**：2 种使用启发式特征，4 种使用独立的 LLM-as-judge 评估。这 13 种策略都不需要执行目标 agent，也不需要同一或其他 agent 的已记录结果。

加上随机抽样，构成我们评估的 14 种主要策略。我们还加入 **Historical Mid-Range** 作为基线：它改编自预测 agent 排行榜名次的工作，使用其他 agent（排除目标 agent）的已记录结果，优先选择通过率接近 50% 的任务——这是**留一 agent** 版本，保留了"选有区分度的中等难度题"的原则，又不使用目标 agent 自己的结果。

研究覆盖 **10 个公开 Agent 基准**，涵盖仓库级软件工程、竞赛编程、终端使用、工具调用对话、计算可复现性、通用助理任务与网页浏览。对每种策略，我们评估在 **10%、20%、50%** 三档任务预算下，所选任务集对每个 agent 全基准成功率的估计有多准，以及它揭示了多少失败。

结果表明，两个目标受益于不同的选择策略。**成功率估计**：改编的黑盒回归测试策略最强，Category Partition 在 10 个基准中的 5 个上取得最低的中位估计误差。**早期失败发现**：基于 LLM-judge 的难度选择更有效，在所选子集中更早地排入会失败的任务。

结果还说明评测成本在实践中可以降下来。对 SWE-bench Multilingual 上的 DeepSeek V3.2，Category Partition 只评 **296 个任务中的 60 个**，执行成本降低约 **82%**（从 **$114 到 $20**），成功率估计的绝对误差 **0.8 个百分点**。在 SWE-Bench Pro 上，用 250 轮上限的 SWE-agent 测 GPT-5 时，LLM-judge 选择在同样 20% 预算下发现的失败比随机抽样多约 **42%**：**91.7% 的选中任务暴露失败，随机抽样为 64.5%**。

### 2. 背景与相关工作（要点）

- **回归测试**旨在降低改动后执行大测试套件的成本。白盒技术依赖语句/分支覆盖率；**黑盒技术只用测试输入本身可得的信息**，因此在没有源码、插桩或历史覆盖率数据时更实用。Henard 等人表明，基于输入特征与多样性的黑盒技术可以与基于覆盖率的技术竞争。
- **类别划分**（Ostrand & Balcer, 1988）：从输入空间的可观察分区派生测试。**自适应随机测试（ART）**：每条新测试都选得离已选测试尽可能远，动机是"失败常在输入空间中聚集"。
- 黑盒回归测试也用文本信息比较和选择测试：把程序改动当查询、把测试当文档，用 TF-IDF、LSI、LDA 按文本相似度排序。
- **本文设定与常规回归测试不同**：我们的测试输入是基准任务，而不是 JUnit 那样的可执行测试用例。每个测试是一个 agent 任务：提示词 + 上下文、文件、仓库状态、工具、成功判据。**执行测试就是让 agent 跑这个任务，观察它是否到达预期结果。** 没有可执行测试体，可执行的过程是 agent 运行，断言由基准的 oracle 或成功判据提供。
- **与排行榜预测工作的区别**：Ndzomga 用历史逐题通过率来构建"缩减套件"以预测排行榜名次（受项目反应理论启发：几乎所有人都过或所有人都不过的题信息量很低）。本文不是找"能预测名次"的子集，而是找"**能在有限预算下预测表现**"的子集，评估标准是成功率估计精度与早期失败暴露。

### 3. 方法

给定基准的任务集 `T = {t1, …, tn}` 和任务预算 `k`，每种策略选出一个子集 `S ⊆ T`，`|S| = k`。策略按各自准则顺序选取，直到达到预算。

**3.1 三类策略（共 14 种，含随机基线）**

| 族 | 策略 | 选择准则 |
|---|---|---|
| 基线 | Random | 纯随机，无放回 |
| 基线 | Historical Mid-Range | 其他 agent 成功率距 50% 的距离（需历史结果） |
| 改编黑盒回归 | Task length | 任务文本长度（长 = 更复杂） |
| | Boundary Value | 在任务输入特征上距中位数的距离（选"极端"任务） |
| | Category Partition | 任务类别 / 文本标记 / 长度四分位，跨类别轮转 |
| | TF-IDF Diversity（原文 / 含代码） | 任务文本（± 代码块）的 TF-IDF 余弦距离，最大化与已选集合的最小距离 |
| | Adaptive Random | CodeT5+ 嵌入 + UMAP-10，最远优先 |
| | Round Robin | CodeT5+ 嵌入 k-means 聚类，跨簇轮转 |
| 任务侧难度估计 | Difficulty Score | 由任务文本与元数据手工构造的难度分 |
| | Difficulty Score + Diversity | 难度分 + 基于聚类的多样性 |
| | LLM-as-Judge | 一次总体 1–4 难度判断 |
| | LLM-as-Judge + Diversity | 总体判断 + 聚类多样性 |
| | Factor-Based LLM-as-Judge | 多个难度因子的判断 |

关键设计：**所有策略都在执行目标 agent 之前完成选择，且不使用任何 agent 结果。** 因此同一组被选任务可以对在该基准上评估的每个 agent 复用。聚类数 `k = max(4, round(0.06n))`，在观察任何 agent 结果之前就固定。

**3.2 两个目标为什么冲突**

- 随机抽样是成功率估计的**无偏**估计量，所以它在估计目标上很强——但它不针对困难或易失败的任务，因此在早期失败发现上较弱。
- 难度策略（尤其 LLM-judge）把"可能失败"的任务排到前面，因此在**发现失败**上强，但会让成功率估计**有偏**（高估失败率）。

这个张力是本文最有实践价值的结论：**先问清楚这次跑评测是为了"报一个数"还是"找 bug"，再选策略。**

### 4. 结果（要点）

- **成功率估计**：Category Partition 在 10 个基准中的 5 个上取得最低中位误差（20% 预算）。
- **成本**：
  - GPT 5.2 Codex / SWE-bench Verified：100 题代替 500 题，$225 → **$47**，误差 **0.8pp**。
  - DeepSeek V3.2 / SWE-bench Multilingual：60 题代替 296 题，$114 → **$20**（−82%），误差 **0.8pp**。
- **早期失败发现**：
  - GPT 5.2 Codex / SWE-bench Verified（20% 预算）：**53.0%** 选中任务暴露失败 vs 随机 **27.4%**。
  - GPT-5 / SWE-Bench Pro（20% 预算，250 轮上限）：**91.7%** vs **64.5%**（约 +42%）。
- **没有全能策略**：不存在同时在两个目标上占优的策略；Historical Mid-Range 在有历史数据时是一个强基线，但它需要其他 agent 的结果。

### 5. 对你意味着什么

1. **把"评测预算"当成一等公民。** 先定预算（10%/20%/50%），再按目标选策略，而不是默认全量。
2. **两套子集，两个用途。** 报指标用"代表性"子集（Category Partition / TF-IDF Diversity / Random）；找 bug 用"难度优先"子集（LLM-judge）。
3. **黑盒是特性不是限制。** 因为你拿不到模型内部信息，所以这些策略可以直接用在任何第三方 agent 上——这对做选型评测的团队尤其重要。
4. **注意 0.8pp 误差的前提。** 这是在该基准、该 agent、该预算下的结果；换基准要重新校准，不要把它当成通用保证。

## 与路线图的挂接

- **E1-03 数据集分层**：这篇文章给了"回归集该多大"的一个定量答案：20% 往往够用，前提是选得对。

## 三个自测问题

1. 为什么随机抽样在"估成功率"上很难被打败，却在"找失败"上表现最差？这两个目标的统计性质有什么不同？
2. 如果你只有 10% 预算，又必须同时给出"成功率"和"是否比上个版本差"，你会怎么组合策略？
3. LLM-judge 判难度会让成功率估计偏高还是偏低？为什么这在"发布门禁"场景里是危险的？
