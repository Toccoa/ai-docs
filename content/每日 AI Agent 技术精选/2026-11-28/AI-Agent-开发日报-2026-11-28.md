### 1. 瑞士确认五起涉及 AI Agent 的网络攻击

- **来源与日期**：瑞士联邦网络安全局（FOCS），2026-11-27
- **链接**：https://aiagentstore.ai/ai-agent-news/this-week

**为什么现在读**
这是国家级机构第一次明确把攻击归因为"使用了 AI Agent"。**五起攻击中四起成功入侵系统，三起针对关键基础设施**，官方称未造成重大中断，也未识别出攻击者。对防守方，这意味着对手可以更低人力完成侦察、漏洞发现、利用，以及部分横向移动。

**核心要点**
1. 数量与结果：5 起攻击、**4 起成功**、**3 起针对关键基础设施**。
2. 归因状态：官方未识别攻击者身份，也未公布具体受害单位。
3. 能力含义：侦察 → 漏洞发现 → 利用 → 横向移动的多环节可以大幅自动化。
4. 防守优先级（原文建议）：外部资产盘点、快速打补丁、强身份控制、监控"工具驱动的异常活动"。
5. 演练建议：做一次"攻击者已找到暴露系统"的应急演练，测量检测、隔离、轮换凭据、确认清除持久化的耗时。

**怎么读**
12 分钟。对你的直接动作：把"暴露面清单"和"凭据轮换预案"从文档变成可执行 runbook——这是唯一能在自动化攻击下缩短响应时间的东西。

### 2. Anthropic：消息接口从 Python 迁到 Rust，CPU 降约 70%

- **来源与日期**：Anthropic，2026-11-27
- **链接**：https://aiagentstore.ai/ai-agent-news/this-week

**为什么现在读**
这是"服务层工程"难得的一手数据：把支撑 Claude Code 等产品的 Messages API 从 Python 迁到 Rust，**每请求 CPU 降约 70%**、**首字延迟中位数降约 20%**，并用真实生产流量做了验证。更值得记的是那句提醒：**常规集成测试通过，并不能证明行为兼容**——重写过程中测试结果与真实输入之间出现了明显差异。

**核心要点**
1. 收益：每请求 CPU **−70%**；首字延迟中位数 **−20%**。
2. 验证方式：用**真实生产流量**校验新实现，而不只跑测试套件。
3. 关键教训：测试通过 ≠ 行为兼容；重写类项目必须做**影子流量对比**。
4. 对 agent 开发者的含义：agent 的体验瓶颈常在这层——成千上万次工具调用、重试、上下文传递、并发会话。
5. 可复用做法：影子流量 → 对比"输出与工具行为"（不只是状态码）→ 保留立即回滚路径。

**怎么读**
15 分钟。如果你在改 agent 运行时（换框架、换语言、换网关），照抄这套流程：**影子流量 + 行为级 diff + 可回滚**。追踪"每个完成任务的成本"和"成功完成时间"，而不是只看 API 延迟。

### 3. TransHarness：从"基准过拟合"到"可迁移的 harness 演化"

- **来源与日期**：arXiv:2611.33757（cs.AI），2026-11-25 提交，22 页
- **链接**：https://browse-export.arxiv.org/abs/2611.33757

**为什么现在读**
前几周的 harness 论文都在证明"我的 harness 更强"，这篇换了问题：**那些提升到底是真能力，还是在特定基准上过拟合**？它提出可迁移的 harness 演化方法，并用两个硬基准给出成绩——**DeepSWE v1.1 76.4%、Terminal-Bench 2.1 95.5%**，分别超过 GPT-6 Astra **2.4 分与 5.6 分**。

**核心要点**
1. 问题重述：harness 优化容易在单一基准上"刷分"，需要检验**跨基准迁移性**。
2. 结果一：DeepSWE v1.1 **76.4%**。
3. 结果二：Terminal-Bench 2.1 **95.5%**。
4. 对比：相对 GPT-6 Astra 提升 **+2.4 / +5.6** 分——幅度不算夸张，但方向是"可迁移"。
5. 阅读提醒：数字来自摘要与索引，具体实验设置建议读原文。

**怎么读**
25 分钟。重点看它如何定义"迁移"（换基准、换模型、换任务族），这决定你能否把方法搬到自己团队。

### 4. "学什么"与"怎么学"：任务能力与接口能力要分开练

- **来源与日期**：arXiv:2611.31427，2026-11-25
- **链接**：https://arxivsignals.io/papers/2611.31427

**为什么现在读**
这篇给出一个反直觉的结论：**光练"任务"或光练"接口"都不行**。它提出"harness rehearsal"（用 harness 做预演），并分解出两种能力：理解任务（what）与使用接口（how）。在 BFCL V3 多轮场景下，只练任务或只练接口的 Qwen3-4B 分别只有 **8.5% 与 32.5%**，合起来 **58.8%**。

**核心要点**
1. 分解：**任务能力（学什么）** 与 **接口能力（怎么学/怎么调）**。
2. 单练结果：任务侧 **8.5%**，接口侧 **32.5%**（BFCL V3 多轮，Qwen3-4B）。
3. 合练结果：**58.8%**——远高于两者之和的一半，说明存在协同。
4. 工程含义：训练/评测 agent 时，"工具用法"要作为独立维度被显式覆盖，不能假设它随任务能力自然增长。
5. 阅读提醒：数字来自索引转述，以原文为准。

**怎么读**
20 分钟。对你团队的含义：eval 集里要同时有"业务正确"和"工具调用正确"两类断言，否则你看不出短板在哪。

### 5. ICLWorld：数字世界与物理世界的能力鸿沟

- **来源与日期**：arXiv:2611.32649v1（cs.CV），2026-11-24 提交
- **链接**：https://arxiv.org/abs/2611.32649v1

**为什么现在读**
同一套上下文学习框架，放到"电脑操作"和"机器人操作"两个世界里，成功率差了三倍。这个差距对做具身/机器人 agent 的团队是明确的预期管理：**数字世界的能力不能自动迁移到物理世界**。

**核心要点**
1. 规模：统一 harness "UIverse"，**30 个环境、630 段视频、160 个任务**。
2. 数字世界：Claude Opus 5.5 与 GPT-6 Astra 在 computer-use 上成功率为 **82% / 76%**。
3. 物理世界：同两模型在 robot-use 上只有 **27% / 26%**。
4. 解读：差距来自动作空间、反馈延迟与不可逆性，而非"模型不够聪明"。
5. 使用建议：做具身 agent 时，把"可恢复性"与"安全边界"作为一等设计对象。

**怎么读**
20 分钟。若你做 GUI/浏览器 agent，这份基准的"数字世界"部分可以直接当评测参考。

### 6. 模型能不能改进自己造的 harness？平均增益 2.80 分，置信区间跨 0

- **来源与日期**：arXiv:2610.30499，2026-10-21 首次提交（补读）
- **链接**：https://arxivsignals.io/papers/2610.30499

**为什么现在读**
这是本周最该拿来"降温"的一篇：如果模型能自己改进 harness，那 harness 工程就变成了自动化问题。但这篇在 ARC-AGI-3 上做了 **27 条演化谱系、81 个快照、2,025 次评测**，结论是**平均留出增益只有 2.80 分，且 95% 置信区间从 −1.44 到 7.35——跨过零**，即无法排除"没有真实提升"。

**核心要点**
1. 规模：**27 条谱系、81 个快照、2,025 次评测**。
2. 结果：平均留出增益 **2.80 分**（RHAE），**95% CI −1.44 ~ 7.35**。
3. 解读：自改进 harness 目前**证据不足**，不能作为架构前提。
4. 与必读 3 的关系：TransHarness 说明"可迁移的演化"有价值；这篇说明"让模型自己演化"还不可靠——两者合起来才是完整图景。
5. 阅读提醒：补读条目，日期为 10-21。

**怎么读**
15 分钟。结论直接可用：**harness 的改进目前仍需人来做**，把预算投在"人的设计 + 可执行验证"上，而不是"让 agent 自己调自己"。

## 四、今日观察

**1. Harness 研究进入"第三阶段"：从刷分到迁移，再到自改进。**
第一阶段的结论是"harness 影响很大"（+42.8 点、21.9%→33.3%）；第二阶段开始问"能不能迁移"（TransHarness：跨基准仍领先 2.4/5.6 分）；第三阶段问"能不能让模型自己改进"（自改进平均增益 2.80，CI 跨 0）。**目前只有前两阶段有坚实证据**，这对预算分配是明确指引。

**2. 真实攻击已经从"概念"变成"统计数字"。**
瑞士官方确认 5 起、4 起成功、3 起打到关键基础设施。防守方要接受一个新基线：**攻击的侦察与利用比你的响应流程快**。缩短"检测→隔离→轮换凭据→确认清除"的时间，比增加检测规则更有效。

**3. 服务层重写是 agent 经济性的隐形杠杆。**
Anthropic 的 Python→Rust 迁移给出 −70% CPU、−20% 首字延迟。对 agent 来说，这层跑的是成千上万次工具调用与重试——**同样的模型，服务层效率差一倍，单位任务成本就差很多**。而"测试通过 ≠ 行为兼容"这条，是所有重写项目的通用警告。

**4. 能力鸿沟按"世界"分层，不按"模型"分层。**
ICLWorld 的 82% vs 27% 说明：同一个模型在数字世界与物理世界的成功率差三倍。选型时问"任务在哪个世界"比问"哪个模型更强"更有意义。
