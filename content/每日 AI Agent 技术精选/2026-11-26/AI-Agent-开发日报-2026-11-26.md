## 二、今日必读

### 1. MCP 大更新：Skills、长任务 Tasks、Elicitation、File Uploads

- **来源与日期**：Anthropic / Model Context Protocol，2026-11-25（要点经 AI Agent Store 周报转述）
- **链接**：https://aiagentstore.ai/ai-agent-news/this-week

**为什么现在读**
这是本周最重要的架构变化。此前 MCP 主要解决"agent 能调什么工具"；这次它把**流程、时长、确认、文件**四件事都纳入了协议：服务端可以下发"skills"（可维护的操作指引），可以跑长任务并异步返回，可以在关键点暂停等用户确认，还可以让文件**不经过模型上下文**直接上传。合起来意味着：**业务逻辑可以住在服务端，而不是塞进 prompt 与上下文窗口**。

**核心要点**
1. **Skills（公测）**：MCP server 可发布由服务端提供的 skills，流程与指引的更新不再依赖客户端改 prompt。
2. **Tasks（GA）**：长时异步任务，agent 可以把工作交给服务端后台跑，稍后取结果——减少"每一步都留在对话里"的上下文消耗。
3. **Elicitation（GA）**：agent 可暂停并向用户请求确认/补充信息，把"人工闸门"做进协议层。
4. **File Uploads（实验）**：即将支持文件上传，且**不流经模型上下文**——大文件与敏感文件的处理路径被单独拆出来。
5. 可用性按套餐滚动：Skills 在 Pro/Max/Ultra 默认开启；Tasks 与 Elicitation 对这些套餐 GA；File Uploads 仍为实验。

**怎么读**
20 分钟。落地建议：挑一个**可重复的业务流程**（开票、报销、调研）做成 MCP skill，验证"服务端更新指引 → agent 行为随之变化"这条链路；File Uploads 先当实验，重点审"批准流程与文件完整性"。

### 2. Meta Muse 登陆英国：消费级 agent 商务进入真实资金

- **来源与日期**：Meta，2026-11-24（行业报道，经 AI Agent Store 周报转述）
- **链接**：https://aiagentstore.ai/ai-agent-news/this-week

**为什么现在读**
上周 Walmart 对 Muse 开放 Agent Gateway，这周 Muse 直接在英国上线，并接入 Sainsbury's、Argos、M&S、easyJet、Trainline 等连接器，支付走 **Stripe 的 Link 钱包**，**购买需要用户确认**。这是"agent 代表用户花钱"第一次在消费级规模上做真实压力测试——而它要解决的从来不是模型能力，而是授权、争议与退款。

**核心要点**
1. 能力：规划购物、组建购物篮、准备预订；覆盖零售与旅行两类高频场景。
2. 支付：通过 Stripe 构建的 Link 钱包完成，**需要用户批准**。
3. 时间点：赶在大型零售季之前，属于有意识的规模化验证。
4. 对商家/平台的工程清单：连接器鉴权、授权粒度、退款与争议路径、同意与数据共享披露。
5. 监管提醒：agent 代购会放大条款、争议处理与数据共享义务方面的暴露面。

**怎么读**
12 分钟。如果你做电商/旅行，先画一张"外部 agent 需要哪些权限"的图，再定哪些环节必须人类确认——这张图比接入文档更有用。

### 3. Simon：十二个月里的三个 LLM 拐点

- **来源与日期**：Simon Willison，2026-11-24（AI Engineer Code Summit 主题演讲改写）
- **链接**：https://simonwillison.net/2026/Nov/24/llm-inflection-points/

**为什么现在读**
这是一份"能力分期"的一手观察，比任何榜单都更适合用来判断"现在该把什么交给 agent"。他给出的三个拐点各有明确的**判据**，尤其第二个——"给目标 + 给工具就能暴力解决"——直接解释了为什么工具设计比 prompt 技巧更重要。

**核心要点**
1. **拐点一（2025-11）**：Claude Opus 4.5 与 GPT-5.1-Codex 让 coding agent **默认结果大体是对的**；作者称这是他第一次把 Claude Code 当日常主力。
2. **拐点二（2026-06/07）**：Fable 类模型——"**能定义目标并提供必要工具，它就能靠暴力解决你的问题**"。例证：修 Safari 显示 bug 时自己搭了 `pyobjc-framework-Quartz` 截图机制和 CORS 本地日志服务；用 5 个 WebAudio 麦克风把神秘蜂鸣定位到 **约 40cm** 内。
3. **拐点三（2026-09/10）**：3D 建模与游戏开发——给 Blender 或让它写 Three.js，能产出可信模型。
4. 他的"Fable 类"名单：Fable 5 / 5.1 / 5.2、Opus 5.5（他称"便宜的 Fable"）、GPT-6 Astra，可能还有 Gemini 4 Neon。
5. 方法论价值：**用"能力形态"而不是"分数"来划分阶段**，这样每次新模型出来，你能问"它是否跨过了某个形态的门槛"。

**怎么读**
20 分钟。带着一个问题读：你的 agent 现在卡在"拐点一"（要人纠正）还是已经到"拐点二"（给目标+工具就能跑）？答案决定你该投资 prompt 还是投资工具与验收。

### 4. GPT-6.2 Astra 用 22 分钟解开一桩历史谜案

- **来源与日期**：历史学者 Mark Humphries 的案例记录，2026-11-24（Simon 转发）
- **链接**：https://generativehistory.substack.com/p/gpt-62-astra-solves-a-historical

**为什么现在读**
这是一个"研究型 agent"的干净案例：目标明确（鉴定匿名手稿作者）、证据公开（档案与二手文献）、结论**可被同行核验**。22 分钟、极少提示，它不仅给出假设，还**预测了"某份冷门档案能证明它"并去查证**——最后那份档案本身还成了重要发现。这种"可验证的探索"正是 agent 最该被用到的形态。

**核心要点**
1. 任务：鉴定耶鲁 Beinecke 图书馆藏 **1808 年匿名素描本**的作者。
2. 过程：仅用公开的一手与二手资料，**约 22 分钟**完成；先形成假设，再预测哪份档案能验证，最后去查。
3. 结果：找到一份此前鲜为人知的档案来源，证实了假设；该来源本身对加拿大史与毛皮贸易史有独立价值。
4. 与"agent 自评"的区别：结论由**档案证据**支撑，而不是由模型自信支撑。
5. 可迁移的方法：让 agent 先写"什么证据能证明/推翻我的假设"，再去检索——这比"直接给答案"更可靠。

**怎么读**
15 分钟。对做研究/尽调 agent 的团队，这个案例的价值在**流程**：假设 → 预测验证证据 → 检索 → 复核。

### 5. Switch-SWE：任务中断后恢复，coding agent 平均掉 11.5 个点

- **来源与日期**：Switch-SWE（arXiv，据索引转述；论文标注 2026-11-05，本期在汇总中浮现）
- **链接**：https://emergent.sh/news/switch-swe-coding-agents-drop-11-5pp-task

**为什么现在读**
真实开发很少"一口气做完"：会被打断、换人、换会话。这个基准专门测"**任务恢复**"——把同一任务拆成多段会话后继续做。结果是平均掉 **11.5 个百分点**（区间 6.0–15.0），而一个插件式上下文管理模块能把损失补回 **5.5–15.5 点**。这直接量化了"上下文断裂"的代价。

**核心要点**
1. 规模：**200 个聚焦任务**、**19 个 Python 仓库**、**400 份会话规格**、**7 个 agent**。
2. 结果：任务恢复场景下平均下降 **11.5pp**（6.0–15.0pp）。
3. 干预：在 OpenCode 上加装上下文管理模块，恢复能力提升 **5.5–15.5pp**。
4. 工程含义：**"会话边界"是 agent 的一等公民**——交接文档、状态快照、未完成事项清单，应该像提交信息一样被产出。
5. 使用提醒：日期与细节来自索引转述，**建议以原文实验设置为准**。

**怎么读**
15 分钟。今天可做：要求 agent 在每次会话结束前产出"交接卡"（当前目标、已完成、下一步、已知坑），下次会话从这张卡开始，而不是从头读代码。

## 四、今日观察

**1. MCP 这次更新把"流程"从 prompt 里搬走了。**
Skills 让指引可服务端维护，Tasks 让长任务异步化，Elicitation 把人工确认做进协议，File Uploads 让文件绕开上下文。四件事合起来是同一个方向：**agent 的"业务逻辑"应该住在服务端，客户端的上下文只放当前决策所需**。这也顺带解决了两个老问题——长任务上下文膨胀、敏感文件进模型。

**2. 消费级 agent 商务开始跑真实资金流。**
Muse 在英国接入多家零售与旅行商家，支付走 Stripe Link、需用户确认；加上 Walmart 的 Agent Gateway，可以判断：**瓶颈已经从"能不能下单"变成"授权、退款、争议、数据共享怎么做"**。对这些平台，agent 专用档案与分级授权会是下一年的标配。

**3. "拐点"式的能力分期，比排行榜更适合做交付决策。**
Simon 的三个拐点各有判据，尤其"给目标 + 给工具 → 暴力解决"这条：它把投资重点从 prompt 技巧转向**工具质量与验收设计**。如果你的 agent 还在"要人不断纠正"，那还在拐点一；如果它能自己搭工具验证假设，就进入了另一个形态。

**4. 可核验的探索，是 agent 最该被用到的形态。**
1808 年素描本的案例之所以可信，不在于模型多强，而在于**结论由档案证据支撑、且预测可被检验**。这与同周的 Switch-SWE（会话断裂掉 11.5 点）形成对照：**能被验证、能被交接的工作，才值得交给 agent**。
