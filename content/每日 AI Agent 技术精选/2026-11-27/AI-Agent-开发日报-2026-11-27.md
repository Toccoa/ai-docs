## 二、今日必读

### 1. Cloudflare Search for Agents：让 agent 不必爬站，直接查

- **来源与日期**：Cloudflare，2026-11-25 发布（beta，全套餐可用）
- **链接**：https://aiagentstore.ai/ai-agent-news/this-week

**为什么现在读**
这是"agent 可发现性"第一次以**协议端点**的形式产品化：打开一个开关，Cloudflare 为你的域名建一个 AI Search 实例，索引内容，并在 `/.well-known/search` 暴露一个**返回 Markdown** 的查询端点。对需要读文档、API 规格、runbook 的 coding agent，这比抓站或自建 API 稳定得多——而且**谁能被 agent 找到、找到什么，变成了一个可配置的权限边界**。

**核心要点**
1. 形态：Dashboard 开关 → 自动建 AI Search 实例 → 索引 → 暴露 `/.well-known/search`。
2. 返回格式：**Markdown**，对 LLM 友好，省去解析与清洗。
3. 价值：coding agent / 开发工具能拿到**版本化、稳定**的站点内容，而不是脆弱的抓取或一次性 API。
4. 风险点（原文强调）：**意外的内容暴露**——CI 日志、私有文件可能被索引；上线前要配 allowlist 与速率限制。
5. 试点建议：先在 staging 域名开，验证返回内容与 robots/元数据、访问控制是否符合预期，再上生产。

**怎么读**
12 分钟。如果你是文档/平台团队，这是"让 agent 正确使用你的产品"的最低成本方式；但请把"索引了什么"当成安全配置来审，而不是当成 SEO 开关。

### 2. Microsoft Agent Framework 遭 PyPI 投毒：供应链攻击打到官方包

- **来源与日期**：Microsoft 安全公告，2026-11-25
- **链接**：https://aiagentstore.ai/ai-agent-news/this-week

**为什么现在读**
这是本周最该立刻行动的一条：**Microsoft Agent Framework 的两个 Python 版本（1.26.1、1.26.2）被未授权上传到 PyPI，包含窃取凭据的代码**。Microsoft 已下架恶意上传、临时关闭仓库并给出补救步骤。agent 环境的特点是"自动装依赖 + 长期持有凭据"，一旦命中，几乎等于把 API key 与令牌整包交出去。

**核心要点**
1. 受影响版本：**1.26.1 与 1.26.2**（被未授权上传，含凭据窃取代码）。
2. 攻击面：任何自动 `pip install` 的 CI、容器构建、agent 沙箱，都可能在解释器启动时执行恶意代码。
3. 处置（原文）：立即检查 lockfile、CI 日志、容器镜像；命中则**轮换该环境可访问的所有凭据**，从干净镜像重建，并 **pin 回 1.26.0**（或经审查的替代版本），等官方确认安全时间线。
4. 长期措施：包来源校验（provenance）、内网镜像、基于 **SBOM** 的 CI 门禁，覆盖 agent 运行时与沙箱宿主。
5. 为什么这条对 agent 特别重要：agent 的运行环境通常比普通服务**权限更大、凭据更多**，且经常由 agent 自己执行安装命令。

**怎么读**
10 分钟内完成排查。**今天就要做**：grep 所有 lockfile 与 Dockerfile；确认 agent 沙箱是否把生产凭据挂进了环境变量——如果是，这周的优先级高于任何新功能。

### 3. 机器人 agent 的 harness 设计：同一模型，最高差 42.8 个点

- **来源与日期**：arXiv:2611.34778（cs.RO），2026-11-25 提交、11-26 上线
- **链接**：https://export.arxiv.org/abs/2611.34778

**为什么现在读**
"harness 比模型更重要"这句话被反复说，但很少有这种规模证据：**47 万+ 次 rollout、8 个仿真基准、6 个视觉语言模型、15 个 VLA/WAM checkpoint**，结论是同一批基座策略在换 harness 后**最高提升 42.8 个点**。虽然领域是机器人，但方法学（如何系统评估 harness 设计）可以直接迁移到编码 agent。

**核心要点**
1. 规模：**470,000+** 次 rollout，覆盖 **8** 个仿真基准。
2. 对象：**6** 个 VLM + **15** 个 VLA/WAM checkpoint。
3. 关键结果：参考配方 **X-Harness** 把基座策略最高提升 **+42.8 点**——远大于通常的模型代际差异。
4. 方法价值：它把 harness 拆成可比较的设计维度，而不是"调 prompt"，这对做 agent 基础设施的团队是可复用的评估框架。
5. 阅读提醒：机器人任务的验证依赖仿真，结论外推到真实世界需谨慎。

**怎么读**
25 分钟看实验设计与 X-Harness 的组成。可迁移的问题：你的 agent 在"工具描述、重试策略、状态表示、验证环节"上，各自值多少点？没有这个分解，换模型就是碰运气。

### 4. RegHarness：code-as-policy agent 该"保留什么"

- **来源与日期**：arXiv:2611.33739（cs.RO），2026-11-25 提交、11-26 上线
- **链接**：https://li469-138.members.linode.com/arxiv/2611.33739

**为什么现在读**
code-as-policy（让 agent 写代码当策略）最大的隐患是：**它会把偶然成功写成规则**，然后在别的场景里错得很自信。RegHarness 研究"从步骤到技能"该保留什么，并给出了一个很干净的三方对照：技能精炼、运行时治理、原生重放。

**核心要点**
1. 结果：LIBERO-PRO 上 **87.8%（158/180）** 成功率，对比 RATs 的 **39.4%**；MolmoSpaces 上 **72.0%**。
2. 拆解：**只做技能精炼**，RATs 的成功试验从 **71 → 135**；**只做运行时治理** → **105**；**原生 reset-and-replay** 只有 **46**。
3. 解读：**"保留并精炼什么"比"多试几次"重要得多**——重放只能复用轨迹，精炼能复用规则。
4. 对编码 agent 的类比：把"这次修好了"沉淀成可复用技能时，要区分**可泛化规则**与**场景特例**，否则技能库会污染。
5. 阅读提醒：结果来自机器人操作任务，迁移到软件领域需重新验证。

**怎么读**
20 分钟。如果你的 agent 有"技能库/记忆"，重点看它的保留判据——这决定了库是资产还是负债。

### 5. Agentic Harness Engineering Beta：pass@1 21.9% → 33.3%，还省 40.8% token

- **来源与日期**：arXiv:2611.24924，2026-11-18/19（日期在不同索引间不一致）
- **链接**：https://arxivsignals.io/papers/2611.24924

**为什么现在读**
这是本周最"可抄"的一篇：它提出**以需求为中心的 harness 演化**方法，在提升 pass@1 的同时**减少 40.8% 的 token 消耗**——不是用更多算力换分数。更有说服力的是人工偏好与跨模型迁移：48 组有效对比中 **31 组**更偏好新 harness，且迁移到 GLM-5.3（+15.8%）与 DeepSeek-V4.1-Flash（+5.3%）仍然有效。

**核心要点**
1. 指标：pass@1 从 **21.9% → 33.3%**。
2. 成本：比基线 harness **少 40.8%** 的 token。
3. 人工评估：**31/48** 组有效对比中更受偏好。
4. 迁移性：GLM-5.3 **+15.8%**、DeepSeek-V4.1-Flash **+5.3%**——说明提升来自 harness 而非某个模型的特调。
5. 阅读提醒：日期在不同索引间不一致（11-18 / 11-19），以 arXiv 原文为准。

**怎么读**
20 分钟。重点看"需求中心"如何转成 harness 组件（工具描述、验证步骤、重试与回退）。如果你在自建 harness，这是本月最值得逐节复现的一篇。

## 四、今日观察

**1. Harness 的收益已经被量化到"不该再讨论要不要投入"的程度。**
机器人侧 **+42.8 点**、编码侧 **pass@1 21.9%→33.3% 且省 40.8% token**、code-as-policy 侧 **87.8% vs 39.4%**——三篇独立工作、不同领域，结论一致：**同一模型，换 harness 就是换档位**。这也解释了为什么"换个更强的模型"经常没感觉：你的 harness 在拖后腿。

**2. 供应链攻击已经成为 agent 生态的头号风险。**
Microsoft Agent Framework 的 PyPI 1.26.1/1.26.2 被未授权上传、含窃密代码，而 agent 环境的特点是"自动装依赖 + 长期凭据 + 常由 agent 自己执行安装"。**pin 版本、SBOM、内网镜像**从"最佳实践"升级为"最低要求"；更激进的做法是：生产凭据**永远不进** agent 沙箱的环境变量。

**3. Agent 可发现性是新的协议层，也是新的权限边界。**
Cloudflare 的 `/.well-known/search` 让 agent 不必爬站就能拿到 Markdown。它的另一面是：**你开始需要决定"哪些内容允许被 agent 读到"**——CI 日志、私有文件一旦进索引，就是一次静默泄露。可发现性要按安全配置来管。

**4. "去个体化"与技术侧的可审计身份是同一件事。**
Simon 引用的观察很扎心：打开视频、会议、邮箱，到处都是 Claude 的声音。当生成内容泛滥，**可辨识的人类署名与责任**会变成稀缺品——这和技术侧"agent 要有可问责身份"（Foundry 的 agent 经理、Tool Gateway 的调用者身份）是同一枚硬币：**没有归属，就没有信任**。
