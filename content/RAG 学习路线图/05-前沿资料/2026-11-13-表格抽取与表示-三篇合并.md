# 表格到底该用什么格式存：三篇 2026 年论文的合并精读

> 定位：前沿资料 · 主题合并（表格抽取与表示）
> 关联知识点：R1-03（表格抽取与表示）、R1-01（文档解析全链路）、R2-05（特殊内容切分）
> 主源三篇：
> - LTEM：《LLM-Friendly Table-Enhanced Markdown》EMNLP 2026 主会，arXiv:2610.29188
> - 表格抽取基准：《Benchmarking Table Extraction from Heterogeneous Scientific PDF Documents》KDD '26，arXiv:2511.16134
> - RealHiTBench：《A Comprehensive Realistic Hierarchical Table Benchmark》ACL 2025，arXiv:2506.13405
> 入库日期：2026-11-27 ｜ 类型：同行评审论文（两篇）+ 基准论文

## 一句话结论

表格的难点不在“抽不出来”，而在“**存成什么格式**”：LLM 最擅长读的 Markdown/CSV 表达不了合并单元格与多级表头，而表达力强的 HTML/LaTeX 又贵且有副作用；LTEM 给出的折中是——**增强版 Markdown，在准确率≈HTML 的前提下把 token 成本压回接近 Markdown**。

## 三篇各回答了什么

**LTEM（arXiv:2610.29188）——该用什么格式**
把表格结构拆成 **6 个原子特征**（跨行跨列、多级表头、分区、跨页等）与 **6 个复杂度档**，用 **STB 基准（1,089 张合成表，按复杂度分层）** 在 5 个 SOTA LLM 上比较 Markdown / CSV / HTML / LaTeX / LTEM 五种表示。结论：
- **LTEM 的理解准确率与 HTML 相当，accuracy–token 权衡优于 HTML 与 LaTeX**；
- **相对 LaTeX，无效输出显著更少**；
- **生成任务上 HTML 仍最好**，LTEM ≈ MultiMarkdown。

**表格抽取基准（arXiv:2511.16134）——抽得出来吗**
**86k 页**规模、两个新异构数据集共 **39k 样本**，同时给子任务与端到端打分，并度量模型不确定性。结论直白：**现有方法在异构数据上缺乏泛化性，鲁棒性与可解释性均有限**。含义：表格链路必须自带质量门禁，不能指望单一工具。

**RealHiTBench（arXiv:2506.13405）——层级表头的重要性**
在 **25 个 SOTA LLM** 上测 LaTeX / HTML / PNG 三种输入，并提出 **TreeThinker**（把多级表头组织成树再做推理），验证“改善模型对表格层级结构的感知”是有效方向。

## 精评：值钱的地方

1. **格式选择第一次有了受控实验依据。** 以前“Markdown 够用”和“必须上 HTML”两种说法都能找到拥护者，原因就是没人按“有无 span/层级表头”分层测过。LTEM 的 F1–F6 分类法可以直接拿来当你自己的验收清单。
2. **“层级要用树喂给模型”是可落地的动作**（TreeThinker 的思路），而不是抽象建议。
3. **86k 页基准的存在本身**，说明“选一个永不犯错的表格工具”是不现实的预期。

## 精评：不能当真（或容易被误读）的地方

- **LTEM 是作者自己提的格式，基准也是作者自己建的 STB。** 合成表与真实财报/规范文档的分布差异可能很大，**跨域效果要自己测**。
- **“准确率与 HTML 相当”是在理解任务上**，生成任务 HTML 仍最好。别把它当成“HTML 可以退休”。
- **86k 页那篇的结论是“缺乏泛化性”**，不是“某个工具最好”。它没有给出“谁第一”的定论，引用时不要替它排名。
- **RealHiTBench 测的是“模型读表能力”**，不是“抽取链路质量”。两者别混。

## 对你的动作（按投入产出比排序）

1. 先查你的表格是**用什么格式存的**（Markdown / HTML / CSV / 图片）；
2. 如果存在合并单元格或多级表头，**立刻换成 HTML 或 LTEM**；
3. 建一个“**能不能算出来**”的三类小测（单值查找 / 跨行聚合 / 跨页拼接），用它验收，而不是看 TEDS；
4. 表格链路加**质量门禁**（空单元格比例、行列数异常、块类型分布异常）。

## 自测

1. 你库里的表格用什么格式存的？如果用户问“全年合计”，你的链路能算出来，还是只会答某一个季度的数？
2. “Markdown 最省 token 且模型最好读”这句话，在什么条件下成立、什么条件下会踩坑？
3. 一张 500 行的台账，你会整表入库还是按行切？两种做法在“检索召回”和“聚合计算”上各有什么表现？
