## 知识点 1：Adaptive RAG（R6-05）

### 一句话结论

**Adaptive RAG 的核心不是“更聪明的模型”，而是“更便宜的分流”。** 先用一个轻量分类器判断 query 类型（事实/推理/摘要），再路由到不同成本的检索范式；2026 年的基准显示，**TF-IDF + SVM 能达到 93.2% 路由准确率，并节省 28.1% token**。

### 为什么重要

- RAG 范式很多：Naive、Hybrid、Iterative、Agentic，成本差几倍；**用最贵的跑所有 query 是浪费**。
- RAGRouter-Bench（arXiv:2602.00296）提供 **7,727 条 query、4 个领域、3 类 query**（factual / reasoning / summarization），并引入“query-corpus 兼容性”作为路由依据。
- 2026 年的基线研究（arXiv:2604.03455）证明：**词法特征（TF-IDF）比语义 embedding 更适合做路由**——表面关键词模式是 query 复杂度的强预测器。

### 核心机制：路由表

```text
query → 轻量分类器（TF-IDF + SVM / 规则）
  ├─ factual      → Hybrid + rerank（便宜、快）
  ├─ reasoning    → Iterative / 多跳检索（中成本）
  ├─ summarization→ 层次检索 / 长上下文（中高成本）
  └─ 不确定       → 默认便宜路径 + 证据不足再升级
```

**关键数字：**

- 路由准确率 **93.2%**，macro-F1 **0.928**（TF-IDF + SVM）
- 模拟 token 节省 **28.1%**（相对“总是用最贵范式”）
- 词法特征比语义 embedding 高 **3.1 macro-F1**
- 领域差异：**医疗最难路由，法律最易**

### 怎么做

1. **先建“问题类型 → 处理路径”表**：事实/推理/摘要/计算/权限，各自默认路径与升级条件。
2. **从规则/ TF-IDF + 线性模型起步**：不需要大模型；先看分类准确率与节省。
3. **设“默认便宜路径 + 升级”**：分类不确定时，先走便宜路径；证据不足再升级（PEA-CAE 思路）。
4. **分层评估**：路由准确率、`cost_per_query`、`answer_accuracy_by_type`、`misroute_rate`。
5. **领域校准**：医疗/法律等差异大，路由阈值要按领域调。

### 权衡与坑

- **坑 1：用大模型做路由。** 成本高、延迟高；轻量分类器通常够用。
- **坑 2：路由错但答案对，仍浪费。** 要测 `misroute_rate` 与 `cost_per_misroute`。
- **坑 3：只按 query 文本路由，忽略 corpus 兼容性。** RAGRouter-Bench 强调 query-corpus 匹配。
- **坑 4：路由后不监控。** 业务分布会漂移，分类器会过期。
- 【我的建议】先做 3 类路由（事实/推理/摘要），比“上 Agentic”便宜得多。

### 架构师视角

- Adaptive RAG 是**成本工程**：它不提升上限，但能显著降低平均成本。
- 观测出口：`routing_accuracy`、`misroute_rate`、`token_savings`、`cost_per_query`、`answer_accuracy_by_type`。
- **一句话**：**不是所有问题都值得用最贵的检索；先分类，再花钱。**

### 自测 3 题

1. 你的系统里，所有 query 都走同一条检索路径吗？成本差多少？
2. 你的 query 类型分布是什么？事实/推理/摘要各占多少？
3. 如果路由器把 10% 的推理题误判为事实题，答案会掉多少？你测过吗？

## 知识点 2：Agentic RAG（R6-06）

### 一句话结论

**Agentic RAG 的收益来自“把一次固定 top-k 变成可迭代的证据获取”，不是来自“多几个 agent”。** 在复杂任务上很实在（BRIGHT recall@1 **49.6%（+21.8pp）**、FinanceBench **92%**），但它**慢、贵、不可控**；正确姿势是**按问题复杂度路由，只对复杂 query 启用**。

### 为什么重要

- 传统 RAG 是“检索一次 → 生成”，对多跳、跨文档、需要验证的任务不够。
- AgenticRAG（arXiv:2605.05538）在现有搜索栈上加一层轻量 harness，给 LLM 配 `search/find/open/summarize` 工具，让它**迭代检索、文档内导航、自主分析**。
- 生产案例（OPG，arXiv:2607.24791）给出可抄的演化路径：**PEA-CAE（渐进证据获取 + 成本感知升级）**。

### 核心机制：Agentic 循环

```text
Query → Planner（分解问题）
      → Router（选工具：向量库/图/Web/文件）
      → Retrieve / Open / Summarize
      → 相关性 & 忠实度检查
      → 足够？ → 生成 + 引用
        不足？ → 改写/换工具/再检索（受预算约束）
```

**关键数字：**

- AgenticRAG：BRIGHT recall@1 **49.6%（+21.8pp over best embedding baseline）**
- WixQA factuality **0.96（+13% relative）**
- FinanceBench answer correctness **92%（within 2pp of oracle）**
- 延迟：**2–10 秒/查询**（综述/实践口径）

### 怎么做

1. **先建路由**：简单 FAQ 走 hybrid+rerank；多跳/研究/跨文档走 agentic；聚合/报表走 SQL。
2. **工具最小集**：先 `search(query)`、`open(doc_id/page)`、`summarize(span)`；不要一上来多 agent。
3. **硬预算**：`max_tool_calls`、`max_tokens`、`timeout`；超过就降级到“返回已收集证据 + 不确定性”。
4. **PEA-CAE 式升级**：低成本先做，证据不足才升级；记录 `escalation_rate`、`cost_per_success`。
5. **评估分层**：单跳、多跳、研究、聚合分开；不要用平均分。

### 权衡与坑

- **坑 1：所有 query 都 agentic。** 成本/延迟爆炸，简单问题反而更慢更差。
- **坑 2：多 agent 协作。** 协调失败与成本高；先单 agent + 工具。
- **坑 3：没有停止条件。** 会无限检索；必须设预算与“证据充分”判据。
- **坑 4：把基准收益当生产收益。** BRIGHT/FinanceBench 分布与业务不同，要自测。
- 【我的建议】Agentic 是“复杂 query 的专用通道”，不是默认架构；先路由，再启用。

### 架构师视角

- Agentic RAG 是**用延迟换准确率**；业务能否接受 2–10 秒，是硬约束。
- 观测出口：`tool_calls_per_query`、`escalation_rate`、`cost_per_success`、`p95_latency`、`answer_accuracy_by_complexity`。
- **一句话**：**Agentic 不是更聪明的 RAG，而是更贵的“证据获取过程”；只在值得的地方用。**

### 自测 3 题

1. 你的查询里，真正需要多轮/多工具的占比是多少？如果没有数据，先量。
2. 你的 Agentic 路径平均几秒？P95 呢？业务能接受吗？
3. 如果 Agentic 把准确率从 70% 提到 85%，但成本涨 5 倍、延迟涨 4 倍，你会全量上还是只对某类 query 上？

## 今日前沿插入

**① 轻量路由就能省 28.1% token（arXiv:2604.03455，2026-04）。**
TF-IDF + SVM：路由准确率 **93.2%**、F1 **0.928**、模拟节省 **28.1%**；词法特征比语义 embedding 高 **3.1 F1**。→ https://arxiv.org/abs/2604.03455

**② Agentic 检索在复杂任务上收益明确（arXiv:2605.05538，2026-05）。**
BRIGHT recall@1 **49.6%（+21.8pp）**、WixQA **0.96**、FinanceBench **92%**；工具是 `search/find/open/summarize`，不是多 agent。→ [精读](../05-前沿资料/2026-12-06-Agentic-RAG的收益与边界.md)

**③ 生产演化路径是“渐进升级”（OPG，arXiv:2607.24791，2026-06）。**
PEA-CAE：低成本高精度先做，证据不足再升级到全文/多 agent；避免“所有 query 都走最贵路径”。

**趋势观察（非定论）**
2026 年 M6 的核心信号：**“按复杂度路由”比“统一上 Agentic”更成熟**。路由器 + 便宜默认路径 + 受预算约束的升级，会成为生产 RAG 的默认形态。**属趋势观察。**
