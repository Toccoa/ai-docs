## 知识点 1：多模态 RAG（R6-07）

### 一句话结论

**多模态 RAG 的核心不是“支持图片”，而是“让图表/版面成为可检索、可引用、可验证的证据”。** 对视觉丰富的文档（财报、研报、扫描合同），页面级检索 + 视觉语言模型往往比“OCR 成纯文本”更保真；但成本、延迟与引用精度都要重新设计。

### 为什么重要

- 企业文档大量是“视觉丰富”的：表格、图表、流程图、扫描件、多栏排版。OCR 成纯文本会丢结构、丢数值、丢关系。
- 2026 年的基准（UniDoc-Bench，70k 真实 PDF 页、8 个领域）与 VisR-RAG-Fin（视觉丰富金融文档）都把“页面级多模态检索”作为独立问题研究。
- 多模态 RAG 的失败往往不在“模型看不懂图”，而在**检索没找到那一页**、**引用指不到图/表**。

### 核心机制：页面级多模态链路

```text
文档 → 页面图像 + OCR 文本 + 版面元素（标题/表格/图注）
  ↓
多模态索引：文本 embedding + 图像 embedding + 版面元数据
  ↓
检索：文本 query → 文本/图像混合召回（页面级）
  ↓
生成：页面图像 + 相关文本 + VLM/多模态 LLM
  ↓
引用：page_id + bbox/图表编号
```

**三种架构：**

| 架构 | 做法 | 适用 |
|---|---|---|
| 文本为主 | OCR + 表格结构化，图转描述 | 文本密集、图表少 |
| 图文混合 | 文本/图像双索引，分别召回再融合 | 图表、扫描件多 |
| 页面级 VLM | 整页图像给 VLM | 版面复杂、需要全局理解 |

### 怎么做

1. **先量“视觉丰富页”占比**：图表/扫描件/多栏页占多少；低于 10% 不必大改。
2. **页面级检索**：以“页”为检索单元，保留 `page_id`；答案引用到页 + 图表编号。
3. **图文双索引**：文本 chunk 与页面图像各自 embedding，RRF 融合；不要只靠一种。
4. **表格/图表单独表示**：表格存 HTML/LTEM + 语义摘要；图表存“图注 + 数据摘要 + 原图”。
5. **评估分层**：文本题、表格题、图表题、跨页题分开测；`page_recall` 与 `answer_faithfulness` 一起看。

### 权衡与坑

- **坑 1：只 OCR，不保留版面。** 表格结构丢失，数值题必错。
- **坑 2：把整页图丢给 VLM，不做检索。** 成本高、上下文噪声大。
- **坑 3：引用指不到图表。** 用户看到“根据财报”，但不知道是哪张表。
- **坑 4：图像 embedding 与文本 embedding 不可比。** 融合时要做归一化/校准。
- 【我的建议】先做“页面级 + 文本/图像双索引”，再考虑端到端 VLM；不要跳过检索。

### 架构师视角

- 多模态 RAG 是**文档智能的一部分**，不是“另一个聊天功能”；它要求解析、索引、生成、引用全链路升级。
- 观测出口：`page_recall@k`、`visual_question_ratio`、`table_answer_accuracy`、`citation_bbox_coverage`、`vlm_cost_per_query`。
- **一句话**：**图表不是装饰，是证据；多模态 RAG 的目标是让图表也能被引用。**

### 自测 3 题

1. 你的语料里，视觉丰富页占多少？其中表格/图表/扫描件各占多少？
2. 你的检索单元是“文本块”还是“页”？图表题能找到正确页吗？
3. 你的引用能定位到具体图表/表格吗？还是只能到文档？

## 知识点 2：双向 RAG / 经验回写（R6-08）

### 一句话结论

**双向 RAG 让系统把“验证过的答案”写回知识库，从而越用越聪明；但写回是高风险动作——一次幻觉回流，就会变成明天的“权威来源”。** 正确形态是：**答案先过验收层（grounding、引用、去重、时效），通过后才写入，失败进隔离区**。

### 为什么重要

- 传统 RAG 只读不写：每次问答的经验都浪费了。
- 双向 RAG（Bidirectional RAG）把“高质量答案”作为新知识写回，能减少重复检索、提升一致性。
- 但知识库一旦被污染，后续所有回答都会被带偏；**写回必须比读取更严格**。

### 核心机制：验收层 + 隔离区

```text
答案生成
  ↓
验收层：
  ① grounding：每个 claim 有证据支持（NLI/引用核查）
  ② attribution：引用可定位
  ③ novelty：与现有知识不重复/不冲突
  ④ authority：来源可信、时效有效
  ↓
通过 → 写入“已验证答案区”（带来源、时间、版本）
失败 → 隔离区（不进入检索，供人工复核）
```

**写回的三条铁律：**

1. **没有引用，不写回。**
2. **与现有知识冲突，不写回**（进隔离区，人工裁决）。
3. **写回内容必须带 `source_answer_id` 与 `verified_at`**，可追溯、可撤销。

### 怎么做

1. **先做“只读 + 候选池”**：把高质量答案存到候选池，不直接进主索引；人工抽检后再晋升。
2. **验收自动化**：NLI 支持度、引用逐字匹配、与现有文档的重复/冲突检测。
3. **隔离区**：失败答案不删除，放隔离区供分析；避免“污染主库”。
4. **版本与撤销**：每条写回记录 `source_answer_id`、`verified_by`、`verified_at`、`supersedes`；支持一键撤销。
5. **监控**：`writeback_rate`、`writeback_reject_rate`、`post_writeback_regression`（写回后指标是否下降）。

### 权衡与坑

- **坑 1：把“用户满意”当“正确”。** 用户可能喜欢一个错误答案；不能作为写回依据。
- **坑 2：没有冲突检测。** 新答案与旧知识矛盾，会把系统搞乱。
- **坑 3：写回不可撤销。** 一旦污染，无法回滚。
- **坑 4：忽略时效。** 写回的答案会过期；要带 `valid_to`。
- 【我的建议】先从“候选池 + 人工晋升”开始，再逐步自动化；不要一上来全自动写回。

### 架构师视角

- 双向 RAG 是**知识运营**，不是检索功能；它需要治理流程与责任边界。
- 观测出口：`writeback_rate`、`writeback_reject_rate`、`isolation_queue_size`、`post_writeback_regression`、`rollback_count`。
- **一句话**：**写回不是“让模型记住”，而是“让组织批准一条新知识”。**

### 自测 3 题

1. 你的系统会把答案写回知识库吗？如果有，验收层有哪些检查？
2. 如果一条写回的答案后来被发现是错的，你能定位并撤销它吗？
3. 用户“满意”但引用不支持结论的答案，你会写回吗？为什么？

**① 多模态 RAG 已有大规模真实基准（UniDoc-Bench，EMNLP 2026 Findings）。**
7 万真实 PDF 页、8 个领域，专门评估文档中心的多模态 RAG；说明“页面级、视觉丰富文档”已经是独立问题。→ https://aclanthology.org/2026.findings-emnlp.534/

**② 视觉丰富金融文档的多模态 RAG 被系统研究（VisR-RAG-Fin，arXiv:2610.24822，2026-10）。**
系统分析 text-only / multimodal / hybrid 三种配置在页面级 QA 上的差异；核心变量是**检索页**与**视觉信息使用**。

**③ MM-R2：先推理“要查什么/在哪查”，再检索（arXiv:2607.22643，2026-06）。**
用 intent-grounded retrieval state + KnowledgeMap 结构化检索，解决“检索目标不明确、搜索空间无结构”两个问题。→ https://arxiv.org/abs/2607.22643

**趋势观察（非定论）**
2026 年 M6 后段的信号：**多模态 RAG 的竞争点从“模型能不能看图”转向“页面检索准不准、引用能不能落到图表”**；写回则从“功能”变成“治理”。**属趋势观察。**
