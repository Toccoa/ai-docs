## 4. 检索 5 篇前沿文章

### 口径（按优先级）

1. **48 小时内**：工程实践、基准论文、评测方法论文、官方工程博客；
2. **7 天内**：重要论文或权威博客；
3. 都不够 3 篇时，**补录**此前未收录过的经典材料，标题注明「（补录）」，并在正文说明理由；
4. 永远不要为了凑数收录：融资、产品发布、纯榜单刷分、与「评测/度量/可靠性」无关的内容。

### 主题范围

评测方法、基准设计、评分器/judge、统计与不确定性、harness 与基础设施、可观测性、安全评测、评测经济学。**宁可选 3 篇真有用的，也不要 5 篇同质化的。**

### 来源清单（每天至少交叉 2 个）

- Hugging Face Blog：`https://huggingface.co/blog/feed.xml`
- Anthropic Research / Engineering：`https://www.anthropic.com/research`、`/engineering`
- OpenAI News：`https://openai.com/news/`
- arXiv（按提交日期）：`https://export.arxiv.org/api/query?search_query=abs:%22agent%22+AND+abs:%22evaluation%22&sortBy=submittedDate&sortOrder=descending&max_results=30`
- METR：`https://metr.org/blog/`
- LangChain Blog：`https://blog.langchain.dev/`
- Simon Willison：`https://simonwillison.net/atom/everything/`
- Google DeepMind / Microsoft Research / UK AISI (Inspect) / Berkeley BFCL

### 工具

优先用会话里的搜索工具（`mcp__anysearch__search` / `web_search` / `web_fetch`）。**任何抓取失败就换 curl**：

```bash
curl -s -L --max-time 30 "<URL>" -o "_raw/YYYY-MM-DD/<slug>.html"
textutil -convert txt -stdin -stdout < "_raw/YYYY-MM-DD/<slug>.html" > /tmp/<slug>.txt
```

### 去重与核验

- 打开 `04-索引.md` 与最近 3 天的 `03-前沿文章/`，**同一篇文章（按标题/URL）不得二次收录**。
- 每篇必须核验：**真实可访问（HTTP 200）、发布日期可在页面上找到、作者/机构可确认**。
- 数字必须来自原文；不得编造论文、引用、链接。日期无法确认时写「日期未确认」。

## 6. 翻译与写作

### 语言

- 原文是中文：直接存档，标注「原文即中文」。
- 原文非中文：**必须译成中文**。不允许只写摘要冒充翻译。

### 翻译标准

- 术语一致：task=任务、harness=执行架（首次出现保留英文）、rollout=试次/rollout、verifier=验证器、trace=轨迹、grader/judge=评分器、benchmark=基准、scaffold=脚手架、held-out=留出、saturation=饱和、contamination=污染。
- **全文翻译**优先；篇幅过长（>6000 词）可「精译」，但必须：保留全部论证与数字、保留章节结构、在头部写明**略去了什么**。
- 数字、单位、条件（p 值、样本量、置信区间）必须逐字核对，**不允许四舍五入掉关键限定**。
- 代码块保留原样，注释可译。

## 13. 失败处理

| 情况 | 处理 |
|---|---|
| 搜索工具不可用 | 改用 curl + RSS/arXiv API；再不行用 `curl` 抓站点首页找最新文章 |
| 某站点 403/超时 | 换来源，不硬抓；同一来源最多重试 2 次 |
| 找不到 5 篇合格新文章 | 收 3–4 篇，其余补录经典（标注「补录」），并在回复里说明 |
| 构建失败 | 先修构建，**不要带着失败推送**；修不动就回滚当天新增文件并报告 |
| 推送失败 | 先 pull --rebase，再重试；仍失败则报告具体错误，不要 force push |
| 当天文件已存在 | 不重复生成，只做线上验证与摘要 |
